# Генераторы тестовых хранилищ

Если задача требует ручного тестирования, агент обязан подготовить папку
`docs/testing/<task-or-epic>/notes/` с готовыми заметками и вложениями для всех
сценариев задачи. Несовместимые наборы размещать в отдельных папках данных.
Для сборки хранилищ использовать единый скрипт
[docs/testing/prepare_vault.py](../testing/prepare_vault.py).
В инструкции каждого сценария указывать папку данных, точный путь хранилища
и команду с `--source` и `--dest`. Перед передачей проверки пользователю
агент проверяет подготовку хранилища; при изменении генератора выполняет его
автоматические проверки.

## Запуск и установка

- Общий генератор писать на Python 3, используя стандартную библиотеку.
- При запуске без параметров выводить краткую справку с примером вызова
  и завершаться успешно без сборки, запросов ввода и изменений файлов.
- При передаче параметров требовать `--source PATH`: существующую папку
  с заметками и вложениями. Копировать её содержимое с сохранением структуры
  и байтов файлов. Данные сценариев хранить файлами, отдельно от генератора.
- Поддерживать `--dest PATH` для нового или существующего хранилища,
  включая пути с пробелами. Без `--dest` использовать соседнюю с исходником
  папку `<имя-исходной-папки>-vault` (для `notes/` — `notes-vault/`).
- Определять корень репозитория по расположению скрипта, чтобы запуск работал
  из любой текущей папки. Относительные `--source` и `--dest` считать от текущей
  рабочей папки пользователя.
- При создании нового хранилища собирать актуальную версию через `npm run build`
  и устанавливать `main.js`, `manifest.json`, `styles.css` в
  `.obsidian/plugins/<id из manifest.json>/`. Зависимости должны быть установлены
  заранее. Исходная папка должна содержать обычные файлы и папки без `.obsidian`
  и символических ссылок; настройки подключения из других хранилищ не копировать.

## Непустое хранилище

Перед изменениями показывать нумерованное меню с этими вариантами и смыслом:

1. **Заменить полностью.** Заменить весь контент и `.obsidian`; собрать и
   установить плагин заново. Прежние настройки сбрасываются.
2. **Заменить, сохранив настройки плагина.** Заменить контент, собрать и обновить
   файлы плагина. Сохранить существующую `.obsidian`, включая
   `.obsidian/plugins/<manifest id>/data.json`, настройки Obsidian и другие плагины.
3. **Заменить только контент.** Заменить заметки и вложения тестовыми данными.
   Оставить `.obsidian`, установленную версию плагина и настройки без изменений.
   Сборку не запускать.
4. **Отмена.** Завершить работу без изменений.

Пустой ответ, конец ввода и прерывание выбирают отмену; неверный номер повторяет
запрос. До выбора явно сообщать, что варианты 1–3 удаляют прежний контент
за пределами `.obsidian`. Для пустой или отсутствующей папки меню не требуется.

## Сохранность данных и проверка

- Запрещать использование корня репозитория и его родительских папок как
  назначения; путь, занятый обычным файлом, отклонять.
- Запрещать совпадение и вложенность исходной папки и назначения в обе стороны,
  включая совпадения через символические ссылки.
- Завершать необходимую сборку и подготовку новых файлов во временной папке
  до удаления существующих данных. Ошибка сборки или подготовки сохраняет
  прежнее хранилище.
- Автоматически проверять создание нового хранилища, все четыре режима,
  побайтовое сохранение `data.json` в режиме 2, неизменность `.obsidian` в режиме 3,
  отмену при пустом вводе/EOF, неверный номер и сохранность при ошибке сборки.
  Дополнительно проверять справку без параметров, обязательность `--source`,
  копирование вложенных заметок и бинарных вложений, назначение по умолчанию,
  запрет пересечения путей и `.obsidian`/символических ссылок в исходниках.
  Проверки выполнять во временных хранилищах.
- В инструкции сценария приводить команду с `--source` и `--dest`, способ восстановления
  и указание закрыть тестовое хранилище перед обновлением.

Проверки общего генератора:

```sh
python3 -m unittest discover -s docs/testing -p 'test_prepare_vault.py' -v
```
