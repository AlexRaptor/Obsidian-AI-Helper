Каждая задача включает поведение от поручения в чате до наблюдаемого результата, локализацию новых сообщений на русском и английском, автоматические тесты через ввод и кнопки ChatView с настоящим клиентом и подставными ответами модель-сервера, полные Vitest и production-сборку. Тесты проверяют результаты, отсутствие лишних записей и видимые статусы, а не приватное устройство модулей. Ручная проверка требуется только там, где нужно подтвердить реальную историю отмены редактора Obsidian; подготовленный комплект приведён в родительской спецификации.

Временный ограниченный объём каждого среза не меняет конечные требования #67. Не реализованный ещё инструмент не объявляется модели как доступный. Обязательные предпросмотры, отдельные подтверждения ясных команд, текстовая имитация инструментов, автоматическое переключение модели и автоматическое применение неполного результата не допускаются ни в одном срезе.

## 1. Создание заметки по поручению в чате

### Parent

https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/67

### What to build

Пользователь поручает создать заметку по обсуждению или явно прикреплённым материалам, получает новый Markdown-файл и ссылку на него. Это первый работающий путь через протокол инструментов, исполнитель поручения, создание в Obsidian и представление результата. Обсуждение и уточняющие вопросы не вызывают запись.

### Acceptance criteria

- [ ] Ясная команда создаёт заметку без обязательного предпросмотра. Сохранение итогового решения учитывает поздние уточнения, не выдаёт отвергнутые идеи за принятые и отделяет открытые вопросы. Несколько явно приложенных материалов допустимы; поиск для записи не запускается автоматически только из-за прежнего включения поиска.
- [ ] Работают заданные название и папка, название по содержанию при его отсутствии и стандартная папка новых заметок Obsidian с активной заметкой на момент отправки. Недостающие явно указанные папки создаются; недопустимые имена, выход из хранилища, служебная папка и файл вместо папки отклоняются без молчаливого выбора другого места.
- [ ] При совпадении имени создаётся свободный вариант с числовым суффиксом, включая регистровые и конкурентные коллизии. Существующая заметка никогда не перезаписывается. Оставшиеся при сбое новые папки отражаются в фактическом отчёте.
- [ ] Существующий клиент поддерживает полный вызов функции без обязательного текстового содержимого, результат инструмента и последующее сообщение модели. Работают HTTP-ответы и потоковые аргументы, собираемые до завершения ответа; при явном отказе от потока сохраняется резервный непотоковый запрос. Выполнение нескольких действий в одном поручении остаётся задачей 5.
- [ ] Вызов с неверными аргументами, неизвестным именем, оборванным потоком, превышением длины или отказом модели ничего не записывает. До завершения и проверки полного вызова побочных эффектов нет. Бюджет включает описания инструментов и их результаты; материалы не обрезаются молча.
- [ ] Явный отказ модель-сервера от инструментов объясняется пользователю; обычный диалог сохраняется без автоматической смены модели и исполнения текста ответа. Отсутствие вызова само по себе не считается доказательством отсутствия поддержки.
- [ ] Остановка, закрытие, очистка диалога и выгрузка запрещают запоздалое создание. Успешное создание фиксируется сразу, с идентификатором логического шага и фактическим файлом; повторная доставка того же вызова не создаёт дубликат. Ошибка последующего ответа модели не теряет видимый результат создания.
- [ ] Неполученный или неполный результат не сохраняется как полный; при превышении доступного объёма предлагается уменьшить задачу. Поведение обсуждения и неоднозначного поручения проверяется подставными текстовыми ответами без записи.
- [ ] Автоматические проверки проходят через пользовательский ввод и настоящий клиент, покрывают создание, коллизии, отказ протокола, остановку и ошибки. Сообщения доступны на русском и английском; полный набор тестов и сборка проходят.

### Blocked by

Нет — можно начать сразу.

## 2. Правка прикреплённой заметки с защитой изменений и обычной отменой

### Parent

https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/67

### What to build

Пользователь поручает изменить целую явно прикреплённую заметку, в том числе из истории диалога. Запись применяется только к той же актуальной заметке, сохраняет свойства по умолчанию и отменяется обычными средствами Obsidian. После конфликта пользователь может явно поручить работу с актуальной версией.

### Acceptance criteria

- [ ] Добавлен инструмент редактирования зарегистрированной цели с ожидаемой версией. Прикрепление без поручения не разрешает запись. При нескольких неясных целях модель уточняет; роли материалов и цели определяются поручением без переключателей.
- [ ] Снимок целой заметки читается при отправке, с учётом несохранённого редакторского текста. Вложение из истории доступно без повторного прикрепления. Произвольный путь в аргументах не разрешает изменить незарегистрированную заметку.
- [ ] Полный текст проверяется перед редакторской транзакцией без асинхронного промежутка. Изменение текста или свойств вызывает конфликт без записи. После открытия редактора цели повторно проверяются файл, текст и действующее поручение; расходящиеся редакторские представления не выбираются молча.
- [ ] Переименование и перемещение без изменения текста сохраняют идентичность цели и обновляют ссылку. Удаление останавливает запись; новый файл по старому пути не наследует цель.
- [ ] По умолчанию заменяется основной текст с неизменным исходным YAML-блоком. Явная команда свойствам разрешает их изменение; недопустимый результат не повреждает заметку. Переименование, перемещение и удаление через инструмент не добавляются.
- [ ] После конфликта автоматического перечитывания и повторной записи нет. Новое поручение взять актуальную целую заметку регистрирует новую основу, не переписывая прежние снимки.
- [ ] Успешная правка сразу сохраняет фактический результат и новую версию. Следующее отдельное поручение может продолжить от неё, в том числе для заметки, созданной задачей 1. Ручная правка или отмена, изменившая ожидаемый текст, вызывает конфликт следующего изменения.
- [ ] Изменение выполняется одной отдельной редакторской транзакцией. Для закрытой цели используется редактор той же заметки, а не прямая файловая запись в обход отмены. Реальная отмена и повтор не объединяются с соседним ручным вводом; автоматического отката нескольких заметок нет.
- [ ] Автоматически покрыты цель из истории, YAML, конфликт во время генерации и открытия, идентичность файла, продолжение собственной правки, остановка и поздний ответ. Для реальной отмены пользователь получает подготовленный сценарий целой заметки и закрытого редактора из комплекта #67; других ручных проверок не требуется. Локализация, полные тесты и сборка проходят.

### Blocked by

Задача 1 — рабочий цикл инструментов, создание цели результата и фиксация действия в чате.

## 3. Замена прикреплённого выделенного фрагмента

### Parent

https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/67

### What to build

Пользователь явно прикрепляет выделенный фрагмент существующим способом и поручает его заменить. Меняется только этот диапазон; устаревшие координаты не используются, даже если ручные правки затронули другую часть заметки.

### Acceptance criteria

- [ ] Используется существующее прикрепление фрагмента, без нового самостоятельного механизма. Текст и диапазон фиксируются при подтверждённом добавлении упоминания согласно ADR-0003; наличие текущего выделения само по себе не делает его целью.
- [ ] Тогда же локально фиксируется полный текст для проверки актуальности. Он не отправляется модели как дополнительный контекст, не попадает в экспорт как скрытое вложение и не расширяет доступную модели часть заметки.
- [ ] Изменение любой части заметки после прикрепления вызывает конфликт, в том числе до отправки, выше диапазона и в YAML. Нет поиска совпадающего фрагмента, автоматического смещения диапазона или слияния.
- [ ] Модель не может расширить прикреплённые границы координатами в аргументах. Успешная замена сохраняет весь соседний текст и свойства; использование фрагмента как материала для новой заметки не меняет его оригинал.
- [ ] Цель из истории сохраняет исходную основу; после конфликта требуется новое явное прикрепление фрагмента. Успешная замена регистрирует новый диапазон результата, позволяя следующему отдельному поручению изменить его без переписывания истории. Другие старые диапазоны не переносятся автоматически.
- [ ] Сохраняются правила идентичности файла, остановки, повторной проверки после открытия редактора и обычной отдельной отмены из задачи 2.
- [ ] Автоматически проверены точные границы, идентичный текст в разных местах, устаревание до отправки и во время генерации, отсутствие полного исходника в запросе и новая цель результата. Ручной сценарий реальной отмены фрагмента входит в комплект #67; сообщения локализованы, полный набор тестов и сборка проходят.

### Blocked by

Задача 2 — реестр версий целей и безопасная редакторская запись с отменой.

## 4. Вставка у зафиксированного курсора и в конец заметки

### Parent

https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/67

### What to build

Пользователь поручает вставить подготовленный материал у курсора или в конец явно указанной заметки. Источник и цель могут различаться, а переключение вкладок после отправки не переносит действие.

### Acceptance criteria

- [ ] Для явной вставки у курсора используется последний пригодный редактор, из которого пользователь перешёл в чат. Заметка, позиция и полный текст фиксируются при отправке; отдельного прикрепления цели для этой команды не требуется.
- [ ] Отсутствие однозначного редактора, несколько курсоров или неясное «сюда» требуют уточнения, а не выбора случайной вкладки. Перемещение курсора и переключение заметки после отправки не меняют цель.
- [ ] Изменение любой части целевой заметки после отправки вызывает конфликт без вставки и автоматического переноса. После конфликта нужно заново явно указать место.
- [ ] Работает вставка в конец прикреплённой заметки, в том числе выбранной из истории. Вставка не подменяется заменой основного текста и не меняет свойства или соседний текст как побочный эффект.
- [ ] Материалом могут быть история диалога, целая заметка и прикреплённый фрагмент через уже существующие вложения. Перевод или саммари вставляется в цель, оригинал сохраняется.
- [ ] Работают идентичность файла, проверка после асинхронного открытия, остановка и новая версия результата по правилам задачи 2.
- [ ] Автоматические проверки через чат покрывают фиксацию позиции, разные источник и цель, конфликт и отсутствие редактора. Пользователь получает ручной сценарий отдельной отмены вставки и соседней правки из комплекта #67; сообщения локализованы, тесты и сборка проходят.

### Blocked by

Задача 2 — адресация той же заметки, версии и редакторская запись с отменой. Замена фрагмента из задачи 3 не требуется: прикрепление фрагмента как материала уже существует.

## 5. Последовательные действия, частичный сбой и повтор без дубликатов

### Parent

https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/67

### What to build

Пользователь выполняет несколько понятных действий одним поручением, видит результат каждого шага и может после сбоя повторить только оставшуюся работу. Сохранённые результаты не теряются при остановке или ошибке последующего ответа модели.

### Acceptance criteria

- [ ] Несколько вызовов выполняются последовательно в порядке ответа после проверки структуры всего набора. Поручение «Сохрани полный вариант и сократи этот фрагмент» проходит от создания копии до ограниченной замены; доступны также целая заметка и вставка.
- [ ] Успешный результат шага может стать целью следующего без повторного прикрепления и изменения исторических снимков. Подготовленный вызов для старой версии не применяется к новой молча; модель получает фактический результат и подготавливает актуальное продолжение.
- [ ] Первый сбой останавливает все оставшиеся шаги, включая независимые. Видимый итог различает выполненное и невыполненное, не заявляет общий успех и не откатывает успешные действия.
- [ ] Журнал логических шагов сохраняется до следующего сетевого запроса. «Попробуй ещё раз» продолжает только невыполненное с проверкой актуальности; новый транспортный идентификатор не разрешает повторить успешный логический шаг. Явное новое поручение создать ещё одну заметку остаётся допустимым.
- [ ] Повторная доставка вызова возвращает сохранённый результат; одинаковый идентификатор с другими аргументами отклоняется. Неустановленный исход записи сначала проверяется по связанному файлу и ожидаемому результату; до этого повтор запрещён.
- [ ] Остановка до шага, между шагами и во время начавшейся записи учитывает фактический результат; поздние ответы не запускают новые действия. Очистка, закрытие и выгрузка действуют аналогично. Никакого восстановления исполнения после перезапуска не добавляется.
- [ ] На один запуск действуют пределы 16 раундов и 32 вызовов; бюджет проверяется на продолжениях, включая результаты инструментов. Достижение предела или контекстного ограничения останавливает оставшееся и сохраняет отчёт; автоматического разбиения нет. Занятость модели удерживается на весь цикл.
- [ ] Автоматически проверены смешанная последовательность, успех записи перед ошибкой сети, остановка во время записи, повтор после частичного сбоя, неизвестный исход и пределы продолжения. Реальная отдельная отмена в нескольких заметках проверяется пользователем по комплекту #67; локализация, полный набор тестов и сборка проходят.

### Blocked by

- Задача 3 — рабочая замена фрагмента и новая цель её результата.
- Задача 4 — рабочая вставка и новая версия её результата.

Задачи 1 и 2 входят в зависимости транзитивно и не добавляются отдельными блокирующими связями.

## 6. Сохранение всей видимой переписки в новую заметку

### Parent

https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/67

### What to build

По поручению «Сохрани весь чат» плагин создаёт заметку с полной видимой перепиской в исходном порядке, а не с пересказом модели. Модель помогает выбрать имя и папку, но не переписывает сообщения.

### Acceptance criteria

- [ ] Сохраняется копия видимой переписки на момент отправки команды, включая саму команду и уже видимые результаты действий. Последующее сообщение об успехе, индикаторы ожидания, системный промпт и технический обмен не включаются.
- [ ] История для экспорта учитывает видимые неуспешные попытки и оборванные ответы, даже если они не вошли в историю запросов модели. Незавершённый текст явно отмечается; неполученный текст не восстанавливается и не становится успешным сообщением в контексте модели.
- [ ] Markdown с ролями и исходным текстом реплик формируется средствами плагина, без пересказа и ограничения длиной ответа модели. Технические подписи локализованы, пользовательский текст не переводится.
- [ ] Вложения по умолчанию обозначены названиями и ссылками. По явному поручению включаются сохранённые полные снимки заметок и снимки выделенных фрагментов; текущее содержимое файлов не подменяет историческое. Скрытый полный текст проверки актуальности не экспортируется.
- [ ] Ожидание ответа модели с названием или папкой не сдвигает границу экспорта. Создание использует правила папок, коллизий, остановки и фиксации результата задачи 1.
- [ ] Сохранение итогового решения остаётся отдельным поручением генерации текста и не заменяет полную переписку. Никакого долговременного восстановления диалога не добавляется.
- [ ] Автоматические проверки через чат покрывают порядок реплик, оборванные ответы, видимые результаты инструментов, точную границу команды, оба режима вложений и неизменность снимков после изменения файлов. Ручная проверка экспорта не требуется; локализация, полный набор тестов и сборка проходят.

### Blocked by

Задача 1 — создание файла по вызову инструмента и сохранение фактических результатов в чате. Редактирование заметок и смешанные последовательности не являются предпосылками экспорта.

## 7. Явный поиск материалов перед созданием и редактированием

### Parent

https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/67

### What to build

Пользователь может явно поручить найти материалы в хранилище и на их основе создать заметку или изменить прикреплённую цель. Автоматический поиск при записи не подмешивает материалы только из-за прежнего состояния переключателя поиска.

### Acceptance criteria

- [ ] Без поручения дополнительного поиска для записи используются поручение, история и явно приложенные материалы. Прежнее включение поиска в чате не запускает новую выдачу автоматически при подготовке записи.
- [ ] Явное поручение «Найди материалы о подготовке поездки и создай сводную заметку» использует существующий поиск по заметкам и создаёт результат через готовый инструмент. Поиск не дублируется новой подсистемой.
- [ ] Явное поручение поиска с последующим дополнением прикреплённой заметки сохраняет её прежнюю цель и проверку актуальности; найденные результаты не становятся целями записи без явного прикрепления.
- [ ] При работе с выделенным фрагментом остальной текст его заметки не подмешивается автоматически. Полный текст локальной проверки не становится поисковым контекстом.
- [ ] Применяются существующие ограничения конфигурации, доступности индекса и бюджета. При ошибке получения явно нужных материалов модель не заявляет, что использовала их, а неполное поручение не выдаётся за успешное. Неполученный контекст не заменяется молча произвольным материалом.
- [ ] Обычное обсуждение с включённым поиском сохраняет прежнее поведение; меняется именно автоматическое получение материалов для записи. Прямые поручения не получают обязательного предпросмотра или дополнительного подтверждения.
- [ ] Автоматические проверки через чат покрывают включённый ранее поиск без поручения, явный поиск с созданием и правкой, ошибку поиска, неизменность цели и отсутствие скрытого текста. Отдельная ручная проверка не нужна; локализация, полный набор тестов и сборка проходят.

### Blocked by

Задача 2 — готовые сквозные сценарии создания и изменения зарегистрированной целой заметки. Зависимость от задачи 1 уже транзитивная; готовая замена фрагмента не требуется для проверки его использования как материала.
