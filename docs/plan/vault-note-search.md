# Поиск по заметкам хранилища

Статус: согласовано пользователем 2026-10-10; интервью завершено. Документ является основой реализации. Реализация не начата.

Спецификация опубликована: [GitHub issue #12](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/12), метка `ready-for-agent`. Точки тестирования отдельно подтверждены пользователем.

## Согласованные требования

- Весь плагин предназначен исключительно для настольного Obsidian; мобильный Obsidian не поддерживается. Текущий manifest уже содержит `isDesktopOnly: true`.
- Пользователь подключает embedding-модель, строит индекс хранилища и задаёт папки, исключённые из индексации.
- Первая версия индексирует только Markdown-заметки.
- Поиск по заметкам включается переключателем в чате, выключенным по умолчанию.
- При включённом поиске модель диалога отвечает на основе найденных фрагментов, со ссылками на заметки для проверки источников.
- Первая версия проверяется на локальных модель-серверах; внешний адрес не запрещается. Первая индексация запускается явно; интерфейс объясняет, каким серверам передаётся текст. Текст исключённых папок не участвует в передаче при индексации и поиске.
- Embedding-модель имеет независимое подключение: адрес модель-сервера, ключ и выбранная модель. Используется OpenAI-совместимый интерфейс. Первая среда проверки — LM Studio, модель диалога `qwen3.8-27b`, embedding-модель `text-embedding-qwen3-embedding-0.6b` (имена указаны пользователем; реальные API-идентификаторы уточняются при подключении).
- Исключение папки распространяется на всё её поддерево. После изменения настройки её фрагменты немедленно исключаются из поиска и удаляются из индекса. Ранее состоявшиеся диалоги не очищаются.
- После первого ручного запуска индекс автоматически обновляется при изменениях заметок с небольшой задержкой. Автоматическое обновление можно приостановить. Удаление заметки и перенос в исключённую папку немедленно исключают её из поиска.
- При правке пересинхронизируется только изменённая заметка. До замены её части индекса она временно исключена из поиска; поиск по остальным заметкам доступен. Команда «Переиндексировать заметку» доступна в меню заметки и палитре команд для ручного повтора.
- Во время первой индексации доступен поиск по обработанным заметкам с указанием неполноты индекса.
- При смене embedding-модели или её подключения требуется перестроение индекса. До перестроения поиск недоступен; обычный диалог доступен.
- При переименовании исключённой папки внутри Obsidian исключение следует за папкой. При внешнем исчезновении папки старый путь сохраняется и отображается как не найденный.
- Индекс сохраняется между запусками для каждого хранилища; его можно удалить и перестроить. Перенос и синхронизация индекса между компьютерами не входят в первую версию.
- Предусмотрены два режима хранения: локальное хранилище приложения по умолчанию и файлы внутри хранилища Obsidian как дополнительный вариант. При файловом режиме интерфейс объясняет необходимость исключения из Git. Локальный вариант через IndexedDB требует проверки в работающем Obsidian; автоматического перехода к файловому режиму при ошибке нет.
- Пользователь синхронизирует хранилище через Git. Настраивается размещение индекса, а не название способа синхронизации.
- Реальное хранилище пользователя: около 500 заметок общим размером 6 МБ без вложений. Это контрольный пример, а не ограничение поддерживаемого размера хранилищ.
- Поисковый запрос учитывает предыдущие сообщения диалога; для его формирования допускается дополнительное обращение к модели диалога.
- Если подходящих сведений в заметках нет, модель сообщает об этом и не подменяет ответ общими знаниями. При частичных сведениях отвечает по найденной части и обозначает пробелы. Ответ по общим знаниям доступен при выключенном поиске.
- Ответ содержит ссылки на заметки; раскрываемый список источников показывает использованные фрагменты. Ссылки открывают заметку, по возможности соответствующий раздел.
- Объём найденных фрагментов ограничивается бюджетом контекста. Если история не оставляет места для полезного контекста, предлагается новый диалог; автоматическое сокращение истории в первую версию не входит.
- Смысловой поиск совмещается с текстовым поиском названий, тегов и точных терминов. Отдельная модель повторного ранжирования в первую версию не входит.
- Индексируются название, путь, заголовки, основной текст и YAML-свойства `tags`/`aliases`; остальные свойства YAML пропускаются. Встроенные заметки не раскрываются в родительской заметке, а индексируются самостоятельно с учётом исключений.
- Для каждого сообщения источники отбираются заново из актуального индекса; прежние фрагменты источников повторно не отправляются как поисковый контекст. Предыдущие сообщения пользователя и модели сохраняются и передаются, поэтому исключение папки не удаляет сведения, уже пересказанные в диалоге.
- Завершённая работа индексации сохраняется. После прерывания работа продолжается с необработанных или изменённых заметок. Интерфейс показывает прогресс, ошибки и команды паузы/продолжения.
- Ошибка поиска останавливает текущую отправку и отображается пользователю; автоматического перехода к ответу без заметок нет.
- Заметки делятся на фрагменты по разделам и абзацам. Длинные разделы дополнительно делятся с небольшим перекрытием. Каждый фрагмент сохраняет связь с названием заметки и цепочкой заголовков; его размер ограничивается отдельно от общего бюджета контекста.

## Факты о текущем плагине

- Одно подключение к модель-серверу и одна выбранная модель; embedding-модель и индекс отсутствуют.
- Клиент поддерживает список моделей и генерацию сообщений, включая потоковую.
- Диалог передаёт полную историю завершённых ходов. Бюджет контекста до запроса не рассчитывается.
- Индексирование заметок и обработка изменений хранилища пока отсутствуют.

## Дополнительные согласованные требования

- При смене режима хранения индекс перестраивается без миграции; предупреждение показывается до переключения. Хранилище, перемещённое на другой путь, допускается считать новым и переиндексировать.
- Чат имеет приоритет: текущий запрос индексации завершается, новые фоновые обращения приостанавливаются до завершения поиска и ответа, затем индексация продолжается.
- Основные настройки: подключение embedding-модели, исключённые папки, режим хранения, автоматическое обновление и управление индексом. Расширенные настройки: размер фрагментов, перекрытие и бюджет контекста источников. Параметры ранжирования первоначально подбираются проверкой качества.
- Численные цели скорости определяются после первого замера на LM Studio; размер реального хранилища пользователя не является пределом поддержки.

## Технические вопросы для проверки при реализации

- Доступность, сохранность, квота и изоляция IndexedDB между хранилищами в настольном Obsidian. Если вариант не проходит проверку, выбор хранения возвращается на обсуждение; файловый режим не включается автоматически.
- Формат файлового индекса и его каталог, ключ локального индекса, размер пакетов и ограничение памяти.
- Начальные размеры фрагментов, перекрытие, оценка бюджета контекста, ранжирование и критерий отсутствия релевантных результатов. Подбираются на контрольных сценариях, а не считаются уже доказанными.
- Реальные API-идентификаторы моделей и получение embeddings в LM Studio. Проверка подключения embedding-модели должна включать реальный запрос embeddings, а не только список моделей.

## Критерии готовности

- Поиск по смыслу, точному идентификатору и вопросу-продолжению.
- Ответ с проверяемыми ссылками, сообщение об отсутствии сведений и обозначение пробелов при частичном ответе.
- Правки, удаление, переименование и исключения без выдачи устаревших фрагментов.
- Прерывание, перезапуск Obsidian и недоступность LM Studio без потери завершённой индексации.
- Большое тестовое хранилище: отзывчивый интерфейс, прогресс и возможность паузы.
- Ссылки модели становятся действующими ссылками на источники только после проверки по набору переданных источников. Текст заметок обрабатывается как данные, а не как команды плагину.

## Как проверять

**Автоматически:** правила исключений (включая похожие префиксы папок), деление и состав фрагментов, обновление одной заметки, удаление/переименование, инвалидирование при смене модели, сохранение прогресса, формирование свежего поискового контекста, бюджет, обработка ошибок и проверка ссылок. Поддельный модель-сервер проверяет контракт embeddings и порядок запросов. Выполняются релевантные проверки Vitest и `npm run build`.

**Вручную в настольном Obsidian с LM Studio:** качество смыслового поиска и ответов на небольшом контрольном хранилище с известными результатами; соответствие утверждений источникам; открытие ссылок и разделов; переключатель поиска, прогресс, пауза и ручная переиндексация; реальная сохранность/изоляция локального индекса после перезапуска; файловый режим с Git-исключением; недоступность сервера. Отдельно проверяется ответ при наличии в заметке инструкций для модели. Проверка действительности ссылки не доказывает, что её текст подтверждает ответ.

**Производительность:** на реальном объёме около 500 заметок / 6 МБ измеряются первая индексация, обновление заметки и поиск. На большом синтетическом хранилище проверяются память, отзывчивость и управление длительной работой.

Ручная приёмка дополняет автоматические проверки фактической среды и качества моделей; полный ручной прогон после каждой правки не требуется. Это описание проверки добавлено в ответ на вопрос пользователя и уточняет согласованные критерии готовности.

## Проверенные ограничения интеграции

- LM Studio документирует OpenAI-совместимый endpoint embeddings: https://lmstudio.ai/docs/developer/openai-compat/embeddings. Запрос использует API-идентификатор модели и текст; способность выбранной модели создавать embeddings следует проверять реальным запросом.
- Документированные Obsidian API `Plugin.saveData` и `DataAdapter` сохраняют файлы внутри хранилища. Размещение в папке плагина само по себе не исключает файлы из Git.
- Типы проекта допускают IndexedDB, но его доступность, изоляция и сохранность в работающем Obsidian ещё не проверены. Такой способ хранения требует проверки перед реализацией основного индекса.
