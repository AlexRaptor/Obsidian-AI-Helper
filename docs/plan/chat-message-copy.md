# Копирование сообщений в чате

Дата: 2026-10-10. Источник: сессия grill-with-docs. Термины — из `CONTEXT.md`.
Статус: реализовано по подтверждённому пользователем плану; автоматические проверки пройдены.

## Согласованные решения

1. Копируется отдельное сообщение пользователя или модели. Копирование всего диалога не входит в эту функцию.
2. В буфер обмена попадает исходный текст сообщения с Markdown-разметкой, без имени роли и служебных подписей. Это сохраняет структуру для вставки в заметку Obsidian.
3. Небольшая иконка копирования расположена справа снизу у каждого сообщения с текстом. Она видима постоянно, имеет подсказку «Копировать сообщение» и доступна через Tab.
4. Сообщение пользователя можно копировать после отправки. Сообщение модели можно копировать после завершения генерации, остановки или ошибки, если есть полученный текст модели. Во время генерации кнопка отключена. У пустого сообщения и индикатора ожидания кнопки нет.
5. При остановке или ошибке копируется только полученный текст модели. Пометка остановки и текст ошибки не входят в копируемый текст. У самостоятельного сообщения об ошибке кнопки нет.
6. После успешного копирования иконка меняется на галочку на две секунды. При неудаче показывается уведомление «Не удалось скопировать сообщение», действие можно повторить. Подписи и уведомления поддерживают английскую и русскую локализацию.
7. Кнопка копирует всё сообщение, включая блоки кода. Отдельные кнопки копирования кодовых блоков не входят в эту задачу.

## Проверка результата

- Копирование сообщений обеих ролей сохраняет исходный текст, переносы строк, Markdown и блоки кода.
- Во время генерации копирование сообщения модели недоступно; после завершения, остановки и ошибки поведение соответствует пунктам 4–5.
- Успех отображается только после записи в буфер; ошибка записи даёт уведомление и позволяет повторить действие.
- Перерисовка Markdown, смена языка и повторное открытие окна сохраняют корректность кнопок.
- Проверяются управление через Tab, подписи на обоих языках и расположение кнопки справа снизу у коротких и длинных сообщений.
- Автоматические проверки поведения дополняются ручной проверкой буфера обмена и расположения кнопки в настольном Obsidian.

## Результат проверки реализации

- `npm test`: 157 тестов пройдены, включая 13 новых проверок копирования.
- `npm run build`: проверка типов и production-сборка пройдены.
- Ручная проверка в Obsidian не выполнена. При установке сборки необходимо проверить запись в системный буфер, расположение кнопки на коротких и длинных сообщениях и управление через Tab.

## Документация домена

Новых доменных терминов не требуется: используются «сообщение», «потоковое сообщение модели» и «диалог» из `CONTEXT.md`. ADR не требуется: решения локальны и легко обратимы.
