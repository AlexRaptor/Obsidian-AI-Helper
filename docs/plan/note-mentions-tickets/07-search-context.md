# Дополнять упомянутые заметки поиском с общим бюджетом контекста

## Parent

Спецификация: https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/33

## What to build

Пользователь отправляет вопрос с несколькими упомянутыми заметками и включённым поиском по заметкам, папкам либо обоим видам источников. Модель получает обязательные полные снимки и дополнительные найденные материалы в пределах доступного контекста. Последующие вопросы используют прежние снимки, сохраняя существующее поведение поисковых источников.

## Acceptance criteria

- [ ] Выбранный режим поиска сохраняется при добавлении упоминаний; комбинация, временно недоступная в первом сценарии, становится работоспособной без дополнительного действия пользователя.
- [ ] Полные снимки выбранных заметок обязательны и не заменяются найденными фрагментами, не обрезаются и не пересказываются. Дополнительные источники ограничены оставшимся бюджетом и существующими настройками поиска.
- [ ] Бюджет учитывает окончательный системный контекст, историю со снимками, новый вопрос, новые снимки, служебное представление источников, резерв ответа и дополнительный запас.
- [ ] При наличии снимков используется только известное автоматическое окно либо корректный ручной лимит; ручное значение имеет приоритет, запасной лимит 8192 не применяется.
- [ ] Если обязательный контекст и необходимые резервы не помещаются или окно неизвестно, запрос блокируется с объяснением и сохраняет черновик. Проверки охватывают и вопрос без новых упоминаний, если история содержит снимки.
- [ ] Промежуточные модельные запросы подготовки поиска также учитывают историю со снимками и собственный бюджет. Остановка или очистка во время подготовки не приводит к поздней отправке основного запроса.
- [ ] Найденные источники остаются отличимы от явных вложений; их прежняя политика текущего запроса не превращается автоматически в постоянные снимки истории.
- [ ] Следующие вопросы получают неизменные исторические снимки и свежие результаты поиска; изменения исходных заметок не переписывают старые снимки.
- [ ] Обычный поиск без снимков, поисковые ссылки, потоковые ответы, остановка и управление приоритетом индексации не регрессируют. Ошибки сохраняют вопрос и упоминания по общему правилу, не перезаписывая новый черновик.
- [ ] Проверки через чат и запросы модели охватывают все три режима поиска, несколько снимков, историю, неизвестный и недостаточный лимит, резерв ответа и отмену промежуточного запроса; проходят релевантные регрессии и производственная сборка с проверкой типов.
- [ ] Отдельная обязательная ручная проверка не требуется: состав контекста, три режима поиска, бюджеты и отмена проверяются автоматически на существующей границе модель-сервера. Приёмку реального компонента упоминаний не дублировать.
