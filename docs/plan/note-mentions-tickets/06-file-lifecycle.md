# Сохранять упоминания при переименовании заметок и объяснять недоступность файлов

## Parent

Спецификация: https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/33

## What to build

Пользователь продолжает писать вопрос с несколькими упоминаниями, пока заметки переименовываются, перемещаются, закрываются или удаляются. Выбор остаётся связан с исходными файлами, отображение обновляется, а отправка либо получает правильные актуальные версии, либо сохраняет весь черновик с понятным объяснением.

## Acceptance criteria

- [ ] Переименование или перемещение выбранного файла до отправки сохраняет все его упоминания; названия и доступные пути обновляются без повторного выбора.
- [ ] Файл с прежним путём, появившийся после переименования исходной заметки, не подменяет выбранную заметку.
- [ ] Повторные упоминания после переименования по-прежнему дают один снимок на выбранный файл, а удаление последнего убирает вложение.
- [ ] После переименования отправляется актуальный текст и новый путь; переключение или закрытие вкладки не теряет привязку.
- [ ] Удаление или ошибка чтения любого выбранного файла блокирует весь запрос с указанием проблемной заметки, сохраняя весь вопрос и упоминания. Удаление проблемного упоминания позволяет исправить черновик и отправить остальные заметки.
- [ ] При удалении выбранного файла и создании нового по тому же пути привязка не восстанавливается автоматически на другой файл; нужен явный новый выбор.
- [ ] Каталог подсказок отражает создание, удаление и переименование заметок, включая текущую заметку, и не предлагает устаревшие имена после обновления.
- [ ] Переименование или удаление оригинала после успешного ответа не изменяет исторический снимок и не мешает последующим вопросам по нему.
- [ ] При закрытии представления обработчики событий освобождаются; повторное открытие не создаёт дублирующие реакции или потерю существующего черновика.
- [ ] Проверки через события хранилища, действия пользователя и запросы модели покрывают несколько упоминаний, прежний путь, новый файл на прежнем пути, закрытую вкладку и неизменность истории; производственная сборка с проверкой типов проходит.
- [ ] Пользователь выполняет подготовленный ручной сценарий переименования, перемещения, закрытия вкладки и удаления в настоящем Obsidian, включая новый файл на прежнем пути. Агент поддерживает сценарий и выполняет автоматические проверки.

Ручная проверка нужна для событий и идентичности файлов настоящего Obsidian. Подготовленный локальный артефакт приёмки: `docs/testing/note-mentions/file-lifecycle.md`, общая подготовка: `docs/testing/note-mentions/setup.md`, исходные данные и генератор: `docs/fixtures/note-mentions/`. Эти файлы должны войти в изменения при реализации; пути обозначают артефакты проверки, а не места реализации.
