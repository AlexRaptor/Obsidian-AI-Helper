# Обсуждать несколько заметок в одном сообщении без дублирования снимков

## Parent

Спецификация: https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/33

## What to build

Пользователь добавляет несколько упоминаний в разные части вопроса, обсуждает разные заметки вместе и продолжает диалог по отправленным снимкам. Повторные упоминания одной заметки не расходуют контекст на повторную передачу её текста.

## Acceptance criteria

- [ ] В одном черновике доступны несколько упоминаний разных заметок; добавление нового не заменяет предыдущие.
- [ ] Можно повторно упомянуть один файл. При отправке создаётся один снимок на уникальную заметку в пределах сообщения, при этом видимые упоминания остаются в своих местах.
- [ ] Удаление одного повторения сохраняет вложение, если остались другие; удаление последнего убирает его полностью.
- [ ] При отправке читается актуальное содержимое всех уникальных файлов, включая несохранённые правки соответствующих открытых редакторов. Переключение вкладки не подменяет ни одну привязку.
- [ ] Если хотя бы один файл недоступен, весь запрос блокируется: нет отправки частичного набора заметок, весь текст и все упоминания сохраняются.
- [ ] Проверка вместимости учитывает все новые снимки и прежнюю историю с резервом ответа; недостаток контекста сохраняет черновик без усечения и пересказа.
- [ ] Успешный ход сохраняет все снимки; следующий вопрос использует их прежние версии. Новый ход с новым выбором может передать новую версию той же заметки, не изменяя старый снимок.
- [ ] Ошибка восстанавливает весь вопрос и все упоминания только при отсутствии нового черновика; повтор читает свежие версии. Остановка и очистка не возвращают старые снимки поздним ответом.
- [ ] Смена языка и существующий жизненный цикл представления не теряют набор упоминаний. Обычный текст и вопрос без новых вложений сохраняют прежнее поведение.
- [ ] Проверки через чат и запросы покрывают несколько файлов, повторения, удаление последнего упоминания, обновление редакторов, недоступность одного файла, историю, ошибку и бюджет; производственная сборка с проверкой типов проходит.
- [ ] Пользователь выполняет подготовленный ручной сценарий реального редактирования нескольких элементов упоминаний: курсор, выделение, удаление и вставка. Агент поддерживает сценарий и выполняет автоматические проверки.

Ручная проверка нужна для реального редактирования нескольких элементов внутри поля, которое не подтверждает вспомогательная модель DOM. Подготовленный локальный артефакт приёмки: `docs/testing/note-mentions/multiple-notes.md`, общая подготовка: `docs/testing/note-mentions/setup.md`, исходные данные и генератор: `docs/fixtures/note-mentions/`. Эти файлы должны войти в изменения при реализации; пути обозначают артефакты проверки, а не места реализации.
