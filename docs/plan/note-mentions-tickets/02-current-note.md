# Обсуждать текущую заметку через упоминание и сохранять её снимок в диалоге

## Parent

Спецификация: https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/33

## What to build

Первый законченный сценарий с выключенным поиском: пользователь вводит @, выбирает текущую заметку, задаёт вопрос и получает ответ по её актуальному содержимому. Следующий вопрос без нового упоминания использует прежний отправленный снимок. Упоминание связано с выбранным файлом, а текст читается при отправке. На этом этапе список предлагает текущую заметку; выбор других заметок и интеграция с поиском добавляются отдельными тикетами.

## Acceptance criteria

- [ ] Текущая заметка определяется как последняя открытая заметка, с которой пользователь перешёл в чат, до потери фокуса редактора. При её отсутствии обычный чат остаётся доступным.
- [ ] Набранный @ в начале строки или после пробела, вне кода, открывает подсказку текущей заметки. Почта, обычный неподтверждённый @ и вставленный текст не создают вложений; в почте и коде подсказка не открывается.
- [ ] Стрелки перемещают выбор; Tab или щелчок подтверждают его. Enter подтверждает после навигации стрелками, иначе сохраняет обычную отправку. Escape закрывает подсказку с сохранением текста.
- [ ] Подтверждённое упоминание — отдельный элемент внутри сообщения с названием, доступным полным путём и цветовым выделением активной темы Obsidian. Удаление элемента убирает вложение; отдельной кнопки прикрепления нет.
- [ ] Переключение вкладки не подменяет выбранный файл. При отправке читается актуальный текст редактора с несохранёнными правками либо содержимое хранилища при отсутствии редактора; закрытие вкладки не препятствует чтению файла.
- [ ] Модель получает название, путь и полный Markdown со свойствами как данные контекста, а не системные инструкции. Связанные заметки и встроенные файлы не раскрываются. Используются публичные API Obsidian и существующий текстовый контракт модель-сервера.
- [ ] Успешно завершённый ход сохраняет снимок с исходным сообщением; последующий вопрос получает тот же снимок даже после изменений оригинала. Очистка диалога удаляет историю и снимки, сохраняя текущий черновик.
- [ ] Для сообщений со снимками проверяется известное окно модели с приоритетом ручной настройки, весь итоговый запрос, история, резерв ответа и дополнительный запас. Неизвестный лимит, недостаточный бюджет или недоступный файл блокируют отправку с объяснением и сохраняют черновик; запасной лимит 8192, усечение и пересказ не применяются. Проверка охватывает и дальнейшие вопросы с историческими снимками.
- [ ] Сообщение с одним упоминанием без вопроса или инструкции не отправляется; черновик сохраняется.
- [ ] Ошибка восстанавливает вопрос вместе с упоминанием только при отсутствии нового черновика. Повторная отправка читает свежую версию. Остановка оставляет частичный ответ без автоматического восстановления; неуспешный ход и поздний результат после очистки не попадают в историю.
- [ ] Переходный этап не отправляет упомянутую заметку молча без её текста при включённом поиске: до тикета интеграции такой запрос сохраняется в черновике с понятным сообщением о недоступности комбинации. Обычный поиск без упоминаний продолжает работать.
- [ ] Новые строки доступны на русском и английском; смена языка сохраняет черновик и упоминание. Проверки выполняются через действия в чате, видимый результат и запросы модель-серверу; проходят регрессии и производственная сборка с проверкой типов.
- [ ] Пользователь выполняет подготовленный ручной сценарий для реального Obsidian: цвет, курсор, удаление элемента, клавиатурное управление и несохранённый текст. Агент выполняет автоматические проверки и поддерживает сценарий актуальным; Computer Use без явной просьбы не применяется.

Ручная проверка нужна для реального поведения редактора и темы, которое не подтверждает вспомогательная модель DOM. Подготовленный локальный артефакт приёмки: `docs/testing/note-mentions/current-note.md`, общая подготовка: `docs/testing/note-mentions/setup.md`, исходные данные и генератор: `docs/fixtures/note-mentions/`. Эти файлы должны войти в изменения при реализации; пути обозначают артефакты проверки, а не места реализации.
