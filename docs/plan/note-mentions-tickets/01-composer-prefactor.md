# Подготовить поле сообщения к поддержке упоминаний без изменения поведения чата

## Parent

Спецификация: https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/33

## What to build

Выполнить небольшой предварительный рефакторинг поля сообщения: отделить управление вводом, черновиком и событиями клавиатуры от остального представления чата. Для пользователя отправка обычного текста, перенос строки, восстановление после ошибки, остановка, очистка и смена языка должны работать как прежде. Это подготовка к отдельным элементам упоминаний, а не новая функция и не широкая переработка чата.

## Acceptance criteria

- [ ] Представление чата взаимодействует с полем ввода через небольшой внутренний интерфейс для чтения, восстановления и очистки черновика и обработки действий пользователя; обработка ввода не размазана по жизненному циклу представления.
- [ ] Обычный текст по-прежнему отправляется кнопкой и Enter, Shift+Enter добавляет перенос строки; пустой вопрос не отправляется.
- [ ] Ошибка восстанавливает прежний вопрос только при отсутствии нового черновика; остановка не восстанавливает вопрос автоматически.
- [ ] Очистка диалога не уничтожает текущий черновик; закрытие и повторное открытие представления сохраняют существующее поведение.
- [ ] Смена языка сохраняет черновик и активный запрос. Поиск и потоковые ответы работают как прежде.
- [ ] Рефакторинг ограничен полем сообщения и его интеграцией; не вводит новую постоянную историю, новый API модель-сервера или публичные интерфейсы только ради тестов.
- [ ] Существующие интеграционные проверки чата, ошибок, остановки и поиска проходят; необходимые проверки наблюдают поведение через ввод и кнопки, а не приватные методы. Производственная сборка с проверкой типов проходит.
- [ ] Обязательная ручная проверка не требуется: поведение не меняется, приёмка выполняется автоматическими регрессиями.
