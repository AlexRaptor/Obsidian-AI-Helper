## Parent

#59 — Поиск смысловых связей для текущей заметки.

## What to build

Для одной текущей Markdown-заметки пользователь запускает команду «Найти связи для текущей заметки» и получает в существующем чате до пяти обоснованных предложений из доступного индекса. Это первый работающий путь от редактора через индекс и модель диалога к проверяемым карточкам; выбор и запись добавляются отдельной задачей.

## Acceptance criteria

- [ ] Команда использует актуальный текст редактора, фиксирует исходную заметку и явно показывает её название. Переключение редактора не меняет привязку результата.

- [ ] Недопустимая или пустая исходная заметка, исключённая папка, исключаемое описание папки и отсутствие пригодного индекса дают понятную причину отказа до запроса модели диалога; исходная заметка не предлагается самой себе.

- [ ] Отбор идёт через настоящий индекс: актуальная часть неполного индекса допустима с предупреждением. Исключённые данные не читаются для обхода исключений и не передаются модели.

- [ ] Формируется расширенный конечный набор кандидатов с фиксированным порядком и группировкой по заметке, независимый от лимита источников обычного поиска. Существующий обычный поиск не меняет поведения.

- [ ] Уже связанные заметки исключаются по цели внутренних Markdown-ссылок, wikilinks, встраиваний и ссылок на заголовки или блоки; подписи не влияют. Примеры внутри кода и обычное упоминание названия связью не считаются; одноимённые заметки различаются.

- [ ] Корректно размеченные блоки связанных заметок исключаются из смыслового анализа обеих сторон, но их ссылки участвуют в дедупликации. При пустом остатке исходной заметки запрос не выполняется. Контракт распознавания согласован с ADR-0005 и пригоден для повторного использования при сохранении.

- [ ] Модель диалога получает материал обеих заметок и предлагает конкретные дополнения, примеры, противоречия или продолжения мысли. Общей темы недостаточно, слабые предложения не добавляются ради заполнения пяти мест.

- [ ] Карточка содержит проверенную ссылку, краткое объяснение, раскрываемый фрагмент с заголовками и числовое «Сходство фрагмента» с существующей шкалой. Число не обозначает полезность; низкое сходство само по себе не запрещает полезную связь.

- [ ] Неизвестные цели, повторные кандидаты и некорректный либо незавершённый ответ модели не становятся доступными предложениями. Содержимое заметок не исполняется как инструкция; объяснение не может внедрить дополнительные ссылки или маркеры будущего блока.

- [ ] Результат является отдельной операцией панели и не добавляет материалы или предложения в историю обычного диалога. На время запросов используется общий механизм занятости модели; базовая отмена освобождает занятость и игнорирует поздний ответ.

- [ ] При отсутствии предложений или недоступности модели видна причина без пустых карточек и без смены модели либо текстового обхода. Бюджет контекста проверяется; до реализации анализа больших заметок показывается явный отказ вместо скрытого обрезания.

- [ ] Новые действия и состояния локализованы на русский и английский, используют нативные компоненты и семантические цвета активной темы Obsidian.

- [ ] Приёмка проверяет внешнее поведение через команду или меню и элементы чата, запросы к модель-серверу и результат в заметках; основная логика не подменена. Тестовые данные преимущественно русскоязычные. Пройдены соответствующие автоматические тесты и производственная сборка с проверкой типов.

## Blocked by
