# Протокол перевода #58

## Разбор и прототип

Исходное воспроизведение: «How to take notes» останавливалась на 0% и из
команды, и из меню. Набор p1–p19, p21–p23 был полным; p20 — локальное
встраивание. Ответы p4, p7, p21, p23 потеряли маркеры ссылок, выделения,
сноски и блока. Минимальные повреждённые ответы:

```text
p4: Прочитайте ⟦AIH0:p4:0⟧, связанную заметку⟦AIH0:p4:2⟧ и полезные ссылки⟦AIH0:p4:4⟧.
p7: Записывайте важные идеи⟦AIH0:p7:0⟧, примеры⟦AIH0:p7:3⟧ и устаревшие советы⟦AIH0:p7:5⟧.
p21: Короткая справка помогает читателю.
p23: Стабильный блок ссылок.
```

Валидатор правильно запрещал запись. Усиление промпта оставило бы ту же
зависимость от копирования разметки моделью. Перевод всего абзаца без
структуры потребовал бы угадывать, куда вернуть ссылки и выделение.

Небольшой прототип — сквозные тесты `#58` через команду и меню в
`test/note-translation.test.ts`: текстовые промежутки локального шаблона
получают отдельные ID, запрос содержит их и контекст абзаца. Перед изменением
оба новых сценария не создали результат; после подключения декодирования
проходят с переводом всех трёх подписей ссылок и всех трёх выделенных фраз,
сноской и блоком. Модель в этих тестах не получает и не возвращает маркеры.
Отдельный тест полной статьи проверяет весь собранный документ, включая
переведённую самоссылку на заголовок с пробелами. Остальной корпус проверяет
вложенное выделение, смешанный язык, код/формулы внутри фраз и деление.
Это доказательство протокола и сборки на подменённой сети, не оценка
семантического качества живой модели.

## Выбор

Внешний ответ остаётся обычным JSON `{"units":[{"id":"p4~1","text":"…"}]}`.
ID без разметки сохраняются (`p1`), при нескольких промежутках ID содержит
номер промежутка (`p4~1`), при делении добавляется ID части (`p4.1~1`).
Позиции определяет оригинал, порядок записей ответа не важен. В ответе
разрешены только `units`, а в каждой записи только `id` и `text`.

Внутренний обратимый шаблон Markdown остаётся локальным: декодирование
сначала проверяет все фрагменты, затем заполняет шаблон. Прежний валидатор
дополнительно проверяет собранную единицу и зависимости. Локально
восстанавливаются пробелы, синтаксис ссылок/выделения, код, формулы, свойства,
теги, идентификаторы и встраивания; содержимое целей не читается.
Старый ответ с маркерами не проходит новый внешний контракт. Пропуск,
дубль, чужой ID, пустой текст, неверный JSON и новая разметка блокируют запись.

Механическое дробление без контекста отвергнуто как основной режим:
отдельная подпись или часть выделенной фразы может потерять согласование.
Поэтому запрос содержит упорядоченные соседние текстовые промежутки
форматированного абзаца, обозначение защищённых промежутков между ними,
раздел и предыдущие принятые пары. Защищённые значения скрыты и в контексте.
Для ограничения объёма контекст абзаца показывает до восьми промежутков,
по 64 UTF-16 единицы на каждый. Обычный абзац не дублируется в этом поле.
Контекст не является переводимой единицей и не участвует в сборке.

Компромисс: модель должна согласовывать части, но не может переносить
перевод между ID. Порядок слов при переводе между языками с разной грамматикой
может страдать, особенно на очень частом вложенном выделении или ссылке
посреди словосочетания. Большой абзац виден не целиком; при слишком малом
бюджете вспомогательный контекст удаляется. Идентификатор не доказывает
семантическую полноту текста внутри фрагмента. Эти ограничения нельзя
оценить эхом или словарной подменой сети; проверка качества ниже обязательна
на реально используемой модели. Гарантии качества любой модели нет.

Бюджет считает сериализованный новый запрос целиком, включая ID и контекст,
через существующий счётчик/оценку. Больше фрагментов означает больше JSON и
меньше текста в одном запросе. Деление, максимум три автоматических уменьшения,
снимок ADR-0004, принятые части, прогресс, непрерывное неполное начало,
арбитраж с чатом, безопасная запись и повтор открытия используют прежнюю
операцию. Дополнительных исправляющих запросов и JSON-режима сервера нет.

Ошибки показывают локализованный вид нарушения и известный ID исходного
фрагмента в прогрессе и уведомлении (включая скрытый прогресс). Неизвестные
ID из ответа не выводятся: они могут содержать произвольные данные модели.
Продолжение повторяет непринятую часть, завершение освобождает операцию.
