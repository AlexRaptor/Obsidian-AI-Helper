# Предложение смысловых связей между заметками

Дата обсуждения: 2026-10-15.
Уточнения при разборе плана: 2026-10-18.
Статус: сводный результат обсуждения подтверждён пользователем 2026-10-18. Спецификация подготовлена и опубликована в [GitHub Issue #59](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/59) с меткой `ready-for-agent`; локальная копия — [спецификация](../spec/semantic-note-links.md).

## Назначение документа

Документ фиксирует результаты обсуждения с пользователем и служит исходным материалом для последующего написания спецификации реализации в Obsidian AI Helper. Здесь описаны пользовательский сценарий, согласованное поведение и основные ограничения подхода. Детальные алгоритмы, задачи реализации и план проверки ещё предстоит определить.

## Цель

Плагин анализирует одну заметку и предлагает полезные связи с другими заметками. Пользователь просматривает предложения и выбирает подходящие. После подтверждения плагин добавляет в конец исходной заметки блок ссылок с кратким объяснением каждой связи.

Связи нужны не только для нахождения похожего содержания, но и для обнаружения полезных пересечений между мыслями.

## Согласованные решения

### Одна исходная заметка

- За один запуск обрабатывается одна текущая заметка.
- Поиск по хранилищу или папкам задаёт область поиска кандидатов для этой заметки. Это не пакетная обработка всех заметок области.
- Предложения привязаны к заметке, для которой был запущен поиск. Её название явно показывается в чате.
- Если пользователь открыл другую заметку, выбранные ссылки всё равно добавляются в исходную заметку.
- Требуется открытая Markdown-заметка с непустым анализируемым содержимым. Используется актуальный текст редактора. Заметки из исключённых папок и файлы описания папок, исключённые существующей политикой индексации, не допускаются и как исходные.

### Запуск и область поиска

- Команда «Найти связи для текущей заметки» запускает поиск кандидатов по всему хранилищу.
- Действие в контекстном меню папки запускает поиск кандидатов в этой папке для текущей заметки.
- Выбор нескольких папок должен позволять запустить поиск кандидатов в их объединённой области для текущей заметки. В локальных публичных типах Obsidian есть событие `files-menu`, позволяющее получить выбранные папки; фактическое поведение меню ещё требуется проверить в Obsidian.
- Исключённые из индекса папки не обрабатываются при любом способе запуска, в том числе при явном выборе папки. Это уточнение от 2026-10-18 заменяет прежнюю договорённость о приоритете явного выбора над исключениями: исключённые заметки отсутствуют в индексе, и отдельная обработка для них не требуется.
- Область выбранной папки включает её подпапки за вычетом исключённых. Пересекающиеся области объединяются без повторов. Пометки кандидатов из исключённых папок не нужны, поскольку такие кандидаты не формируются.
- Контекстное действие показывается только при выборе одних папок. Смешанный выбор файлов и папок не поддерживается. Если после исключений область пуста, показывается причина без обращения к модели.

Пример: открыта заметка «Сон», а поиск запущен через контекстное меню папки «Здоровье». Плагин ищет в «Здоровье» заметки, связанные со «Сном». Ссылки добавляются в «Сон»; остальные заметки папки по очереди не обрабатываются.

### Какие связи предлагать

- Предлагаются и близкие по содержанию заметки, и полезные смысловые связи: дополнения, практические примеры, противоречия, продолжения мысли.
- У каждого предложения есть конкретное краткое объяснение связи.
- Объяснение опирается на конкретное содержание обеих заметок и показывает дополнение, пример, противоречие или развитие мысли. Общей темы недостаточно; порция не дополняется слабыми предложениями ради количества.
- Степень сходства показывается отдельно от объяснения: полезная связь не обязательно означает высокое сходство содержания.
- Если в исходной заметке уже есть ссылка на найденную заметку, такую заметку исключаем из предложений. Ссылки не дублируются, в том числе если они уже добавлены в блок связанных заметок.
- Первая версия отбирает расширенный набор кандидатов через индекс хранилища, после чего модель диалога проверяет полезность связей и формирует объяснения. Это не исчерпывающий анализ всех заметок области: некоторые полезные связи могут быть пропущены.
- Числовой показатель называется «Сходство фрагмента»: он отражает сходство раскрываемого фрагмента найденной заметки с исходным текстом, а не полезность связи. Используется привычная цветовая шкала; минимальное сходство не является обязательным условием полезности.
- Исходная заметка никогда не является собственным кандидатом. Существующими связями считаются внутренние Markdown-ссылки, wikilinks, встраивания и ссылки на разделы или блоки — по целевой заметке независимо от подписи. Примеры внутри кода и простое упоминание названия ссылками не считаются.

### Покрытие и объём анализа

- Поиск разрешён по актуальной части неполного индекса с явным предупреждением об ограниченном покрытии. Если пригодных записей нет, предлагается индексация; обращения к модели диалога не происходит.
- Недоступность модели показывается как ошибка с возможностью повтора. Автоматического переключения на другую модель или на текстовый поиск нет.
- Большие заметки анализируются по фрагментам с заголовками и окружающим контекстом. Для исходной заметки материал отбирается из разных частей, а не только из начала; для кандидата — по предполагаемой связи. Об анализе по фрагментам сообщается явно.
- Если даже отобранный материал не помещается в контекст модели, обработка останавливается с объяснением, без скрытого обрезания.
- Все блоки связанных заметок с корректными маркерами исключаются из смыслового анализа, включая перенесённые блоки. Их ссылки по-прежнему учитываются для предотвращения дублей. Если после исключения блоков исходная заметка пуста, поиск не запускается.

### Просмотр в существующем чате

- Предложения показываются в существующем чате плагина.
- Представление опирается на уже реализованный поиск по заметкам в чате: ссылка на заметку, раскрываемый фрагмент, числовая степень сходства и привычная цветовая шкала.
- Дополнительно показываются объяснение связи и возможность выбрать предложение для добавления.
- Пользователь может выбрать или отклонить предложение. Редактирование объяснения перед добавлением не требуется.
- Отказы не запоминаются между поисками: при следующем запуске отклонённое предложение может появиться снова.
- Предложения отображаются как отдельный результат операции и автоматически не добавляются в историю сообщений модели диалога. Проанализированные тексты также не становятся контекстом последующих обычных вопросов.

### Количество и дополнительные предложения

- В настройках задаётся «Количество предложений связей».
- Значение по умолчанию — 5.
- Допустимы целые значения от 1 до 20. Размер порции фиксируется при запуске; изменение настройки применяется к следующему поиску.
- Сначала показывается одна порция указанного размера. Если полезных связей меньше, показывается доступное количество.
- Кнопка «Показать ещё» выдаёт следующую порцию того же размера без повторения уже показанных предложений в рамках этого поиска.
- При запросе следующей порции выбор ранее отмеченных предложений сохраняется.
- Отсутствие повторов внутри одного поиска не означает сохранения истории отказов между отдельными запусками.
- При запуске фиксируются расширенный набор кандидатов и порядок их проверки. «Показать ещё» продолжает обработку этого набора до заполнения порции полезными связями или исчерпания кандидатов.
- После исчерпания набора показывается «Больше предложений в этом поиске нет». Это не утверждение об отсутствии других связей в хранилище.
- При ошибке или отмене готовые предложения и выбор сохраняются. Незавершённая порция не показывается; её получение можно повторить. Отмена останавливает обработку, оставляя готовые результаты. Если предложений ещё нет, показывается причина завершения без пустых карточек.

### Добавление ссылок

- Пользователь подтверждает выбор действием «Добавить выбранные связи».
- В конец исходной заметки добавляется блок связанных заметок.
- В блок попадают выбранные ссылки и краткие объяснения причин связей. Сохранение в заметку фрагментов и числовых оценок сходства не согласовывалось.
- При повторном добавлении существующий блок дополняется: прежние ссылки и объяснения сохраняются, новые подтверждённые связи добавляются туда же.
- Дополняется только блок в конце заметки. Если пользователь перенёс блок в другое место, он сохраняется, а в конце создаётся новый блок. Уже существующие ссылки по-прежнему исключаются независимо от их расположения.
- Блок распознаётся по невидимым HTML-маркерам границ. После закрывающего маркера допустимы только пробельные символы; если ниже появился текст, создаётся новый блок в конце. Заголовок — «Связанные заметки», формат строки — `- [[Заметка]] — объяснение`. Ручные правки внутри распознанного блока сохраняются. Новый заголовок локализуется по текущему языку интерфейса, существующий сохраняется; маркеры одинаковы для обоих языков. Точные значения маркеров ещё нужно определить.
- При повреждённых или неоднозначных границах блока запись останавливается с объяснением, выбор сохраняется; плагин не пытается угадывать границы текста.
- Перед записью повторно проверяются уже существующие ссылки. Переименования и перемещения найденных заметок отслеживаются; ссылки формируются по актуальному расположению. Найденные заметки с изменённым содержимым и удалённые заметки пропускаются с объяснением; остальные выбранные связи добавляются.
- Связи можно добавлять несколькими действиями в рамках одного поиска. Добавленные карточки помечаются «Добавлено» и исключаются из выбора; остальные сохраняются. Собственное добавление блока не считается посторонним изменением исходной заметки. Во время записи повторное нажатие блокируется. Итог показывает число добавленных связей и причины пропуска остальных.

### Изменения исходной заметки

- Поиск использует содержимое исходной заметки на момент запуска.
- Если перед добавлением содержимое изменилось, выбор сохраняется для просмотра, но запись блокируется до нового поиска. Новый поиск начинается без отметок: пользователь подтверждает предложения по актуальному содержимому.
- Переименование и перемещение при неизменном содержимом разрешены: операция отслеживает ту же заметку. При удалении исходной заметки добавление блокируется.

### Срок жизни поиска

- Одновременно действует один поиск связей. Новый запуск заменяет предыдущий; при несохранённом выборе пользователь получает предупреждение о его потере.
- Предупреждение предлагает действия «Начать новый поиск» и «Отмена».
- Простое скрытие и повторное открытие панели сохраняет поиск. Перезапуск плагина сбрасывает его.
- Закрытие панели с уничтожением её экземпляра и очистка диалога сбрасывают поиск; при несохранённом выборе требуют подтверждения.
- Во время обращения к модели доступна отмена, а другие операции модели блокируются с понятным сообщением. После получения порции обычное общение разрешено, предложения сохраняются.

## Основной пользовательский сценарий

1. Пользователь открывает заметку, для которой хочет найти связи.
2. Запускает команду поиска по всему хранилищу либо действие в контекстном меню папки или нескольких папок.
3. Получает в существующем чате первую порцию предложений с названием исходной заметки.
4. Изучает объяснения, фрагменты и степень сходства, выбирает подходящие предложения.
5. При необходимости нажимает «Показать ещё» и продолжает выбор.
6. Нажимает «Добавить выбранные связи».
7. Плагин добавляет выбранные ссылки с объяснениями в блок в конце исходной заметки либо дополняет существующий блок.

## Детали следующей спецификации

Следующие инженерные детали не являются уже выбранными алгоритмами или готовой реализацией:

- Точные значения маркеров блока связанных заметок, однозначное распознавание границ и безопасное формирование Markdown-ссылок и объяснений.
- Размер расширенного набора кандидатов, ранжирование, подбор фрагментов из разных частей исходной заметки, расчёт сходства и учёт бюджета контекста выбранной модели.
- Фиксация содержимого и настроек поиска, проверка актуальности кандидатов при обработке следующих порций и перед записью, отслеживание переименований и перемещений.
- Безопасная запись на основе актуального текста без потери параллельных правок, обработка ошибки записи и повторной попытки без дублей.
- Поддержка актуального текста редактора при распознавании ссылок: нельзя полагаться на синхронное обновление кэша метаданных без проверки.
- Автоматические проверки согласованных переходов и инвариантов; отдельная проверка в Obsidian для фактического меню нескольких папок и поведения, зависящего от редактора и жизненного цикла панели, если автоматических проверок недостаточно.

### Факты существующей реализации

- `src/note-index.ts`: исключённые заметки отсутствуют в допустимой области индекса; существующий поиск работает по актуальным проиндексированным фрагментам. Его ограничения выдачи не являются готовой пагинацией предложений связей.
- `src/chat-view.ts`, `src/similarity-appearance.ts`: уже есть показ ссылки, раскрываемого фрагмента и числового сходства с цветовой шкалой. Текущая оценка относится к запросу и фрагменту, а не к полезности связи двух заметок.
- `src/conversation-model.ts`: операции модели уже используют общий механизм исключения одновременных обращений.
- `node_modules/obsidian/obsidian.d.ts`: публичное событие `files-menu` принимает массив `TAbstractFile[]`; минимальная версия плагина допускает его использование. Наличие типов не подтверждает поведение File Explorer в интерфейсе.

В начале обсуждения предлагалось не переписывать исходный текст ради встраивания ссылок и не добавлять автоматически симметричные блоки во вторые заметки, опираясь на обратные ссылки Obsidian. Отдельного подтверждения этих предложений не было. Утверждённый сценарий — добавление блока в исходную заметку; расширять изменения на другие заметки без отдельного решения не следует.

## Ориентир для следующего этапа

При подготовке спецификации следует использовать согласованные решения выше как продуктовую основу, изучить существующие поиск по заметкам и представление результатов в чате, проверить условие множественного выбора папок и явно отделить новые проектные решения от договорённостей этого документа. Код и файлы реализации в рамках обсуждения этой функции не менялись.
