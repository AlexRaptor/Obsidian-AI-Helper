# Предложение смысловых связей между заметками

Дата обсуждения: 2026-10-15.
Статус: продуктовые договорённости сохранены; спецификация реализации ещё не написана.

## Назначение документа

Документ фиксирует результаты обсуждения с пользователем и служит исходным материалом для последующего написания спецификации реализации в Obsidian AI Helper. Здесь описаны пользовательский сценарий и согласованное поведение. Техническая архитектура, алгоритмы, задачи реализации и план проверки пока не определены.

## Цель

Плагин анализирует одну заметку и предлагает полезные связи с другими заметками. Пользователь просматривает предложения и выбирает подходящие. После подтверждения плагин добавляет в конец исходной заметки блок ссылок с кратким объяснением каждой связи.

Связи нужны не только для нахождения похожего содержания, но и для обнаружения полезных пересечений между мыслями.

## Согласованные решения

### Одна исходная заметка

- За один запуск обрабатывается одна текущая заметка.
- Поиск по хранилищу или папкам задаёт область поиска кандидатов для этой заметки. Это не пакетная обработка всех заметок области.
- Предложения привязаны к заметке, для которой был запущен поиск. Её название явно показывается в чате.
- Если пользователь открыл другую заметку, выбранные ссылки всё равно добавляются в исходную заметку.

### Запуск и область поиска

- Команда «Найти связи для текущей заметки» запускает поиск кандидатов по всему хранилищу.
- Действие в контекстном меню папки запускает поиск кандидатов в этой папке для текущей заметки.
- Желаемый сценарий: выбрать несколько папок и запустить из контекстного меню поиск кандидатов в этих папках для текущей заметки. Это требование условно: нужно проверить, позволяет ли Obsidian реализовать такое действие для нескольких выбранных папок.
- В настройках задаются папки исключения. При поиске по всему хранилищу эти папки пропускаются.
- Явный выбор папки имеет приоритет над исключением: если пользователь запускает поиск через контекстное меню выбранной папки, поиск должен выполняться в ней, даже если эта папка указана в исключениях. Правило распространяется и на явно выбранные папки при множественном выборе.

Пример: открыта заметка «Сон», а поиск запущен через контекстное меню папки «Здоровье». Плагин ищет в «Здоровье» заметки, связанные со «Сном». Ссылки добавляются в «Сон»; остальные заметки папки по очереди не обрабатываются.

### Какие связи предлагать

- Предлагаются и близкие по содержанию заметки, и полезные смысловые связи: дополнения, практические примеры, противоречия, продолжения мысли.
- У каждого предложения есть конкретное краткое объяснение связи.
- Степень сходства показывается отдельно от объяснения: полезная связь не обязательно означает высокое сходство содержания.
- Если в исходной заметке уже есть ссылка на найденную заметку, такую заметку исключаем из предложений. Ссылки не дублируются, в том числе если они уже добавлены в блок связанных заметок.

### Просмотр в существующем чате

- Предложения показываются в существующем чате плагина.
- Представление опирается на уже реализованный поиск по заметкам в чате: ссылка на заметку, раскрываемый фрагмент, числовая степень сходства и привычная цветовая шкала.
- Дополнительно показываются объяснение связи и возможность выбрать предложение для добавления.
- Пользователь может выбрать или отклонить предложение. Редактирование объяснения перед добавлением не требуется.
- Отказы не запоминаются между поисками: при следующем запуске отклонённое предложение может появиться снова.

### Количество и дополнительные предложения

- В настройках задаётся «Количество предложений связей».
- Значение по умолчанию — 5.
- Сначала показывается одна порция указанного размера. Если полезных связей меньше, показывается доступное количество.
- Кнопка «Показать ещё» выдаёт следующую порцию того же размера без повторения уже показанных предложений в рамках этого поиска.
- При запросе следующей порции выбор ранее отмеченных предложений сохраняется.
- Отсутствие повторов внутри одного поиска не означает сохранения истории отказов между отдельными запусками.

### Добавление ссылок

- Пользователь подтверждает выбор действием «Добавить выбранные связи».
- В конец исходной заметки добавляется блок связанных заметок.
- В блок попадают выбранные ссылки и краткие объяснения причин связей. Сохранение в заметку фрагментов и числовых оценок сходства не согласовывалось.
- При повторном добавлении существующий блок дополняется: прежние ссылки и объяснения сохраняются, новые подтверждённые связи добавляются туда же.

## Основной пользовательский сценарий

1. Пользователь открывает заметку, для которой хочет найти связи.
2. Запускает команду поиска по всему хранилищу либо действие в контекстном меню папки или нескольких папок.
3. Получает в существующем чате первую порцию предложений с названием исходной заметки.
4. Изучает объяснения, фрагменты и степень сходства, выбирает подходящие предложения.
5. При необходимости нажимает «Показать ещё» и продолжает выбор.
6. Нажимает «Добавить выбранные связи».
7. Плагин добавляет выбранные ссылки с объяснениями в блок в конце исходной заметки либо дополняет существующий блок.

## Что ещё нужно определить при написании спецификации

Основной продуктовый сценарий согласован. Следующие детали не обсуждались достаточно подробно; их нельзя выдавать за уже утверждённые требования:

- Точное поведение вложенных папок, пересекающихся областей при множественном выборе и исключённых подпапок внутри явно выбранной родительской папки. Утверждён приоритет явно выбранной папки над её собственным исключением.
- Точный формат, заголовок и способ распознавания блока связанных заметок, в том числе после ручного редактирования пользователем.
- Правила ранжирования и оценки сходства для разных типов смысловых связей. Высокое сходство не должно автоматически трактоваться как единственный вид полезной связи.
- Поведение при отсутствии предложений, исчерпании результатов, отмене, ошибке и повторном нажатии кнопки добавления.
- Поведение, если исходная или найденная заметка изменена, перемещена либо удалена до подтверждения, а также если ссылка добавлена пользователем после поиска.
- Судьба предложений при новом поиске, закрытии чата и перезапуске плагина. Согласовано сохранение выбора при «Показать ещё», но не его долговременное хранение.
- Допустимые значения настройки количества предложений и связь новых настроек исключений с существующими настройками поиска.
- Возможность контекстного действия для нескольких выбранных папок в публичном API Obsidian; способ замены этого сценария при ограничениях API с пользователем не согласован.

В начале обсуждения предлагалось не переписывать исходный текст ради встраивания ссылок и не добавлять автоматически симметричные блоки во вторые заметки, опираясь на обратные ссылки Obsidian. Отдельного подтверждения этих предложений не было. Утверждённый сценарий — добавление блока в исходную заметку; расширять изменения на другие заметки без отдельного решения не следует.

## Ориентир для следующего этапа

При подготовке спецификации следует использовать согласованные решения выше как продуктовую основу, изучить существующие поиск по заметкам и представление результатов в чате, проверить условие множественного выбора папок и явно отделить новые проектные решения от договорённостей этого документа. Код и файлы реализации в рамках обсуждения этой функции не менялись.
