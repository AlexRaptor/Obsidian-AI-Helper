# Ручная проверка обновления заметок (#18)

Автоматические тесты используют публичный модуль поиска и подменяемый HTTP-транспорт. Они не заменяют проверку событий и меню настоящего Obsidian. Реальная проверка Obsidian/LM Studio для #18 пока не проводилась.

1. Выполнить `npm run build`, скопировать `main.js`, `manifest.json`, `styles.css` в каталог плагина тестового хранилища, перезагрузить Obsidian. Использовать заметки из `test/fixtures/manual-vault-index/vault`.
2. Настроить embedding-модель LM Studio, исключить `Private`, явно построить индекс. Включить поиск по заметкам в чате. Убедиться, что обычный диалог доступен при выключенном поиске.
3. Проверить значение задержки в настройках: по умолчанию 3 секунды, затем установить 5 секунд. Изменить время отправления поезда в `Private-public/Train.md` несколько раз подряд. Обработка должна начаться после выбранной задержки без новых изменений файла. До завершения обновления старый текст не должен использоваться; после обновления запрос должен возвращать последнее время. Проверить журнал LM Studio: обновляется только изменённая заметка, без повторной обработки остальных заметок.
4. Создать новую разрешённую Markdown-заметку. После короткой задержки она должна стать доступна для поиска, а покрытие индекса измениться. Создание заметки в `Private` не отправляет её текст серверу.
5. Переименовать заметку с поездом и папку с ней. Новый ответ должен содержать новый путь, заголовок и рабочую ссылку на источник. Перенести заметку в `Private`: она немедленно перестаёт участвовать в поиске. Повторить во время обработки длинной заметки, затем удалить её: поздний ответ не возвращает источник.
6. Переименовать исключённую папку `Private` в `Secrets` внутри Obsidian: настройки должны сохранить исключение по новому пути, включая вложенные исключения. Папка `Private-public` остаётся разрешённой. При внешнем удалении исключённой папки её путь остаётся в настройках с предупреждением.
7. Выключить автоматическое обновление в настройках. Изменить разрешённую заметку: индекс становится неполным, HTTP-запрос не выполняется. Обновить её через контекстное меню файла и через команду индексации активной заметки в палитре. Оба действия обновляют только выбранную заметку; исключённая заметка отклоняется.
8. Остановить LM Studio. Изменить заметку, дождаться ошибки обновления, затем сделать несколько правок и создать новую заметку. Новых попыток подключения после первой ошибки быть не должно. Удалить или переименовать ожидающую заметку: устаревшего пути в поиске нет.
9. Запустить LM Studio и выполнить «Повторить ожидающие обновления индекса». Индексируется последняя версия ожидающих заметок; остальные не пересчитываются. Повторить восстановление через выключение/включение поиска и через перезапуск плагина. При выключенной автоматизации включение поиска и перезапуск не запускают обработку; ручной повтор доступен.
10. При выключенном Obsidian изменить, создать и удалить заметки. После запуска покрытие сверяется с хранилищем, изменения обрабатываются при включённой автоматизации. Повторить с паузой: изменения остаются в очереди до ручного повтора.
11. С полностью построенным индексом перезапустить Obsidian дважды. Плагин должен быстро зарегистрировать интерфейс, а сверка после готовности хранилища сохранить исходное число разрешённых заметок без повторных embedding-запросов. Повторить после переименования исключённой папки: новое имя должно сразу отражаться даже в уже открытых настройках. При очистке индекса во время фоновой сверки он остаётся пустым.
12. Проверить настройки, статусы и ошибки на английском и русском; при недоступной embedding-модели обычный диалог с доступной моделью диалога продолжает работать.

Очередь и индекс сохраняются в локальном IndexedDB. Тексты заметок отправляются настроенному embedding-серверу после явной первой индексации; автоматизация включена по умолчанию и может быть приостановлена в настройках. Периодических проверок сервера нет.
