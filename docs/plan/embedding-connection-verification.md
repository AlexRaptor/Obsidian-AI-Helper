# Проверка подключения embedding-модели (#14)

Автоматические проверки используют подменяемый HTTP-транспорт. Они проверяют POST `/embeddings`, необязательный Bearer-токен, индексы входных текстов, размерность и пригодность векторов, ошибки и поздние ответы. Список моделей не подтверждает поддержку embeddings. Проверка подключения отправляет только два синтетических текста, не читает заметки и не оценивает смысловое качество модели.

## Ручная приёмка в Obsidian и LM Studio

Статус: ручная проверка успешно проходит по подтверждению пользователя от 2026-10-10. Версии Obsidian/LM Studio, фактический API-идентификатор embedding-модели, размерность вектора и результаты отдельных шагов не сообщены.

1. Выполнить `npm run build`. Скопировать `main.js`, `manifest.json` и `styles.css` в `.obsidian/plugins/<id из manifest.json>/` тестового хранилища. Перезагрузить настольный Obsidian.
2. В LM Studio загрузить выбранную пользователем embedding-модель, запустить OpenAI-совместимый сервер и записать её фактический API-идентификатор. Список моделей можно использовать для поиска идентификатора, но не как результат проверки embeddings. [Документация LM Studio](https://lmstudio.ai/docs/developer/openai-compat/embeddings) описывает POST `/v1/embeddings` с `model` и `input`.
3. Сохранить рабочее подключение модели диалога. В разделе «Поиск по заметкам: embedding-модель» задать отдельный адрес, например `http://localhost:1234/v1`, API-идентификатор из предыдущего шага и ключ, если сервер требует авторизацию. Убедиться, что интерфейс показывает именно адрес назначения embeddings.
4. Нажать «Проверить embeddings». Ожидать сообщение об успешной проверке с размерностью вектора. В журнале сервера проверить POST `/v1/embeddings` с указанной моделью и двумя синтетическими текстами. Без API-ключа заголовок Authorization отсутствует. Содержимое заметок не отправляется.
5. Перезагрузить Obsidian: три параметра embeddings должны сохраниться, подключение модели диалога — остаться прежним. Статус проверки после перезапуска требует повторной проверки.
6. Проверить неверный ключ при включённой авторизации, неверный API-идентификатор, модель без поддержки embeddings и остановленный сервер. Ожидать понятную ошибку соответствующего класса. Повторить на EN/RU. При зависшем запросе проверка завершается через 15 секунд.
7. Во время проверки изменить адрес, ключ или модель, в том числе вернуть прежнее значение; затем дождаться старого ответа. Старый ответ не должен подтверждать новое подключение. Повторить с двумя быстрыми нажатиями кнопки и закрытием настроек.
8. Задать разрешённый пользователем внешний HTTP(S)-адрес OpenAI-совместимого сервера. Интерфейс должен показывать внешний адрес назначения; запрета внешних серверов нет. Авторизация задаётся отдельным полем ключа; адреса с данными авторизации, query или fragment отклоняются до отправки текста.
9. Отправить сообщение модели диалога и проверить чтение потокового текста, остановку генерации и обычный ответ сервера без SSE. Изменения подключения embeddings не должны менять адрес, ключ, модель и историю диалога.

Записать версии Obsidian/LM Studio, фактический API-идентификатор, размерность, результаты шагов и ошибки консоли, не записывая API-ключи.
