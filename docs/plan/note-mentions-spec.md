# Упоминания заметок в чате: выбор через @ и снимки при отправке

Статус: требования и подход к тестированию согласованы пользователем; готово к реализации. Реализация не начата.

Опубликована в [GitHub Issue #33](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/33) с меткой `ready-for-agent`.

## Problem Statement

Пользователь хочет обсуждать с моделью текущую открытую заметку и другие заметки хранилища, явно указывая их в сообщении. Сейчас чат принимает только текст вопроса, а найденные поиском источники не заменяют явный выбор заметок и не сохраняют переданное содержимое для последующих вопросов.

Пользователю важно быстро выбрать текущую заметку, сопоставить несколько заметок в одном вопросе и продолжить обсуждение без повторного прикрепления. Если он изменил заметку во время подготовки сообщения, модель должна получить исправленный текст. При этом обычный символ @ и адреса электронной почты должны оставаться обычным текстом.

## Solution

Добавить выбор заметок через @ в поле сообщения. При вводе @ в начале строки или после пробела открывается список Markdown-заметок хранилища. Без фильтра первой предлагается последняя открытая заметка, с которой пользователь перешёл в чат. Ввод после @ фильтрует список по названию и пути, поддерживая несколько слов и сокращённый ввод с пропуском букв.

После явного выбора в сообщении появляется цветовое упоминание с названием заметки и доступным полным путём. Пользователь может упомянуть несколько разных заметок. Упоминание привязывается к выбранной заметке сразу, но её актуальный текст читается при отправке. Отправленные снимки сохраняются с сообщением в истории диалога для последующих вопросов. Изменение исходных заметок после отправки не переписывает историю.

Отдельная кнопка прикрепления не нужна. Содержимое не передаётся автоматически из-за наличия открытой заметки или простого ввода @. Недоступная заметка, неизвестная вместимость модели или недостаточный контекст блокируют отправку с объяснением и сохраняют черновик.

## Implementation Decisions

- Расширить поле сообщения и представление чата поддержкой явных упоминаний, сохранив обычный текстовый ввод, отправку, остановку, очистку, локализацию и работу с черновиком. Выбранные упоминания являются отдельными элементами внутри сообщения; простой textarea не обеспечивает их требуемое отображение.
- Список выбора открывается на набранный @ в начале строки либо после пробела, вне кода. Ввод после @ образует фильтр, в том числе многословный. Неподтверждённый текст не становится вложением.
- Адреса электронной почты не открывают список. Вставка текста не создаёт упоминания автоматически. Escape закрывает список, сохраняя введённый текст.
- Стрелки меняют выбранный элемент. Tab и щелчок подтверждают выбор. Enter подтверждает только после перемещения стрелками; в остальных случаях сохраняет существующее поведение отправки. Требуемое состояние выбора должно отличать явную навигацию от первой автоматически показанной подсказки.
- Каталог выбора включает все Markdown-заметки хранилища независимо от поискового индекса и исключённых папок. Для выбора не требуется построение индекса или embedding-модель.
- Текущая заметка — последняя открытая заметка, с которой пользователь перешёл в чат. Её нужно определить до потери фокуса редактора, а не получать как активное представление уже после активации чата. При отсутствии текущей заметки другие заметки доступны.
- Без фильтра текущая заметка предлагается первой, остальные упорядочены по пути. Имена с одинаковым написанием различимы по пути. При отсутствии совпадений отображается локализованное сообщение, фильтр сохраняется.
- Фильтрация нечувствительна к регистру. Каждый разделённый пробелами токен должен совпасть с полным путём; порядок токенов относительно друг друга не ограничен.
- Для каждого токена поддержать как цельную подстроку, так и последовательность символов с пропусками. Порядок букв внутри токена сохраняется; пропуски могут включать разделители папок. Пример project monexa находит 1.Projects/Monexa.md, Docs/ProjectDescriptionMonexa/README.md и Monexa/Project.md, но не Projects/Another.md. Пример projemonex находит первые два пути.
- При фильтрации цельные совпадения выше совпадений с пропусками; более компактные совпадения с пропусками предпочтительнее разреженных. При равной релевантности порядок определяется путём. Приоритет текущей заметки применяется к списку без фильтра.
- Подтверждённое упоминание хранит привязку к выбранной заметке независимо от текста фильтра и последующих переключений вкладок. Переименование сохраняет привязку и обновляет отображаемое название. Выбор другого файла требует нового или заменённого упоминания.
- Упоминание выделяется цветом активной темы Obsidian, имеет название и доступный полный путь. Цвет дополняет форму и текст, а не является единственным различием. Использовать публичные компоненты и API Obsidian, семантические переменные темы и необходимый минимум собственного CSS.
- Черновик должен содержать текст и подтверждённые упоминания. Удаление элемента удаляет его привязку. Несколько упоминаний одного файла дают один снимок на отправляемое сообщение; вложение исчезает после удаления последнего упоминания этого файла.
- При отправке сформировать снимки всех уникальных выбранных заметок. Читать актуальный текст открытого редактора, включая несохранённые изменения; для заметок без открытого редактора читать содержимое хранилища. Предпочитать актуальный редактор представлению чтения, как в существующем разборе заметок.
- Не перечитывать заметки из-за простого переключения фокуса или после отправки для изменения уже сохранённых снимков. Повторная отправка нового запроса, включая повтор после ошибки, формирует новые снимки из актуального содержимого.
- Снимок включает название, путь и полный Markdown со свойствами. Внутренние ссылки и встраивания остаются текстом; содержимое связанных заметок, изображений и других файлов не раскрывается.
- Если хотя бы одна выбранная заметка удалена или недоступна, блокировать весь запрос, объяснить причину и сохранить черновик. Закрытие вкладки само по себе не является ошибкой.
- Расширить модель сообщения и историю диалога, чтобы успешно отправленный и завершённый ход сохранял снимки с исходным сообщением. Последующие запросы сериализуют эту историю с прежними снимками. Не ограничиваться контекстом только текущего запроса, как сейчас происходит с найденными поиском источниками.
- Видимый текст вопроса и его упоминания должны оставаться отличимы от полного содержимого снимков, передаваемого модели. Содержимое заметок — данные контекста, а не дополнительные системные инструкции; использовать существующий подход к отделению источников от вопроса.
- Сохранить OpenAI-совместимый текстовый контракт модель-сервера: снимки передаются в контексте сообщений, отдельная загрузка файлов не требуется. Доступ к заметкам выполнять через публичные API Obsidian, без Node-only зависимостей.
- Сохранить выбранный режим поиска. Полные снимки выбранных заметок являются обязательным контекстом, найденные материалы дополняют их только в пределах оставшегося бюджета. Явное вложение заметки и найденный источник остаются разными понятиями.
- Проверка бюджета учитывает итоговый запрос: системный контекст, историю со снимками, новый вопрос, новые снимки, служебное представление контекста, резерв ответа и существующий дополнительный запас. Использовать существующие механизмы определения окна и подсчёта токенов.
- Для сообщения с вложениями нужен известный лимит модели: автоматический либо корректно заданный вручную в существующих настройках. При неизвестном лимите блокировать отправку и объяснять, где его задать. Не использовать запасное значение 8192 для этого сценария.
- При недостаточном бюджете не обрезать и не пересказывать снимки, не исключать выбранные заметки и не усекать историю молча. Сохранять черновик и показывать понятную причину блокировки.
- Упоминания без вопроса или инструкции недостаточны для отправки: сохранить черновик и предложить добавить вопрос.
- Ошибка или остановка не добавляет ход в историю следующих запросов. Частичный ответ остаётся видимым. При ошибке восстановить вопрос с упоминаниями, только если пользователь не начал новый черновик. Остановка автоматически вопрос не восстанавливает.
- Очистка диалога удаляет историю и принадлежащие ей снимки, прерывая активный запрос. Сохранить существующее поведение черновика: очистка истории сама по себе не должна уничтожать набираемое сообщение. Поздний ответ очищенного или остановленного запроса не возвращает снимки в историю.
- Все новые строки интерфейса локализовать на английский и русский. Изменение локали не должно терять черновик, упоминания или активный запрос.

## Testing Decisions

- Основной и предпочтительно единственный уровень проверки функции — интеграционные тесты представления чата через ввод, клавиатуру, выбор из списка, удаление упоминаний и кнопки. Наблюдать пользовательский результат и сообщения на существующей границе клиента модель-сервера. Не добавлять публичные тестовые интерфейсы для внутренних обработчиков, хранения токенов или функций ранжирования.
- Использовать существующую подмену Obsidian API, управляемое хранилище заметок и модель-сервер с наблюдаемыми запросами. При необходимости расширить вспомогательную модель DOM и событий для нового поля ввода, не подменяя ею продуктовую валидацию или решение о выборе заметки.
- Проверить представление чата, интеграцию с историей диалога, чтением открытых редакторов и хранилища, поиском и проверкой контекста через один пользовательский сценарий. Дополнительные прямые тесты существующей модели диалога допустимы для её изменённого публичного контракта, если интеграционный сценарий не покрывает инвариант; не дублировать одинаковые проверки на нескольких уровнях.
- Образец — существующие тесты жизненного цикла чата: ввод вопроса, отправка, наблюдение запроса, ошибка, повтор, очистка и поздний ответ. Тесты интеграции поиска дают образец проверки состава контекста, истории и бюджета. Тесты остановки дают образец работы с частичным ответом и отменой. Тесты разбора заметок дают образец несохранённых правок, переименования и событий хранилища.
- Тестировать внешнее поведение: видимые названия и пути, порядок результатов, доступность действий, текст ошибок, сохранение черновика, полный и неизменный состав отправленных снимков. Не закреплять конкретную формулу оценки релевантности, внутренние структуры данных, CSS-классы или приватные методы.
- Проверить список без фильтра с текущей заметкой, без текущей заметки, одинаковые названия, отсутствие результатов и заметки из исключённых папок. Предпочитать русскоязычные данные, сохранив согласованные примеры project monexa и projemonex как отдельные языковые сценарии.
- Проверить многословный поиск с перестановкой слов, нечувствительность к регистру, отрицательный пример, сокращение без пробелов, сохранение порядка букв и приоритет цельного совпадения над совпадением с пропусками.
- Проверить стрелки, Tab, щелчок, Enter до и после навигации, Escape, обычный @, почту, код и вставленный текст. Подтверждение выбора должно быть необходимым условием появления контекста в запросе.
- Проверить несколько разных заметок, повторное упоминание одного файла, удаление одного повторения и последнего упоминания. Наблюдать фактическую передачу одного снимка на уникальную заметку в сообщении.
- Проверить изменение заметки между выбором и отправкой, несохранённые правки редактора, переключение вкладок, закрытие вкладки, переименование, удаление и ошибку чтения одного из нескольких файлов. Блокировка сохраняет весь черновик и не отправляет частичный набор вложений.
- После успешного ответа изменить исходную заметку и задать вопрос без новых упоминаний: запрос должен содержать старый снимок. После очистки старые снимки не должны появляться в новом запросе. Новый явный выбор и повторная отправка читают актуальную версию.
- Проверить известное автоматическое окно, ручной приоритет, неизвестный лимит и недостаточную вместимость с историей, несколькими вложениями и резервом ответа. Проверить включённый поиск: полные снимки остаются обязательными, поисковые материалы используют оставшийся бюджет.
- Проверить ошибку с восстановлением вопроса и упоминаний, ошибку при уже набранном новом черновике, повтор с обновлёнными заметками, остановку и поздний результат после очистки. Неуспешный ход не должен попасть в историю последующих запросов.
- Проверить сообщение только с упоминаниями, локализацию новых строк и сохранение черновика при смене языка. Цвет, реальный курсор, редактирование отдельных элементов, клавиатурную доступность и отображение в разных темах дополнительно проверяет пользователь в Obsidian: вспомогательная модель DOM не заменяет эту проверку.
- При реализации выполнить релевантные Vitest-проверки, регрессии чата, поиска, истории и остановки, затем производственную сборку с проверкой типов. Подготовить ручные сценарии в docs/testing, а отдельное тестовое хранилище и генератор — в docs/fixtures. Автоматические проверки выполняет агент, ручную проверку выполняет пользователь; Computer Use только по отдельной явной просьбе.
- Пользователь подтвердил основной уровень тестирования: действия в представлении чата, видимый результат и содержимое запросов модель-серверу.

## Out of Scope

- Передача выделенного фрагмента заметки; она отложена на следующий этап, но модель упоминания и снимка должна допускать такое расширение.
- Автоматическое раскрытие связанных заметок, содержимого изображений и других встроенных файлов.
- Автоматическое редактирование заметок по ответам модели, применение патчей и изменение файлов хранилища этой функцией.
- Отдельная кнопка прикрепления, фиксированный плейсхолдер @note и автоматическая передача текущей заметки без подтверждённого выбора.
- Автоматическое усечение или пересказ заметок и молчаливое удаление истории ради вместимости.
- Поиск заметок через embedding-модель как обязательное условие работы списка упоминаний.
- Исправление опечаток с перестановкой, заменой или добавлением букв: согласованный сокращённый поиск сохраняет порядок введённых букв и допускает пропуски.
- Новая система постоянного хранения диалогов или их восстановления после перезапуска; функция расширяет существующий жизненный цикл истории.

## Further Notes

Требования согласованы в обсуждении. Первоначальный сценарий только текущей заметки был расширен пользователем до выбора любых Markdown-заметок через @ и нескольких упоминаний в одном сообщении. Передача выделения остаётся отложенной. После подтверждения основного сценария пользователь дополнительно потребовал поддержку projemonex без пробелов; требование включено в спецификацию.

Доменный словарь различает упоминание заметки, вложение заметки, снимок заметки и источник, найденный поиском. Решение о привязке при выборе и снимке при отправке закреплено отдельным ADR; локальный поисковый индекс остаётся восстанавливаемым производным представлением и не становится условием доступа к явным вложениям.

Подсчёт токенов следует возможностям существующего клиента и может использовать оценку, если сервер не предоставляет точный подсчёт. Проверка вместимости должна учитывать весь контекст и резерв ответа; известный размер окна не делает оценку токенов точной для каждой модели.

Сейчас подготовлена только спецификация. Реализация, автоматические тесты функции и ручная проверка не выполнялись. Пользователь подтвердил предусмотренный to-spec подход к тестированию; тикет предназначен для публикации с меткой ready-for-agent.
