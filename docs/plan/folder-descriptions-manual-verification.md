# Ручные проверки описаний папок и разбора заметок

Статус: требования к подготовке ручных проверок будущей реализации. Этот документ не является отчётом о выполненном тестировании.

## Обязательное тестовое хранилище

Для ручных проверок нужно не только написать чеклист, но и подготовить воспроизводимые тестовые данные и фактически создать отдельное тестовое хранилище Obsidian. Рабочее хранилище пользователя для этих проверок не используется.

Каждый документ ручного тестирования должен содержать:

1. Способ создания отдельного хранилища и установки собранной версии плагина.
2. Готовый набор файлов либо генератор, создающий точные пути и содержимое. Одного перечня предполагаемых заметок недостаточно.
3. Настройки плагина и Obsidian, необходимые сценарию, включая язык, имя описания, исключения, модель-сервер, модель диалога и обновление внутренних ссылок.
4. Исходное состояние, действия и наблюдаемые ожидаемые результаты каждого сценария.
5. Способ восстановления исходных данных после переносов и переименований. Общий набор фикстур можно переиспользовать, но каждый сценарий должен начинаться с известного состояния.
6. В отчёте — использованный набор данных, версия плагина и Obsidian, реально выполненные проверки и результаты. Подготовленный чеклист сам по себе не означает, что проверка выполнена.

Тестовые данные должны быть вымышленными. Адрес и ключ модель-сервера задаются проверяющим отдельно и не входят в распространяемые фикстуры.

## Состав общего набора данных

При реализации подготовить набор с конкретными текстами, покрывающий следующие состояния. Это требования к набору, а не готовые фикстуры.

| Данные | Для чего нужны |
| --- | --- |
| Inbox с несколькими заметками разных назначений и вложенной папкой | Подсчёт, выбор рекурсивности, перенос, пропуск и остановка очереди |
| Заметка о выборе микрофона для запуска подкаста и заметка с общими сведениями о микрофонах | Различие активного проекта и справочного материала |
| Заметка о GTD и справочная папка о продуктивности | Рекомендация существующей заметке и совет до создания файла |
| Родительская папка проектов с описанием и вложенная папка активного проекта со своим описанием | Контекст родителей и собственное описание кандидата |
| Явно противоречащие родительское и локальное описания | Приоритет конкретного описания и сообщение пользователю |
| Папка без собственного описания внутри описанного родителя | Отсутствие кандидата по одному лишь описанию родителя |
| Незаполненный шаблон и описание только с одним содержательным разделом | Исключение заготовок и необязательность всех разделов |
| Русское описание и английское описание | Смешанные языки данных и локализация новых шаблонов |
| Исключённая папка с описанием и обычной заметкой | Разные правила доступа поиска папок, обычных заметок и явного разбора |
| Обычная содержательная заметка и тематически близкое описание папки | Три режима поиска, отсутствие конкуренции и дублирования источников |
| Заметка назначения с тем же именем, что у переносимой заметки | Отказ от перезаписи и автоматического переименования |
| Отдельная заметка с внутренними ссылками на переносимую заметку и на файл описания | Обновление ссылок при переносах и смене имени описания |
| Старое и новое имя описания одновременно в одной папке | Предварительный конфликт массового переименования |
| Набор длинных описаний с фиксированным небольшим контекстным окном | Явный отказ вместо скрытого сокращения набора кандидатов |

Для каждой задачи использовать минимальный нужный поднабор, дополняя общий набор только новыми сценариями. Для повторяемости переносов и переименований предусмотреть восстановление копии исходного набора.

## Установка и начальные настройки

Собрать плагин производственной сборкой с проверкой типов. Создать отдельное хранилище, разрешить community plugins и установить собранные `main.js`, `manifest.json`, `styles.css` в папку плагина с идентификатором из манифеста. Перезагрузить Obsidian и проверить консоль.

Для проверок, затрагивающих поиск обычных заметок, настроить embedding-модель и построить обычный индекс. Отдельно проверить режим «Папки» и рекомендации без embedding-модели и без готового обычного индекса.

Для проверок ссылок записать состояние настройки автоматического обновления внутренних ссылок. Для проверки превышения контекста задать известное небольшое окно. Для очереди записать, включены ли вложенные папки; для исключений — точные исключённые папки.

## Проверки по задачам

1. **Создание описаний:** меню только папок, новый шаблон, открытие существующего файла без изменений, английский и русский язык, сохранение старого файла при смене языка, валидация имени, подсчёт, отмена и изменение только настройки.
2. **Переименование описаний:** успех, обновление ссылок, включение пустых шаблонов и исключённых папок, предварительный конфликт без частичных изменений. Сбои и восстановление детерминированно проверяются также автоматическими тестами с управляемым хранилищем; в ручном отчёте не выдавать их за воспроизведённые в Obsidian, если они не воспроизводились.
3. **Поиск папок:** нативные элементы чата, полный путь и открытие описания, совет о будущей заметке без файловых действий, смешанные языки, собственные описания и родители, отсутствие embedding-зависимости, превышение контекста.
4. **Смешанный поиск:** три режима, различимые проверенные источники, правила исключений, отсутствие дублирования описаний и смена режима между сообщениями.
5. **Рекомендации:** отдельная вкладка справа рядом с чатом, доступный основной редактор, кандидаты и ссылки, отсутствие файловых действий при получении ответа, изменение заметки и явное обновление.
6. **Перенос:** выбор кандидата, перенос по актуальным и по явно выбранным прежним рекомендациям, сохранение правок заметки, изменение описания, конфликт имени без перезаписи и обновление ссылок.
7. **Очередь:** предварительный счётчик, вложенные папки, исключение описаний, поочерёдное открытие и редактирование, перенос, пропуск, удаление до анализа, ошибка и повтор, остановка с итогом и новый запуск без восстановления прежней очереди.

Ручная проверка оценивает реальное взаимодействие с Obsidian и правдоподобие рекомендаций выбранной модели. Детерминированные проверки файловых конфликтов, ошибок сети, отмены и поздних ответов остаются частью автоматических тестов через согласованный публичный seam.
