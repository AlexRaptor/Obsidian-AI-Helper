# Нативный интерфейс Obsidian

Дата: 2026-10-11.
Статус: план реализации; минимальная версия приложения изменена на 1.13.0.
Основание: аудит исходников и поручение пользователя. Каждое изменение выполняется отдельным коммитом в указанном порядке.

## Цель и ограничения

Использовать публичные компоненты и настройки Obsidian для оформления и поведения интерфейса. Сохранить существующие подключения, параметры моделей, историю диалога, потоковое получение сообщений, проверку источников и индекс хранилища.

- Поддерживать английский и русский язык во всех новых подписях, подсказках и командах.
- Сохранить текущую структуру данных настроек, кроме явно описанного расширения выбора языка. Обновление не должно сбрасывать пользовательские значения.
- Использовать переменные темы и публичный API; не обращаться к внутренним настройкам приложения.
- Оставить собственную компоновку сообщений и поля ввода: публичного готового компонента чата нет.
- Сохранить текстовое отображение ответов поиска по заметкам. Произвольные ссылки из сообщения модели не должны обходить проверку источника.
- Настольная платформа остаётся единственной заявленной платформой. Мобильная поддержка в этот план не входит.

## Совместимость

Минимальная версия Obsidian — **1.13.0**. Она позволяет реализовать весь план, включая декларативные настройки, встроенный выбор папок, списки и подстраницы настроек.

Версии появления публичного API:

| Возможность | Версия |
| --- | --- |
| `ItemView.addAction()` | 1.1.0 |
| `ProgressBarComponent` | 1.4.4 |
| `AbstractInputSuggest` | 1.4.10 |
| `Vault.getFileByPath()` — уже используется | 1.5.7 |
| `Workspace.ensureSideLeaf()` — уже используется | 1.7.2 |
| `getLanguage()` | 1.8.7 |
| `SettingGroup` | 1.11.0 |
| Декларативные настройки, `SettingPage`, folder-control и списки | 1.13.0 |

Источник: [официальные определения Obsidian API](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts). Миграция: [официальное руководство](https://docs.obsidian.md/plugins/guides/migrate-declarative-settings).

`minAppVersion` изменяется в `manifest.json`. Версия самого плагина остаётся 0.1.0: это отдельный параметр, пользователь попросил исправить совместимость. Скрипт `version-bump.mjs` сохраняет `minAppVersion` при сборке.

Для коммита 1 обновить пакет типов `obsidian` и lock-файл до опубликованной версии, содержащей API 1.13.0. Не использовать утверждения типов для имитации отсутствующего API. При отсутствии подходящего пакета сверить способ получения типов с официальным репозиторием перед реализацией.

## Проверки и границы каждого коммита

1. Внести только изменение соответствующего шага, его локализацию и необходимые адаптации существующих тестов/мока Obsidian.

3. Запускать затронутые тесты, затем `npm test` и `npm run build` как финальный gate перед коммитом.
4. Проверять diff после сборки: не включать случайные сгенерированные файлы и посторонние правки.
5. Сообщения коммитов писать на русском. Если работа будет привязана к тикету, добавить `#НОМЕР:` перед указанным заголовком.
6. Отмечать отдельно автоматические и ручные проверки. Мок API не доказывает правильность нативного оформления.
