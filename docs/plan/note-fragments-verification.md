# Поиск по фрагментам длинных заметок — #16

Индексация активной заметки теперь последовательно отправляет ограниченные фрагменты, сохраняя название, путь, цепочку заголовков и только YAML-свойства `tags`/`aliases`. Содержимое встроенных заметок и ссылок не читается. Успешная индексация следующей заметки по-прежнему заменяет выбранную заметку; индексирование всего хранилища относится к следующим тикетам.

Размер включает метаданные и основной текст: по умолчанию 4000 символов, допустимо 256–16000. Перекрытие основного текста по умолчанию 200 символов, допустимо 0–четверть размера. Если метаданные не оставляют места основному тексту с перекрытием, выводится явная ошибка. Разделы разделяются по заголовкам, внутри раздела предпочитаются границы абзацев; слишком длинный абзац делится с перекрытием. Поиск выбирает один подходящий фрагмент, поэтому количество разделов не увеличивает объём контекста запроса. Бюджет окна и резерв ответа дополнительно проверяются чатом.

Изменение размера/перекрытия требует переиндексации; параметры и версия формата входят в идентификатор совместимости. Старый индекс #15 не используется молча. Смена только порога сходства по-прежнему не требует переиндексации. При проверке актуальности используется хеш полной выбранной заметки, а раскрытый источник содержит ровно отправленный фрагмент. Ссылка открывает последний заголовок через Obsidian `openLinkText`; неоднозначные повторяющиеся заголовки разрешает Obsidian.

## Ручной сценарий Obsidian / LM Studio

1. Собрать `npm run build`, установить `main.js`, `manifest.json`, `styles.css` в папку плагина и перезагрузить Obsidian. Проверить подключение embeddings и модель диалога.
2. Создать заметку с YAML `tags: [rail]`, `aliases: [North]`, `secret: hidden-password`. В тексте добавить `# Travel`, `## Departure` с временем 18:30, несколькими абзацами и разделом длиннее 8000 символов; добавить `## Arrival` с временем 22:00. Добавить `![[Secret]]` и `[[Linked]]`; связанная заметка содержит уникальное значение, которого нет в родителе.
3. Явно проиндексировать активную заметку. В журнале модель-сервера ожидаются несколько последовательных запросов с названием, путём, нужными заголовками, tags/aliases. Не должно быть `hidden-password` или содержимого связанных заметок. Размер каждого входа не превышает настройку; соседние фрагменты длинного абзаца перекрываются.
4. Включить поиск и спросить время прибытия. Ожидается источник с `Travel → Arrival`, соответствующий ответ и раскрытый текст, совпадающий с JSON-контекстом запроса. Ссылка открывает раздел Arrival. Задать вопрос по середине длинного раздела: передаётся подходящий фрагмент, а не весь раздел.
5. Изменить заметку после ответа и нажать ссылку: ожидается сообщение об устаревшем индексе. После переиндексации поиск работает; перезапуск сохраняет совместимый индекс.
6. В расширенных настройках задать сначала перекрытие 32, затем размер 512. До переиндексации поиск требует перестроения. Следующая индексация реально отправляет меньшие фрагменты. Проверить недопустимые значения: пустое, дробное, отрицательное, размер 255/16001 и перекрытие больше четверти. Последние корректные значения сохраняются.
7. Проверить EN/RU: подписи, пояснение о переиндексации, ошибки, цепочку заголовков и раскрытый фрагмент. Уменьшить окно контекста: чат сообщает о нехватке места, история не сокращается.

## Статус проверки

Автоматические проверки выполняются через публичный модуль поиска, ввод/кнопки чата, настройки и подменяемый HTTP-транспорт; используется настоящий IndexedDB API через fake-indexeddb. Реальная ручная приёмка Obsidian/LM Studio для #16 в этой сессии не выполнялась. Автоматические результаты не подтверждают качество embeddings выбранной модели или навигацию реального Obsidian.
