# Потоковое отображение сообщений модели

Источник: сессия grill-with-docs. Все решения и итоговый документ подтверждены пользователем 2026-10-10. План готов к реализации; реализация в этой сессии не выполнялась.

Спецификация опубликована в [GitHub issue #5](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/5) с меткой `ready-for-agent`. Точки тестирования подтверждены пользователем при подготовке спецификации.

## Согласованные решения

1. Текст поступает частями от модель-сервера и отображается до завершения генерации. Анимация уже полученного текста не решает задачу.
2. Markdown отображается во время генерации; временно незавершённая разметка допустима. После завершения выполняется окончательное отображение.
3. В область задачи входит кнопка «Остановить» для активной генерации.
4. После остановки частичный текст остаётся видимым с пометкой «Остановлено». Пара сообщений пользователя и модели не входит в историю следующего запроса.
5. При обрыве соединения частичный текст сохраняется вместе с ошибкой. Незавершённая пара не входит в историю; автоматического повтора нет.
6. При явном отказе модель-сервера в потоковом режиме до получения текста допускается один повтор обычным запросом. Полное JSON-сообщение отображается целиком. Другие ошибки не запускают повтор.
7. Прокрутка следует за новым текстом, пока пользователь находится у нижнего края. Прокрутка вверх отключает слежение; возвращение вниз включает его снова.
8. Закрытие окна останавливает генерацию; полученная часть сохраняется с пометкой «Остановлено» в состоянии текущего окна. Очистка диалога удаляет всё. Хранение между перезапусками Obsidian не входит в задачу.
9. Добавляется настройка «Время ожидания ответа». По умолчанию она пуста; пустое значение означает бесконечное ожидание. Непустое значение ограничивает ожидание первого текста и каждую последующую паузу без нового текста, но не общую длительность генерации.
10. В диалоге может быть только один активный запрос. Поле ввода доступно для следующего черновика; кнопка «Отправить» временно становится «Остановить». Enter во время генерации не отправляет сообщение и не останавливает генерацию. Кнопки отличаются цветами из темы Obsidian.
11. Первый текст отображается сразу; последующие обновления Markdown происходят примерно раз в 100 мс, только для растущего сообщения. Завершение и остановка сразу отображают последнюю полученную часть.
12. Статистика токенов берётся только у модель-сервера для успешно завершённого сообщения. При её отсутствии показывается «нет данных» вместо значения предыдущего сообщения.
13. Время ожидания задаётся целым положительным числом секунд. Ноль, отрицательные, дробные и нечисловые значения недопустимы: показывается пояснение, последнее корректное значение не заменяется.
14. «Отправить» использует акцентный цвет темы Obsidian. «Остановить» имеет нейтральный фон, текст и рамку цвета `--text-error`. Действия различимы по подписям, не только по цвету.
15. Основание для одного повтора обычным запросом — явное указание в ошибке на отсутствие поддержки параметра `stream` или потокового режима до получения текста. Одного HTTP-статуса недостаточно; неоднозначная ошибка отображается без повтора.
16. При остановке до первого текста сообщение пользователя остаётся видимым, а ветка модели содержит пометку «Остановлено». Пара не входит в историю; следующий черновик не меняется.
17. Закрытие соединения без подтверждения завершения генерации считается обрывом. Текст сохраняется с пояснением; незавершённая пара исключается из истории.
18. Успешное завершение без текста отображается как ошибка «Модель-сервер вернул пустое сообщение». Пара не входит в историю.
19. Поддержка desktop и mobile сохраняется. Автоматические проверки дополняются ручной проверкой внутри Obsidian на обеих платформах.
20. Настройка ожидания фиксируется при запуске запроса. Изменения применяются со следующего запроса; переход на обычный режим использует значение исходного запроса.

## Исходное поведение

- Клиент запрашивает полное сообщение (`stream: false`).
- В историю для следующих запросов попадают только успешно завершённые пары сообщений пользователя и модели.
- Ошибки видны в окне, но не входят в историю для модель-сервера.
- Очистка диалога и закрытие окна отменяют активный запрос.
- Каждое отображение пересоздаёт список сообщений и прокручивает его вниз.
- Диалог хранится только в памяти; плагин заявляет поддержку desktop и mobile.

## Критерии проверки

### Автоматические проверки

- Текст отображается до завершения генерации; первый текст появляется сразу, последующие обновления объединяются примерно на 100 мс, финальное обновление не теряет последние части.
- Обновляется только растущее сообщение; устаревшие асинхронные результаты не восстанавливают содержимое после очистки или остановки и не затрагивают новый запрос.
- Остановка до первого текста и после частичного текста сохраняет согласованное отображение, исключает пару из истории и не меняет следующий черновик.
- Ошибка и закрытие соединения без подтверждения завершения сохраняют частичный текст; пустое сообщение отображается как ошибка. Незавершённые пары не попадают в следующий запрос.
- Очистка удаляет диалог и отменяет запрос; закрытие окна отменяет запрос и сохраняет частичное сообщение в состоянии текущего окна.
- Пустая настройка отключает таймаут. Положительное число секунд ограничивает ожидание первого текста и паузы без текста, но не общую длительность генерации. Некорректный ввод не заменяет корректное значение.
- Изменение настройки не влияет на активный запрос, включая переход на обычный режим.
- Явный отказ в поддержке streaming до получения текста допускает ровно один обычный запрос; неоднозначные ошибки и ошибки после получения текста не запускают повтор.
- Полное JSON-сообщение корректно отображается. Статистика берётся у модель-сервера только для успешного сообщения; при её отсутствии выводится «нет данных».
- Во время генерации Enter не отправляет и не останавливает запрос; кнопка останавливает генерацию, ввод следующего черновика доступен.
- Все новые подписи, пояснения и ошибки локализованы на английский и русский.
- Проходят `npm test` и `npm run build`.

### Ручные проверки в Obsidian

- На desktop и mobile текст появляется до завершения генерации; остановка работает до и после получения текста.
- Markdown корректно обновляется для незавершённых списков, ссылок и кодовых блоков, включая финальное отображение после завершения или остановки.
- Длинное сообщение не мешает редактировать следующий черновик и читать предыдущие сообщения.
- Прокрутка следует за генерацией у нижнего края, прекращает слежение при прокрутке вверх и возобновляет его при возвращении вниз.
- Кнопки «Отправить» и «Остановить» различимы в светлой и тёмной темах и используют цвета темы Obsidian.

## Границы задачи

В задачу не входят хранение диалога между перезапусками, виртуализация длинных диалогов и автоматическое продолжение прерванной генерации. Существующий 120-секундный таймаут запросов генерации заменяется согласованной настройкой; изменение таймаутов других операций модель-сервера не обсуждалось.
