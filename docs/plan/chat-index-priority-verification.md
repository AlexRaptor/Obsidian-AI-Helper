# Приоритет чата перед индексацией (#22)

При отправке сообщения, в том числе без поиска, чат получает временный приоритет до окончания ответа, ошибки, остановки или закрытия представления. Уже отправленный embedding-запрос индексации завершается до обращений чата к модель-серверу. Следующие пакеты и заметки ждут; полученные пакеты длинной заметки сохраняются в текущей операции. Несколько представлений чата удерживают приоритет независимо.

Изменения хранилища остаются в очереди, устаревшие источники отклоняются обычной проверкой поиска. Освобождение приоритета не снимает сохраняемую ручную паузу и не сбрасывает ошибку соединения. Повтор подключения разрешён только действиями, описанными в #19; периодических проверок сервера нет. Временный приоритет не сохраняется в IndexedDB.

Автоматические проверки: `test/chat-index-priority.test.ts` через публичный модуль поиска, ввод/кнопки чата и подменяемый HTTP-транспорт проверяет порядок запросов, все способы освобождения приоритета, EN/RU, очередь правок, ручную паузу, ожидание сервера, пакеты длинной заметки и независимое освобождение приоритетов. Остальные проверки поиска и восстановления запускаются вместе с полным набором; производственная сборка включает проверку типов.

Итог: `npm test` — 406 тестов в 31 файле проходят; `npm run build` — проверка типов и производственная сборка проходят. Ревью стандартов и соответствия тикету завершено без оставшихся замечаний.

## Ручная демонстрация Obsidian / LM Studio

Пользователь подтвердил успешное прохождение ручной проверки для #22 в Obsidian / LM Studio. Результат зафиксирован отдельно от автоматических проверок; ниже сохранён сценарий для повторной демонстрации.

1. Выполнить `npm run build`, скопировать `main.js`, `manifest.json`, `styles.css` в `<vault>/.obsidian/plugins/<manifest id>/`, перезагрузить Obsidian. В LM Studio включить журнал запросов, загрузить модели диалога и embeddings. В тестовом хранилище использовать несколько коротких и много длинных заметок, чтобы индексация продолжалась несколько минут.
2. Включить поиск и запустить индексацию. После нескольких готовых заметок отправить вопрос по ним. В журнале сначала завершается начатый запрос индексации, затем выполняются поиск и ответ. Между ними новые фоновые embedding-запросы не появляются. Шапка показывает «Приоритет у чата…» с текущим покрытием.
3. Во время ответа несколько раз изменить ожидающую заметку, создать новую и изменить уже готовую. Покрытие пересчитывается; новые запросы индексации ждут. После ответа обрабатываются последние версии очереди, ранее готовые неизменённые заметки не индексируются повторно. Следующий вопрос не использует старый текст изменённого источника.
4. Повторить во время обработки длинной заметки: после ответа продолжаются оставшиеся пакеты. Повторить с обычным чатом без поиска, ошибкой модели диалога и кнопкой остановки. Во всех случаях фон может продолжить работу после освобождения приоритета.
5. Во время ответа нажать ручную паузу. Завершить или остановить ответ: пауза остаётся, новых запросов нет до явного продолжения. Отдельно остановить embedding-сервер, дождаться состояния ожидания сервера, затем завершить обычный диалог с доступной моделью диалога. Чат не создаёт повтор подключения, даже если сервер снова запущен; проверить явное продолжение и переход в поиск по правилам #19.
6. Закрыть чат во время ответа: фон может продолжить разрешённую работу. Затем повторить с выгрузкой всего плагина: новых фоновых запросов нет; поздний ответ не возобновляет индексацию. После повторной загрузки сохраняются готовая часть индекса, очередь и ручная пауза.
7. Проверить русский и английский языки, смену языка во время ответа, управление кнопками с клавиатуры и подписи покрытия. Ручная пауза и ожидание недоступного сервера отображаются своим состоянием и не подменяются временным приоритетом чата.
