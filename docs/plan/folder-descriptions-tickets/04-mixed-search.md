# Совместный поиск заметок и папок в чате

## Parent

[Спецификация #25](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/25).

## What to build

Добавить третий режим «Заметки и папки», чтобы один вопрос мог получать содержательные источники из заметок и рекомендации папок по описаниям, не меняя правила доступа каждого типа.

## Acceptance criteria

- [ ] При включённом поиске доступны все три режима: «Заметки», «Папки», «Заметки и папки». По умолчанию остаётся тип «Заметки».
- [ ] В смешанном режиме обычные заметки соблюдают существующие исключения, а описания папок доступны независимо от этих исключений.
- [ ] Описание не дублируется как обычная заметка и как описание папки. Отбор учитывает выбранные типы до ранжирования результатов.
- [ ] Ответ позволяет различить обычную заметку и папку: папка представлена полным путём и ссылкой на описание; обычные источники сохраняют существующие проверенные ссылки.
- [ ] В смешанном режиме можно спросить о месте создания будущей заметки, уточнять вопрос по истории и получать обоснованные варианты без файловых действий.
- [ ] Требования обычного поиска заметок к embedding-модели и индексу сохраняются. Режим «Папки» продолжает работать независимо от них; ради смешанного режима готовность обычного поиска не становится условием поиска только папок.
- [ ] Общий бюджет контекста учитывает историю, обычные источники, описания и место для ответа. Описания не исключаются и не усекаются молча при нехватке места.
- [ ] При переходе между режимами последующие запросы используют выбранные источники и не переиспользуют неподходящий контекст предыдущего запроса.
- [ ] Через чат проверены смешанный запрос, отдельные правила исключений, отсутствие дубликатов, различимые проверенные ссылки, смена режима, нехватка контекста и сохранение поведения двух отдельных режимов.
- [ ] Релевантные Vitest-проверки и производственная сборка проходят; смешанный ответ и ссылки проверены в Obsidian.
- [ ] Для ручной проверки подготовлено и фактически создано отдельное тестовое хранилище Obsidian с воспроизводимыми тестовыми данными для сценариев этой задачи. Можно использовать общий набор фикстур с дополнениями; рабочее хранилище пользователя не используется.
- [ ] Каждый документ ручного тестирования описывает создание тестового хранилища, способ получения точных файлов и их содержимого (готовый набор или генератор), настройки плагина и Obsidian, ожидаемые результаты и восстановление исходных данных. Отчёт указывает использованный набор и реально выполненные проверки.
