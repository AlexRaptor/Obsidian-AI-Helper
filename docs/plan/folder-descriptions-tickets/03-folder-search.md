# Поиск папок и совет до создания заметки в чате

## Parent

[Спецификация #25](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/25).

## What to build

В существующем чате пользователь включает поиск и выбирает «Папки», чтобы найти папку по назначению или спросить, где создать будущую заметку. Ответ показывает полный путь, проверенную ссылку на описание и объяснение; при необходимости диалог уточняет намерение.

На этом этапе работают режимы «Заметки» и «Папки». Смешанный режим добавляется в #29. Правила получения содержательных описаний и контекста родителей сосредоточены в общем модуле работы с описаниями и используются также рекомендациями #30.

## Acceptance criteria

- [ ] При включённом поиске можно выбрать «Заметки» или «Папки»; тип «Заметки» выбран по умолчанию. Существующее поведение включения поиска сохраняется, отдельного окна поиска папок нет.
- [ ] В режиме «Заметки» файлы с настроенным именем описания не конкурируют с обычными заметками; существующие исключения обычного поиска сохраняются. Типы источников фильтруются до отбора лучших результатов.
- [ ] В режиме «Папки» доступны описания всех папок, включая исключённые из обычной индексации, без чтения остальных заметок этих папок.
- [ ] Кандидат имеет собственное содержательное описание. Комментарии не участвуют в анализе; файл только из заголовков, комментариев и пробелов исключается. Достаточно одного содержательно заполненного раздела.
- [ ] Описания всех родителей дополняют контекст, но не делают папку без собственного описания кандидатом. При явном противоречии конкретное описание имеет приоритет и пользователь видит сообщение.
- [ ] Поддерживаются русские и английские описания одновременно; нет жёсткой схемы PARA или встроенного предпочтения проектов.
- [ ] Поиск папок работает без embedding-модели, полной индексации хранилища или готовности обычного индекса. Описания — отдельный тип источников; отдельный физический индекс не обязателен.
- [ ] Используются настроенные модель-сервер и модель диалога, обычная история и пользовательский системный промпт чата.
- [ ] Передаются все подходящие описания с контекстом родителей; при превышении доступного контекста пользователь получает понятное сообщение без скрытого сокращения набора папок.
- [ ] Запрос о будущей заметке, например о GTD, может вернуть несколько обоснованных вариантов, уточняющий вопрос или отсутствие подходящей папки. Запрос не создаёт и не перемещает файлы.
- [ ] Ответ представляет полный путь папки и кликабельную ссылку на проверенное описание. Выдуманные или недоступные источники не открываются; содержимое источников не запускает произвольные действия с файлами.
- [ ] Обычный поиск Obsidian продолжает видеть описания как Markdown-файлы. Изменение настроенного имени учитывается последующими запросами.
- [ ] Через поля и элементы чата проверены режимы, состав переданного контекста, исключения, пустые шаблоны, родители, история, ссылки, отсутствие побочных файловых действий, нехватка контекста, ошибки и отмена с игнорированием поздних результатов.
- [ ] Релевантные Vitest-проверки и производственная сборка проходят; в Obsidian проверены нативный выбор источников и открытие описания. С настроенной моделью проверен совет о будущей заметке.
- [ ] Для ручной проверки подготовлено и фактически создано отдельное тестовое хранилище Obsidian с воспроизводимыми тестовыми данными для сценариев этой задачи. Можно использовать общий набор фикстур с дополнениями; рабочее хранилище пользователя не используется.
- [ ] Каждый документ ручного тестирования описывает создание тестового хранилища, способ получения точных файлов и их содержимого (готовый набор или генератор), настройки плагина и Obsidian, ожидаемые результаты и восстановление исходных данных. Отчёт указывает использованный набор и реально выполненные проверки.
