# Перенос заметки по выбранной рекомендации

## Parent

[Спецификация #25](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/25).

## What to build

Пользователь выбирает предложенную папку в панели разбора и явно переносит туда заметку. Если заметка изменилась, можно обновить рекомендации либо осознанно перенести по прежним. Конфликты и изменившиеся описания не приводят к скрытым файловым изменениям.

## Acceptance criteria

- [ ] Для выбранного кандидата доступно явное действие переноса; получение рекомендации само по себе ничего не перемещает.
- [ ] При изменении заметки пользователь видит устаревший результат и выбирает «Обновить рекомендации» либо «Перенести по прежним рекомендациям». Второй вариант позволяет перенос без обязательного повторного анализа; это отдельный явный выбор.
- [ ] Перед переносом проверяются существование исходного файла, папки назначения и актуальность использованных описаний. При изменении описаний требуется повторный анализ: разрешение прежнего результата касается изменения заметки.
- [ ] Назначение принадлежит проверенному набору кандидатов, а не произвольному пути из ответа модели.
- [ ] При совпадении имени перенос останавливается, существующий файл можно открыть. Заметки не перезаписываются и не переименовываются автоматически.
- [ ] Перенос выполняется публичными средствами Obsidian с корректной обработкой внутренних ссылок; основное содержимое заметки сохраняется, включая пользовательские изменения перед переносом.
- [ ] Для «оставить в текущей папке» и «подходящей папки нет» не выполняется фиктивное перемещение.
- [ ] Панель сообщает результат или причину отказа и не показывает успешный перенос при ошибке.
- [ ] Через действия панели и управляемое хранилище проверены успешный перенос, явный выбор старого результата, обновление, изменение описаний, отсутствие файла или папки, выдуманный кандидат, конфликт и открытие существующего файла. Проверяется итоговое содержимое и положение файлов.
- [ ] Релевантные Vitest-проверки и производственная сборка проходят; перенос из панели и внутренние ссылки проверены в Obsidian при соответствующих настройках.
- [ ] Для ручной проверки подготовлено и фактически создано отдельное тестовое хранилище Obsidian с воспроизводимыми тестовыми данными для сценариев этой задачи. Можно использовать общий набор фикстур с дополнениями; рабочее хранилище пользователя не используется.
- [ ] Каждый документ ручного тестирования описывает создание тестового хранилища, способ получения точных файлов и их содержимого (готовый набор или генератор), настройки плагина и Obsidian, ожидаемые результаты и восстановление исходных данных. Отчёт указывает использованный набор и реально выполненные проверки.
