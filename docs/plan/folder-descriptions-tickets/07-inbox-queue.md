# Последовательный разбор Inbox или выбранной папки

## Parent

[Спецификация #25](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/25).

## What to build

Из меню любой папки пользователь запускает очередь Markdown-заметок, просматривает и редактирует каждую в основном редакторе и выбирает перенос, пропуск или завершение в общей панели разбора. Ошибки сохраняют позицию; остановка отменяет запрос и показывает итог, сохраняя выполненные переносы.

## Acceptance criteria

- [ ] Действие «Разобрать заметки» доступно в контекстном меню любой папки; специальная настройка Inbox не требуется.
- [ ] До запуска показаны число заметок и опция «Включить вложенные папки», выключенная по умолчанию. Число соответствует выбранной области.
- [ ] Очередь включает Markdown-заметки в выбранной области и не включает файлы описаний с текущим настроенным именем. Исключения обычной индексации не блокируют явно выбранный разбор.
- [ ] Используется существующая вкладка «Разбор заметок», общий сценарий рекомендаций и переноса. Для каждой заметки показываются название и исходный путь; сама заметка открывается в основном редакторе.
- [ ] Для открытой заметки учитывается текущий текст редактора; остальные читаются непосредственно перед анализом. Редактирование и явный выбор прежних рекомендаций сохраняют поведение #30 и #31.
- [ ] Доступны «Перенести», «Пропустить», «Завершить разбор». После успешного переноса или пропуска открывается следующая заметка; автоматического применения рекомендаций ко всей папке нет.
- [ ] При ошибке анализа позиция сохраняется и предлагаются «Повторить», «Пропустить», «Завершить разбор». Ошибка модель-сервера, нехватка контекста или некорректный ответ не приводят к автоматическому пропуску или бесконечным повторным запросам.
- [ ] Если файл удалён до начала анализа, это отмечается и очередь переходит к следующему без попытки перемещения удалённого файла.
- [ ] Завершение останавливает текущий запрос и показывает количество перенесённых, пропущенных и оставшихся заметок. Поздний ответ не продолжает очередь и не выполняет перемещения.
- [ ] Уже выполненные переносы сохраняются. Очередь существует только в рамках одного запуска, не сохраняется между закрытиями представления или перезапусками Obsidian. Повторный запуск собирает новый набор из текущей выбранной папки.
- [ ] Успешное завершение всей очереди показывает итог без необходимости повторно запускать команду для каждой заметки.
- [ ] Интерфейс локализован на английский и русский и остаётся нативным и доступным на узком экране.
- [ ] Через меню, редактор и панель проверены область и счётчик, вложенные папки, исключённые папки, исключение описаний, очередность открытия, перенос, пропуск, редактирование, удаление до анализа, ошибки с повтором, остановка и поздние ответы, итог и новый запуск без восстановления прежней очереди.
- [ ] Релевантные Vitest-проверки и производственная сборка проходят; в Obsidian выполнен разбор нескольких заметок с просмотром и редактированием в основном редакторе, переносом, пропуском и остановкой.
- [ ] Для ручной проверки подготовлено и фактически создано отдельное тестовое хранилище Obsidian с воспроизводимыми тестовыми данными для сценариев этой задачи. Можно использовать общий набор фикстур с дополнениями; рабочее хранилище пользователя не используется.
- [ ] Каждый документ ручного тестирования описывает создание тестового хранилища, способ получения точных файлов и их содержимого (готовый набор или генератор), настройки плагина и Obsidian, ожидаемые результаты и восстановление исходных данных. Отчёт указывает использованный набор и реально выполненные проверки.
