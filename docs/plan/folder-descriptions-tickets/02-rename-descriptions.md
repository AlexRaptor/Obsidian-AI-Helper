# Переименование описаний при смене настройки

## Parent

[Спецификация #25](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/25).

## What to build

При смене имени описания пользователь выбирает изменение только настройки, переименование всех существующих описаний либо отмену. Переименование проверяет конфликты до начала и пытается восстановить прежние имена при сбое.

## Acceptance criteria

- [ ] Диалог смены имени показывает число затронутых описаний и три действия: использовать новое имя без изменения файлов, переименовать существующие описания, отменить.
- [ ] Переименование охватывает все описания со старым именем, включая незаполненные шаблоны и исключённые папки.
- [ ] До первой операции проверяются все назначения. Любой конфликт останавливает операцию до изменения файлов и показывает конфликтующие пути.
- [ ] После конфликта пользователь может устранить его и повторить выбор либо сохранить только новую настройку без переименования.
- [ ] Файлы не объединяются и не перезаписываются. Переименование производится публичными средствами Obsidian с обработкой внутренних ссылок.
- [ ] Новая настройка сохраняется только после успешного переименования всего набора; создание и распознавание описаний затем используют новое имя.
- [ ] При сбое сохраняется прежняя настройка и выполняется попытка вернуть уже переименованным файлам прежние имена.
- [ ] При неполном восстановлении пользователь видит точные пути остаточных изменений; интерфейс не сообщает об успешном полном восстановлении.
- [ ] Изменение только настройки и отмена сохраняют поведение #26.
- [ ] Через настройки и управляемый хранилищем сценарий проверены успех, отмена, изменение только настройки, предварительный конфликт, сбой с полным восстановлением и сбой восстановления. Не подменяется сам сценарий переименования.
- [ ] Релевантные Vitest-проверки и производственная сборка проходят; обновление внутренних ссылок проверено в Obsidian при соответствующих настройках.
- [ ] Для ручной проверки подготовлено и фактически создано отдельное тестовое хранилище Obsidian с воспроизводимыми тестовыми данными для сценариев этой задачи. Можно использовать общий набор фикстур с дополнениями; рабочее хранилище пользователя не используется.
- [ ] Каждый документ ручного тестирования описывает создание тестового хранилища, способ получения точных файлов и их содержимого (готовый набор или генератор), настройки плагина и Obsidian, ожидаемые результаты и восстановление исходных данных. Отчёт указывает использованный набор и реально выполненные проверки.
