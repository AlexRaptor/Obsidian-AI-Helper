# Создание описаний папок и настройка имени

## Parent

[Спецификация #25](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/25).

## What to build

Пользователь задаёт единое имя описания, создаёт и открывает локализованный Markdown-шаблон из меню папки. Смена имени может оставить существующие файлы без изменений или быть отменена. Переименование существующих описаний добавляется отдельной задачей #27.

В рамках этого сценария начать общий модуль работы с описаниями: единое распознавание файлов по текущей настройке, получение файлов и их папок, создание и открытие описания. Поиск и разбор далее используют тот же модуль, не копируют правила именования и доступа.

## Acceptance criteria

- [ ] Имя по умолчанию `_folder.md`; настройка принимает допустимое имя Markdown-файла с расширением `.md` без пути. Недопустимое значение не сохраняется.
- [ ] Действие «Создать описание» доступно только в меню папки, создаёт файл непосредственно в выбранной папке и открывает его в Obsidian.
- [ ] Если файл существует, действие открывает его без перезаписи или изменения содержимого.
- [ ] Шаблон содержит разделы «Назначение», «Сюда относятся», «Не относятся» с крайне краткими нейтральными пояснениями в Markdown-комментариях согласно родительской спецификации.
- [ ] Новый шаблон использует текущий язык плагина. Английская и русская локализации полны; смена языка не меняет существующие файлы и настроенное имя.
- [ ] Исключения обычной индексации не блокируют создание, открытие и обнаружение описаний. Обычные заметки не добавляются в индекс этим действием.
- [ ] Перед сменой имени показывается число файлов со старым именем, включая незаполненные шаблоны и файлы в исключённых папках.
- [ ] Можно сохранить новое имя без переименования файлов либо отменить изменение. После сохранения распознаётся только новое имя; при отмене настройка и файлы остаются прежними. Не обещать ещё не реализованное переименование: оно входит в #27.
- [ ] Работа с пользовательскими Markdown-описаниями не меняет способ хранения производного индекса и не требует embedding-модели или готового обычного индекса.
- [ ] Интерфейс использует стандартные компоненты Obsidian и доступен на узком экране.
- [ ] Поведение проверяется через меню и настройки с управляемым хранилищем: создание, существующий файл, неподходящий контекст файла, локализация, валидация, подсчёт, сохранение и отмена. Проверяется содержимое файлов, а не приватные методы.
- [ ] Релевантные Vitest-проверки и производственная сборка с проверкой типов проходят; меню папок и открытие описания дополнительно проверены в настоящем Obsidian.
- [ ] Для ручной проверки подготовлено и фактически создано отдельное тестовое хранилище Obsidian с воспроизводимыми тестовыми данными для сценариев этой задачи. Можно использовать общий набор фикстур с дополнениями; рабочее хранилище пользователя не используется.
- [ ] Каждый документ ручного тестирования описывает создание тестового хранилища, способ получения точных файлов и их содержимого (готовый набор или генератор), настройки плагина и Obsidian, ожидаемые результаты и восстановление исходных данных. Отчёт указывает использованный набор и реально выполненные проверки.
