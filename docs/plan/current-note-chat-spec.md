# Обсуждение заметок через упоминания в чате

Статус: согласовано пользователем 2026-10-14; готово к реализации. Реализация не начата.

Итоговая спецификация в формате `to-spec`: [Упоминания заметок в чате](note-mentions-spec.md). Этот документ сохраняет решения исходного интервью.

## Задача

Пользователь хочет обсуждать с моделью содержимое заметок, явно упоминая их в тексте сообщения. Текущая открытая заметка должна быть доступна первым предложением, но пользователь может выбрать другие заметки и упомянуть несколько заметок в одном сообщении. Содержимое каждой заметки должно учитывать правки, сделанные до отправки вопроса.

## Подтверждённые решения

- Первая версия позволяет обсуждать целые заметки хранилища, выбранные через упоминания. Передача выделенного текста отложена; дальнейшее проектирование должно учитывать возможность такого расширения.
- При наборе `@` открывается список заметок. Ввод после `@` фильтрует список по именам заметок и частям путей. Без фильтра первой предлагается текущая заметка — последняя открытая заметка, с которой пользователь перешёл в чат.
- Вложение добавляется только после явного выбора заметки из списка. Обычный символ `@` и сочетания с ним, включая адреса электронной почты, должны оставаться доступными как текст сообщения.
- После выбора в сообщении видно упоминание выбранной заметки. Отдельной кнопки прикрепления нет. Автоматической передачи заметки при каждой отправке нет.
- Упоминание отображается отдельным элементом внутри сообщения, выделенным цветом активной темы Obsidian, с названием и доступным полным путём. Фиксированный цвет не используется; выделение дополняет название и визуальную форму элемента.
- Удаление элемента убирает соответствующее упоминание. Повторные упоминания одной заметки не дублируют её содержимое в запросе; вложение убирается при удалении последнего упоминания этой заметки.
- Список открывается при наборе `@` в начале строки или после пробела, вне кода. Адреса электронной почты вроде `user@example.com` не открывают список. Вставленный текст не создаёт вложений автоматически.
- Стрелки перемещают выбор, Tab или щелчок подтверждают его. Escape закрывает список, сохраняя текст. Enter подтверждает выбор только после перемещения стрелками; иначе сохраняет обычное поведение отправки сообщения.
- Выбор охватывает все Markdown-заметки хранилища, включая исключённые из индексации. Исключение из поиска не запрещает явную передачу выбранной заметки модели.
- Фильтр работает без учёта регистра по названию и пути и поддерживает несколько слов: каждый поисковый токен должен совпасть с полным путём, токены могут находиться не рядом и в любом порядке. Запрос `project monexa` находит `1.Projects/Monexa.md`, `Docs/ProjectDescriptionMonexa/README.md` и `Monexa/Project.md`, но не `Projects/Another.md`.
- Помимо цельных подстрок поддерживается поиск с пропуском букв: символы каждого поискового токена должны встречаться в пути в той же последовательности, но между ними допустимы другие символы, включая разделители папок. Поэтому `projemonex` находит `1.Projects/Monexa.md` и `Docs/ProjectDescriptionMonexa/README.md`. Это дополнение к многословному поиску; требование совпадения всех токенов сохраняется.
- При фильтрации совпадения цельными подстроками ранжируются выше совпадений с пропусками; среди совпадений с пропусками предпочтительны более компактные совпадения. При одинаковой релевантности порядок определяется путём. Правило текущей заметки первой применяется к списку без фильтра.
- Без фильтра текущая заметка предлагается первой, остальные упорядочены по пути. При одинаковых названиях виден путь. При отсутствии совпадений показывается «Заметки не найдены», введённый текст сохраняется.
- Текущей считается последняя заметка, с которой пользователь работал перед переходом в чат. При отсутствии такой заметки нет предложения текущей заметки; выбор других заметок остаётся доступным.
- Упоминание привязывается к заметке при добавлении. Переключение вкладки до отправки не подменяет выбранную заметку; для другой заметки нужно заменить упоминание.
- Содержимое заметки фиксируется на момент отправки сообщения: изменения после упоминания заметки должны попасть в запрос, включая актуальные правки редактора.
- Одно сообщение может упоминать несколько разных заметок. При отправке читается актуальное содержимое каждой выбранной заметки; каждая привязка сохраняется независимо от переключения вкладок.
- Отправленный снимок сохраняется с исходным сообщением в истории диалога и доступен модели при последующих вопросах до очистки диалога. Правки заметки после отправки не изменяют историю.
- Передаются название, путь и весь Markdown, включая свойства. Ссылки и встраивания остаются текстом; связанные заметки, изображения и файлы автоматически не раскрываются.
- Если вложение, история и вопрос не помещаются в контекст модели, отправка блокируется с объяснением; автоматического усечения или пересказа нет.
- Выбранный режим поиска сохраняется: найденные материалы дополняют обязательный полный снимок в пределах доступного контекста.
- Вложение заметки отличается от источника, найденного поиском по заметкам.
- При переименовании заметки привязка сохраняется и название обновляется. Закрытие вкладки не препятствует отправке: содержимое читается из хранилища. Если хотя бы одна выбранная заметка удалена или недоступна, весь запрос блокируется с объяснением, черновик сохраняется.
- Сообщение с упоминаниями требует вопроса или инструкции помимо самих упоминаний. При их отсутствии отправка блокируется с предложением добавить вопрос, черновик сохраняется.
- Ошибка или остановка запроса не добавляет ход в историю последующих запросов; частичный ответ остаётся видимым. При ошибке вопрос с упоминаниями восстанавливается, если пользователь не начал новый черновик. Остановка автоматически вопрос не восстанавливает. Повторная отправка читает актуальное содержимое заметок заново.
- Для отправки сообщения с вложениями необходим известный лимит контекста: автоматически определённый или вручную заданный в существующих настройках. При неизвестном лимите отправка блокируется с объяснением, где указать значение; черновик сохраняется. Запасное значение 8192 для этого сценария не используется.

## Критерии приёмки

- Пользователь может выбрать текущую или другую заметку через `@`, видеть подтверждённые упоминания с цветовым выделением и отправить вопрос с несколькими заметками.
- Текущая заметка предлагается первой без фильтра; многословный фильтр выдаёт все три положительных примера выше и исключает отрицательный пример.
- Запрос без пробелов `projemonex` выдаёт `1.Projects/Monexa.md` и `Docs/ProjectDescriptionMonexa/README.md`; поиск сохраняет порядок букв внутри каждого токена, игнорирует регистр и предпочитает цельные совпадения совпадениям с пропусками.
- Одинаковые имена заметок различимы по пути, отсутствие результатов не уничтожает текст.
- Обычный `@`, адрес электронной почты, код и вставленный текст не создают вложений без подтверждения выбора.
- Изменения выбранной заметки до отправки попадают в запрос; переключение на другую вкладку не подменяет выбранную заметку.
- Повторные упоминания одной заметки передают один снимок; разные заметки передают отдельные снимки.
- Следующий вопрос в диалоге использует ранее отправленные снимки, даже если исходные заметки позднее изменены.
- Переименование сохраняет привязку; закрытие вкладки допускает отправку; недоступный файл блокирует весь запрос без потери черновика.
- Неизвестный или недостаточный лимит контекста не приводит к молчаливому усечению или отправке без выбранных заметок.
- Поиск дополняет выбранные заметки, а ошибка или остановка не добавляет неуспешный ход в историю последующих запросов.

## Границы первой версии

- Передача выделенного фрагмента отложена.
- Автоматическое раскрытие связанных заметок и вложенных файлов не входит в задачу.
- Автоматическое изменение заметок по ответу модели не входит в задачу: функция предназначена для обсуждения содержимого в чате.
- Нет отдельной кнопки прикрепления или обязательного плейсхолдера `@note`; способ выбора — список по `@`.
- Автоматическое усечение и пересказ выбранных заметок не входят в задачу.
- Нужны нативное оформление Obsidian, цвета активной темы и доступное управление списком с клавиатуры.

## Проверка при реализации

Автоматические проверки должны охватить многословную фильтрацию и поиск с пропуском букв, ранжирование, привязку и удаление упоминаний, чтение актуального текста при отправке, историю снимков, обычный ввод `@`, ошибки чтения и ограничения контекста. Перед коммитом обязательна `npm run build`. Инструкции ручной проверки размещаются в `docs/testing`, отдельные тестовые хранилища и их генераторы — в `docs/fixtures`; ручную проверку выполняет пользователь.

Спецификация составлена по итогам интервью `grill-with-docs`; пользователь подтвердил общее понимание и окончательный набор требований. После подтверждения пользователь дополнительно потребовал поддержку сокращённого ввода без пробелов, например `projemonex`; это требование включено в фильтрацию и критерии приёмки.
