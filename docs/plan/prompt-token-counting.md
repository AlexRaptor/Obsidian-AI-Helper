# Подсчёт токенов для рекомендаций папок

Реализован пункт 1 [списка задач по контексту](folder-recommendation-context-fallback.md) для LM Studio. Автоматические проверки (596 тестов) и производственная сборка пройдены. Пользователь подтвердил прохождение ручной проверки в Obsidian. Автоматический embedding-отбор папок в эту работу не входит.

## Поведение

Разбор существующей заметки, поиск папок и смешанный поиск в чате используют токенизатор выбранного загруженного экземпляра LM Studio. Плагин читает `/api/v1/models`, однозначно сопоставляет выбранную модель с загруженным экземпляром и через браузерный SDK применяет шаблон диалога ко всем сообщениям, затем считает токены полученного текста. Инструкции, история, вопрос, заметка и описания включаются в том виде, в котором будут отправлены для ответа. Генерация для подсчёта не запускается, модели не загружаются автоматически.

К числу токенов добавляются резерв ответа (по умолчанию 1024) и запас 256 токенов. Для запроса уточнения поисковой формулировки резерв ответа составляет 256 токенов. В смешанном поиске сначала учитываются все описания папок, затем оставшееся место выделяется источникам заметок; добавленные источники по-прежнему ограничиваются бюджетом UTF-8 байт, после чего весь итоговый запрос проверяется снова.

Текст подсчитывается на том же настроенном сервере, который генерирует ответ. Для localhost это локальная обработка без отправки текста в Интернет. Подсчёт требует передачи текста и работы токенизатора, но не создаёт ответ и не добавляет сообщения в историю диалога. Для генерации текст передаётся повторно.

При отсутствии поддерживаемых метаданных, незагруженной или неоднозначной модели, недоступном WebSocket/SDK, некорректном ответе либо таймауте используется прежняя оценка: каждый UTF-8 байт сериализованного запроса считается токеном. Ожидание одного подсчёта ограничено пятью секундами. Отмена закрывает SDK-клиент и предотвращает запуск следующих этапов; поздние результаты игнорируются. Адрес, префикс обратного прокси и ключ берутся из текущего снимка настроек. При проверке не опрашиваются другие серверы.

В сообщении о нехватке контекста при разборе указывается использованный способ подсчёта. Предпросмотр размера описаний в настройках остаётся локальной консервативной оценкой, явно обозначенной как оценка по байтам; открытие настроек не отправляет описания для подсчёта. Поиск только по заметкам сохраняет консервативную проверку. Подсчёт для других модель-серверов — будущая задача.

## Критерии приёмки

1. Полный запрос проходит, когда подсчёт выбранной моделью с резервом и запасом помещается в окно, даже если оценка по байтам превышает его.
2. Запрос отклоняется при превышении окна; заметка, история и описания не усекались. Равенство размеру окна допустимо.
3. Шаблон диалога применяется до токенизации; используется именно выбранный загруженный экземпляр, без подмены на первую доступную модель.
4. Подсчёт не вызывает генерацию и не добавляет сообщения в историю. Данные отправляются только на настроенный сервер.
5. При ошибке или отсутствии поддержки сохраняется консервативная проверка; некорректное число токенов не ослабляет её.
6. Отмена и таймаут освобождают SDK-клиент; поздний результат не запускает токенизацию или ответ.
7. В смешанном режиме все описания сохраняются, бюджет источников заметок остаётся в байтах, итоговый запрос проверяется целиком.

Основа выбранного способа: [LM Studio — Tokenization](https://beta.lmstudio.ai/docs/typescript/tokenization), [браузерный SDK](https://lmstudio.ai/docs/typescript). Ручная проверка: [инструкция](../testing/prompt-token-counting.md).
