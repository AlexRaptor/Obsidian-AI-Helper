# Подсчёт токенов для рекомендаций папок

Реализован пункт 1 [списка задач по контексту](folder-recommendation-context-fallback.md) для LM Studio; добавлена поддержка vLLM и llama.cpp. Автоматические проверки (627 тестов) и производственная сборка пройдены. Пользователь подтвердил ручную проверку LM Studio. Проверку новых адаптеров в Obsidian нужно выполнить отдельно. Автоматический embedding-отбор папок в эту работу не входит.

## Поведение

Разбор существующей заметки, поиск папок и смешанный поиск в чате используют токенизатор выбранной модели там, где сервер предоставляет подходящий API. Инструкции, история, вопрос, заметка и описания включаются в том виде, в котором будут отправлены для ответа. Генерация для подсчёта не запускается.

| Сервер | Способ подсчёта |
| --- | --- |
| LM Studio | `/api/v1/models` однозначно сопоставляет выбранную модель с загруженным экземпляром; браузерный SDK применяет шаблон диалога и считает токены текста. |
| vLLM | `/v1/models` подтверждает выбранный идентификатор и `max_model_len`; `/tokenize` получает все сообщения и модель, применяет серверный шаблон с началом ответа. Дополнительные специальные токены поверх шаблона отключены, как в запросе диалога. Число сверяется с массивом возвращённых идентификаторов токенов. |
| llama.cpp | `/v1/models` подтверждает модель; `/props?model=…&autoload=false` проверяет свойства выбранной модели. `/apply-template` формирует запрос, затем `/tokenize` считает его с обработкой специальных токенов, как в запросе ответа. Все POST содержат выбранную модель и `autoload=false` в адресе; токенизация не загружает модель через маршрутизатор. |
| Ollama | По решению пользователя сохраняется консервативная оценка по байтам. В публичном API нет отдельной токенизации; пробный запрос генерации не используется. |

Выбор адаптера основан на метаданных сервера, а не на названии модели. Неподдерживаемые версии API переходят к оценке по байтам.

К числу токенов добавляются резерв ответа (по умолчанию 1024) и запас 256 токенов. Для запроса уточнения поисковой формулировки резерв ответа составляет 256 токенов. В смешанном поиске сначала учитываются все описания папок, затем оставшееся место выделяется источникам заметок; добавленные источники по-прежнему ограничиваются бюджетом UTF-8 байт, после чего весь итоговый запрос проверяется снова.

Текст подсчитывается на том же настроенном сервере, который генерирует ответ. Для localhost это локальная обработка без отправки текста в Интернет. Подсчёт требует передачи текста и работы токенизатора, но не создаёт ответ и не добавляет сообщения в историю диалога. Для генерации текст передаётся повторно.

При отсутствии поддерживаемых метаданных, недоступной или неоднозначной модели, недоступном WebSocket/SDK или HTTP API, некорректном ответе либо таймауте используется прежняя оценка: каждый UTF-8 байт сериализованного запроса считается токеном. Ожидание одного подсчёта ограничено пятью секундами для всей цепочки запросов. Отмена закрывает SDK-клиент или отменяет HTTP-запрос и предотвращает запуск следующих этапов; поздние результаты игнорируются. Адрес, префикс обратного прокси и ключ берутся из текущего снимка настроек. При проверке не опрашиваются другие серверы.

В сообщении о нехватке контекста при разборе указывается использованный способ подсчёта и название фактически применённого сервера. Предпросмотр размера описаний в настройках остаётся локальной консервативной оценкой, явно обозначенной как оценка по байтам; открытие настроек не отправляет описания для подсчёта. Поиск только по заметкам сохраняет консервативную проверку.

## Критерии приёмки

1. Полный запрос проходит, когда подсчёт выбранной моделью с резервом и запасом помещается в окно, даже если оценка по байтам превышает его.
2. Запрос отклоняется при превышении окна; заметка, история и описания не усекались. Равенство размеру окна допустимо.
3. Шаблон диалога применяется до токенизации; используется именно выбранный загруженный экземпляр, без подмены на первую доступную модель.
4. Подсчёт не вызывает генерацию и не добавляет сообщения в историю. Данные отправляются только на настроенный сервер.
5. При ошибке или отсутствии поддержки сохраняется консервативная проверка; некорректное число токенов не ослабляет её.
6. Отмена и таймаут освобождают SDK-клиент или отменяют HTTP-запрос; поздний результат не запускает следующий этап или ответ.
7. В смешанном режиме все описания сохраняются, бюджет источников заметок остаётся в байтах, итоговый запрос проверяется целиком.
