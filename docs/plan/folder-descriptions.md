# Описания папок, поиск папок и рекомендации размещения

Статус: итоговый документ согласован пользователем; общее понимание подтверждено. Реализация не начата.

Спецификация опубликована в [GitHub Issue #25](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/25) с меткой `ready-for-agent`; локальная версия — [folder-descriptions-spec.md](folder-descriptions-spec.md).

## Назначение и область первой версии

Пользователь описывает назначение папок в отдельных Markdown-файлах. Плагин использует эти описания для поиска папок и предложения места хранения существующей или будущей заметки.

Правила организации задаются описаниями. Встроенного предпочтения PARA нет; PARA поддерживается шаблонами описаний с явно сформулированными целями, критериями и приоритетами.

Первая версия работает с одной открытой заметкой, последовательным разбором заметок выбранной папки (включая Inbox) и вопросами в чате. Проверка всего хранилища на правильность существующего размещения, автоматическое перемещение без выбора пользователя, копирование в несколько папок и создание новых папок по рекомендации не входят в область первой версии.

## Файлы описаний

- Имя по умолчанию — `_folder.md`. В настройках задаётся единое имя Markdown-файла с расширением `.md`, без пути.
- Описание относится непосредственно к папке, где находится файл. Кандидатами могут быть только папки с собственным содержательным описанием.
- Описания родителей дополняют контекст вложенной папки. При явном противоречии более конкретное описание имеет приоритет; противоречие показывается пользователю.
- Описание родителя само по себе не делает вложенную папку кандидатом.
- Обрабатываются описания во всех папках, включая исключённые из обычной индексации. Исключения продолжают действовать для обычного поиска заметок.
- Связанные заметки и вложения автоматически не читаются.

## Создание и локализация описаний

Действие «Создать описание» доступно только в контекстном меню папки. Оно создаёт и открывает файл с настроенным именем. Если файл уже существует, действие открывает его без перезаписи.

Шаблон содержит три раздела с крайне краткими нейтральными пояснениями в Markdown-комментариях:

| Раздел | Пояснение |
| --- | --- |
| Назначение | Для чего нужна папка |
| Сюда относятся | Какие заметки хранить здесь |
| Не относятся | Что хранить в других папках |

Комментарии не участвуют в анализе. Файл, содержащий только заголовки, комментарии и пробелы, не делает папку доступной для поиска или рекомендаций. Заполнение всех разделов не обязательно: достаточно содержательного описания.

Новые шаблоны используют текущий язык плагина. Смена локализации не изменяет существующие файлы и их имена. Русские и английские описания могут использоваться одновременно. Описания заполняет пользователь; генерация описаний моделью не входит в первую версию.

## Рекомендация для открытой заметки

1. Пользователь явно вызывает команду «Предложить папку для текущей заметки».
2. Для анализа используется текущий текст редактора, название и свойства заметки. Команда доступна и для заметки из исключённой папки; это не включает заметку в обычный индекс.
3. Плагин передаёт заметку, пути папок и подходящие описания, включая контекст родителей, настроенной модели диалога на модель-сервере.
4. Анализ выполняется как самостоятельная задача без истории чата и его пользовательского системного промпта.
5. Результат показывается в нативной вкладке «Разбор заметок» в правой панели Obsidian: до трёх кандидатов, короткие объяснения, возможность просмотра описания и кнопка переноса после выбора пользователя. Проценты уверенности не показываются.

Допустимы результаты «оставить в текущей папке» и «подходящей папки нет». При недостатке содержания плагин сообщает об этом, не угадывая назначение по ссылкам. Плагин проверяет, что предлагаемые папки существуют и принадлежат переданному набору кандидатов.

Результат представляет полный путь папки, ссылку на её описание и объяснение соответствия заметке.

Вкладка разбора расположена рядом с чатом и становится активной при запуске. Содержимое чата не заменяется. Заметка остаётся доступной для просмотра и редактирования в основном редакторе; полный текст в панели разбора не дублируется. Эта же вкладка используется для очереди заметок.

Если текст, название или свойства обрабатываемой заметки изменились после начала анализа, пользователь получает сообщение об изменениях. Рекомендации для прежней версии отмечаются как устаревшие. Пользователь может выбрать «Обновить рекомендации» и анализировать текущую версию либо «Перенести по прежним рекомендациям». Автоматической отправки запросов при каждом изменении нет.

## Последовательный разбор Inbox или другой папки

Действие «Разобрать заметки» доступно в контекстном меню любой папки. Отдельная настройка папки Inbox не обязательна.

Перед запуском показываются число Markdown-заметок и опция «Включить вложенные папки». По умолчанию разбираются только заметки непосредственно в выбранной папке. Файлы описаний не включаются в очередь. Явный запуск разрешает анализ выбранных заметок, включая заметки из исключённых папок.

Пользователь последовательно получает рекомендации для каждой заметки и выбирает «Перенести», «Пропустить» или «Завершить разбор». После переноса или пропуска показывается следующая заметка, которая открывается в основном редакторе. Панель показывает название и исходный путь обрабатываемой заметки. Для открытой заметки используется текущий текст редактора; остальные читаются непосредственно перед их анализом. Решение о каждом переносе принимает пользователь; автоматического применения рекомендаций ко всей папке нет.

При ошибке анализа текущая позиция сохраняется; показываются причина и действия «Повторить», «Пропустить», «Завершить разбор». Ошибка не приводит к автоматическому пропуску или бесконечным повторным запросам. Если файл удалён до начала его анализа, это отмечается и очередь переходит к следующему.

Очередь существует только в рамках одного запуска разбора. При завершении текущий запрос останавливается и показывается итог: сколько заметок перенесено, пропущено и осталось неразобранными. Выполненные переносы сохраняются. Повторный запуск заново собирает заметки выбранной папки; сохранения очереди между запусками нет.

## Поиск папок и советы в чате

Отдельное окно поиска папок не создаётся. При включённом поиске в чате пользователь выбирает источники:

- «Заметки» — режим по умолчанию, обычные заметки с соблюдением существующих исключений; файлы описаний не конкурируют с ними.
- «Папки» — описания папок независимо от исключений обычной индексации.
- «Заметки и папки» — оба типа источников с их соответствующими правилами доступа.

Выбор типов источников применяется до отбора лучших результатов. Описания доступны как отдельный тип источников; необходимость отдельного физического индекса этим решением не устанавливается.

Поиск папок остаётся частью обычного диалога, использующего историю и пользовательский системный промпт чата. Ответ представляет полный путь найденной папки, кликабельную ссылку на описание и объяснение соответствия запросу. Обычный поиск Obsidian продолжает видеть файлы описаний как Markdown-заметки.

В режимах «Папки» и «Заметки и папки» можно попросить совет ещё до создания заметки, например: «В какой папке лучше создать заметку о методе GTD?». Модель рекомендует существующие папки по их описаниям, при необходимости уточняет намерение в диалоге или сообщает, что подходящей папки нет. Сам вопрос не создаёт заметку и не перемещает файлы.

## Объём данных и модель-сервер

Первая версия анализа описаний не требует embedding-модели или индексации всего хранилища. Для подбора папки передаются все подходящие описания. Если заметка и описания не помещаются в доступный контекст, анализ останавливается с объяснением без молчаливого усечения. Предварительный смысловой отбор описаний оставлен на последующее развитие.

При анализе модель-сервер получает текст анализируемой заметки и описания папок. В поиске папок используются описания; совет о будущей заметке использует сформулированный пользователем запрос. Исключения обычной индексации не ограничивают передачу описаний папок для этих функций.

## Перенос заметки

- Перенос выполняется после выбора и подтверждения пользователя средствами Obsidian для корректной обработки внутренних ссылок.
- Перед переносом проверяются существование исходного файла, папки назначения и актуальность использованных описаний. При изменении описаний предлагается повторить анализ.
- Если заметка изменилась, перенос по прежним рекомендациям возможен после явного выбора соответствующего действия пользователем. Вместо обязательного повторного анализа пользователь сам выбирает обновление рекомендаций или перенос по прежнему результату.
- При совпадении имени перенос останавливается; пользователь может открыть существующий файл. Автоматической перезаписи и переименования заметки нет.

## Смена имени файла описания

Перед сохранением нового имени показывается число существующих описаний со старым именем, которые перестанут распознаваться. Пользователь выбирает:

1. Использовать новое имя: сохранить настройку, оставить существующие файлы без изменений и распознавать только файлы с новым именем.
2. Переименовать существующие описания: переименовать файлы со старым именем и сохранить новую настройку после успешного завершения всей операции.
3. Отмена: оставить настройку и файлы без изменений.

Переименование охватывает файлы описаний со старым именем, включая незаполненные шаблоны и файлы в исключённых папках.

Перед началом переименования проверяются все назначения. При любом конфликте операция не начинается; показываются конфликтующие пути. Пользователь может устранить конфликт или выбрать изменение настройки без переименования. Файлы не объединяются и не перезаписываются.

Переименование выполняется средствами Obsidian для обработки ссылок. При ошибке новая настройка не сохраняется; плагин пытается вернуть уже переименованным файлам прежние имена. Если восстановление удалось не полностью, показываются точные пути оставшихся изменений.

## Проверочные сценарии для будущей реализации

- Содержательная заметка получает подходящие папки и объяснения; текущая папка и отсутствие подходящей папки являются допустимыми результатами.
- Совет о ещё не созданной заметке работает в чате и не создаёт файл.
- Разбор выбранной папки последовательно предлагает места для заметок, допускает пропуск и завершение; вложенные папки включаются только по явному выбору.
- Файлы описаний не входят в очередь разбора; исключения обычной индексации не блокируют явно выбранный разбор.
- Панель разбора открывается отдельной вкладкой справа рядом с чатом; очередная заметка открывается в основном редакторе.
- Изменение обрабатываемой заметки помечает рекомендации как устаревшие; пользователь может обновить их или явно перенести по прежним рекомендациям.
- Ошибка анализа сохраняет позицию очереди и допускает повтор, пропуск или завершение. Остановка отменяет текущий запрос и сохраняет уже выполненные переносы.
- Папка без собственного описания не становится кандидатом благодаря описанию родителя.
- Описания исключённых папок доступны для поиска и рекомендаций; обычные заметки этих папок остаются исключёнными из обычного поиска.
- Незаполненный шаблон не участвует в анализе; заполнение одного раздела делает описание содержательным.
- Смена языка меняет новые шаблоны, сохраняя существующие файлы.
- Три режима поиска используют соответствующие типы источников до отбора результатов.
- Превышение контекста не приводит к скрытому сокращению набора описаний.
- Конфликт имени заметки не приводит к перезаписи или автоматическому переименованию.
- При смене имени описания проверяются отмена, изменение только настройки, успешное переименование, конфликт до начала и ошибка с восстановлением.
