# Фрагменты и поиск в общем бюджете контекста

## Parent

Спецификация: https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/41

## What to build

Пользователь включает существующий поиск для вопроса с несколькими фрагментами и целыми заметками. Модель получает все явно выбранные снимки без изменений; найденные материалы занимают только оставшуюся часть общего бюджета контекста.

## Acceptance criteria

- [ ] Во всех существующих режимах поиска явно выбранные фрагменты и целые вложения остаются обязательным контекстом и не заменяются найденными материалами.
- [ ] Проверка вместимости учитывает системный контекст, историю со снимками, новый вопрос, все новые снимки, служебные представления, резерв ответа и существующий запас. Учитывается также подготовительный запрос поиска, если он выполняется.
- [ ] Применяются существующие автоматический лимит и приоритет корректного ручного значения. Неизвестный лимит блокирует отправку с понятным объяснением; запасное значение окна для сообщений со снимками не используется.
- [ ] При недостаточном бюджете сохраняется весь черновик, запрос с частичным набором вложений не отправляется. Нет молчаливого обрезания снимков, удаления истории или исключения выбранного контекста ради поисковых материалов.
- [ ] Поисковые материалы используют оставшийся бюджет с сохранением существующих правил каждого режима. Отсутствие места для необязательных найденных фрагментов само по себе не удаляет явно выбранные снимки и не меняет их текст.
- [ ] В следующем вопросе успешная история содержит прежние снимки, а поиск получает актуальные материалы согласно существующему поведению. Старый снимок не перечитывается ради повторного подсчёта контекста.
- [ ] Выключенный поиск не требует готового индекса для явных фрагментов; включённый поиск сохраняет существующие требования к настройкам и доступности выбранного режима. Новые режимы и настройки не добавляются.
- [ ] Автоматические интеграционные проверки наблюдают содержимое итоговых и подготовительных запросов, резерв ответа, блокировку и сохранность черновика при разных лимитах. Сценарии охватывают несколько фрагментов, полное вложение, историю и все существующие режимы поиска.
- [ ] Регрессии поиска, бюджета, истории и целых вложений, а также производственная сборка проходят. Дополнительная ручная приёмка не требуется.
