# Контекст диалога и бюджет источников — ручная проверка #21

Автоматические проверки используют публичный поиск по заметкам, ввод/кнопки чата,
настройки и подменяемый HTTP-транспорт. Реальная приёмка Obsidian/LM Studio
в рамках реализации не выполнялась; этот сценарий подготовлен для неё.

1. Собрать плагин (`npm run build`), установить `main.js`, `manifest.json`,
   `styles.css` в папку плагина и перезагрузить Obsidian. Подключить модель
   диалога и embedding-модель, указать фактическое окно контекста либо проверить
   его автоматическое определение.
2. Создать заметку «Проект Север»: «Проект Север начинается 10 октября.
   Срок завершения — 20 ноября. Ответственный — Анна». Построить индекс,
   включить поиск в новом диалоге. Спросить «Расскажи о проекте Север», затем
   «А какие сроки?». Ожидается поиск сроков проекта Север и ответ со ссылкой
   на актуальный фрагмент. Дополнительный запрос к модели формулирует поисковый
   запрос; его текст не появляется как сообщение диалога.
3. Изменить срок на 1 декабря и обновить индекс. Повторить вопрос-продолжение.
   Раскрытый фрагмент должен содержать новый срок. Старые реплики сохраняются;
   исходные фрагменты прошлых ответов не входят в историю нового запроса.
4. Исключить папку проекта. Настройки поясняют, что пересказанные сведения
   в прежних сообщениях сохраняются. Следующий поиск не использует исключённые
   заметки; при ошибке или отсутствии источников обычный ответ не запускается.
5. В расширенных настройках изменить «Бюджет источников» / «Source budget»
   с 12000 на 24000 байт. Пустое значение, 0, отрицательные числа и дроби
   отклоняются; сохраняется последнее корректное значение. Значение сохраняется
   после перезапуска. Фактический объём дополнительно ограничен доступным окном:
   учитываются системная инструкция, полная история, вопрос и резерв ответа.
   Оценка консервативная: каждый байт сериализованного контекста считается токеном,
   также оставляется запас 256. Это не точный токенизатор модели.
6. Уменьшить бюджет до 1 байта либо накопить длинную историю, оставляющую мало
   места для источников. Ожидается предложение начать новый диалог. История
   сохраняется целиком, автоматической суммаризации и сокращения нет.
7. Во время формирования поискового запроса отключить модель-сервер. Ожидается
   ошибка формирования запроса, вопрос возвращается во ввод, ответ без заметок
   не запускается. Восстановить соединение и повторить: в истории одна успешная
   пара сообщений для этого вопроса. Повторить с кнопкой остановки во время
   формирования запроса и поиска; запоздалый результат не должен запускать ответ.
8. Повторить состояния ошибки и бюджета на русском и английском языках.
   Проверить, что кнопка нового диалога очищает историю по явному действию.
