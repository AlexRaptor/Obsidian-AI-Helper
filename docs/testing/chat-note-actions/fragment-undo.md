# №70: обычная отмена замены прикреплённого фрагмента

Автоматические проверки покрывают границы, полную основу на момент прикрепления, конфликты, идентичность файла, остановку и новый диапазон результата. Ручная проверка нужна только для интеграции с реальной историей отмены Obsidian: заменитель API и отдельная история CodeMirror её полностью не воспроизводят. Проверку выполняет пользователь; до подтверждения №70 остаётся открытым.

## Подготовка и восстановление

Исходные данные: `/Users/selivanov/code/Obsidian-AI-Helper/docs/testing/chat-note-actions/notes/`.

Хранилище: `/Users/selivanov/code/Obsidian-AI-Helper/docs/testing/chat-note-actions/fragment-vault/`.

Закройте это тестовое хранилище перед подготовкой или восстановлением. Из корня репозитория:

```sh
python3 docs/testing/prepare_vault.py --source docs/testing/chat-note-actions/notes --dest docs/testing/chat-note-actions/fragment-vault
```

Первый запуск собирает и устанавливает текущий плагин. Настройте подключение к модель-серверу с поддержкой инструментов в этом хранилище; генератор не переносит секреты из других хранилищ. Для обновления реализации выберите режим 2 (восстановить материалы, пересобрать плагин, сохранить настройки); между сценариями — режим 3 (восстановить материалы без сборки). Режимы 1–3 удаляют тестовый контент вне `.obsidian`. После восстановления заново откройте хранилище: начнутся новая история отмены и новый диалог.

## Фрагмент, соседний ручной ввод и две последовательные замены

1. Откройте `Проверка/План.md` в редакторе. Допишите в конце заметки «Ручная метка до правки».
2. Выделите только абзац, начинающийся «Мы собираемся отправиться в поездку на поезде…». Перейдите в чат, введите «Замени прикреплённый фрагмент кратким списком дел @@» и подтвердите предложение фрагмента клавишей Tab или нажатием на него. Отправьте сообщение.
3. После фактического результата «Изменена заметка» проверьте, что в редакторе заменился только выделенный абзац. Одна Cmd/Ctrl+Z возвращает весь исходный абзац, не затрагивая ручную метку, YAML, верхнюю и нижнюю границы и ссылку. Обычный повтор возвращает весь список одним действием.
4. Допишите «Ручная метка после правки». Убедитесь, что сначала отменяется только этот ручной ввод, затем отдельной отменой — замена фрагмента. Повторы возвращают их раздельно.
5. Для проверки следующей собственной замены восстановите хранилище приведённой командой, режим 3, и повторите шаг 2 без ручных меток. Не делая ручных изменений, отдельным сообщением поручите «Сократи полученный список до двух пунктов». После успеха две отмены по одной возвращают предыдущий список, затем исходный абзац; два повтора возвращают обе замены раздельно. Остальной текст остаётся прежним.

Перед следующим сценарием восстановите это же хранилище приведённой командой, режим 3.

## Закрытый редактор цели

1. Откройте `Проверка/План.md`, выделите тот же абзац. В чате введите «Замени прикреплённый фрагмент кратким списком дел @@» и подтвердите предложение, но пока не отправляйте сообщение.
2. Закройте вкладку заметки, оставив чат открытым, затем отправьте подготовленное сообщение. Плагин должен открыть редактор той же заметки и применить замену только выбранного абзаца.
3. В открытом редакторе одна обычная отмена возвращает весь исходный абзац, а повтор — весь список. YAML, соседние абзацы и ссылка сохраняются. Само открытие заметки не должно обходить историю отмены.

При несоответствии достаточно сообщить сценарий, шаг и фактическое поведение. Проверка вставки у курсора из общего комплекта `native-undo.md` относится к следующему тикету и для №70 не требуется.
