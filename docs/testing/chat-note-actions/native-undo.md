# Отмена редактирования заметок через чат в Obsidian

Эта проверка нужна после реализации: заменитель Obsidian в Vitest не воспроизводит реальную историю отмены и группировку редакторских транзакций. Сейчас данные подготовлены для будущей приёмки; наличие собранного тестового хранилища не означает, что инструменты уже реализованы.

Ручную проверку выполняет пользователь. Остальное поведение задачи проверяется автоматически. Проверять на настольном Obsidian с реализованной версией плагина и моделью диалога, поддерживающей вызовы инструментов. Подключение настроить в тестовом хранилище самостоятельно; генератор не переносит секреты и настройки других хранилищ.

## Хранилище и восстановление

Исходные данные: `/Users/selivanov/code/Obsidian-AI-Helper/docs/testing/chat-note-actions/notes/`.

Хранилище: `/Users/selivanov/code/Obsidian-AI-Helper/docs/testing/chat-note-actions/notes-vault/`.

Перед подготовкой и восстановлением закрыть это хранилище в Obsidian. Из корня репозитория выполнить:

```sh
python3 docs/testing/prepare_vault.py --source docs/testing/chat-note-actions/notes --dest docs/testing/chat-note-actions/notes-vault
```

Первый запуск собирает текущий плагин и устанавливает его по идентификатору manifest. Для повторной приёмки после изменения кода выбрать режим 2: восстановить материалы, пересобрать плагин и сохранить настройки. Между сценариями без изменения кода выбрать режим 3: восстановить материалы, сохранив установленный плагин и настройки. Эти режимы удаляют созданные тестом заметки за пределами `.obsidian`. После восстановления открыть хранилище заново, чтобы начать с новой историей отмены и новым диалогом.

## 1. Целая заметка и соседний ручной ввод

1. В указанном выше хранилище открыть `Проверка/План.md` в режиме редактирования. Вручную дописать в конце «Ручная метка до правки».
2. Прикрепить целую заметку через существующее упоминание `@`. Поручить: «Исправь в прикреплённой заметке фразу “Мы собираемся отправиться в поездку на поезде” на “Мы поедем на поезде”. Остальное сохрани».
3. После сообщения об успехе вернуться в редактор. Одно Cmd/Ctrl+Z должно отменить только правку модели, оставив ручную метку. Обычным повтором вернуть только правку модели.
4. Добавить «Ручная метка после правки». Проверить, что ручной ввод и правка модели отменяются отдельными действиями в обратном порядке. YAML и остальной текст сохраняются.

Восстановить это же хранилище описанной выше командой с режимом 3 перед следующим сценарием.

## 2. Выделенный фрагмент и вставка

1. В этом же хранилище выделить только абзац о покупке билетов в `Проверка/План.md`, прикрепить через `@@` и поручить: «Замени прикреплённый фрагмент кратким списком дел».
2. Проверить, что одна обычная отмена восстанавливает весь исходный абзац, а повтор возвращает весь список. Верхняя и нижняя границы, YAML и ссылка не меняются.
3. Поставить курсор после строки «Место вставки…», перейти в чат и поручить: «Вставь у курсора отдельной строкой: Проверить документы».
4. Убедиться, что одна отмена удаляет только вставку. Следующая отмена отменяет предшествующую замену фрагмента; повторы возвращают их раздельно.

Восстановить это же хранилище описанной выше командой с режимом 3 перед следующим сценарием.

## 3. Несколько заметок и закрытый редактор цели

1. В этом же хранилище прикрепить `Проверка/План.md` и `Проверка/Материал.md`. Закрыть вкладку второй заметки, оставив чат открытым.
2. Поручить: «Добавь в конец заметки “План” строку “План проверен”, затем добавь в конец заметки “Материал” строку “Материал проверен”».
3. После фактического выполнения открыть каждую заметку и проверить, что её обычная отмена убирает только её добавленную строку. Отмена в одной заметке не меняет другую. Повтор возвращает строку в той же заметке.
4. Если для записи второй заметки плагин открывал редактор, проверить отмену именно в этом редакторе: открытие цели не должно обходить историю отмены записью напрямую в хранилище.

При любом несоответствии не считать требование отмены выполненным. Для исправления достаточно указать сценарий, шаг и фактическое поведение; отдельный отчёт по остальным пользовательским историям не требуется.
