# Тикет №32: последовательный разбор папки

Сценарии подготовлены для проверки пользователем в настоящем Obsidian. Агент их вручную не выполнял.

## Чистое хранилище и восстановление

Из корня `/Users/selivanov/code/Obsidian-AI-Helper`:

```sh
npm run build
node docs/fixtures/issue32-folder-review/create-vault.mjs docs/fixtures/issue32-folder-review/vault
```

Готовое хранилище: `/Users/selivanov/code/Obsidian-AI-Helper/docs/fixtures/issue32-folder-review/vault`.
Генератор с точным содержимым исходных файлов: `docs/fixtures/issue32-folder-review/create-vault.mjs`.
Он копирует собранный плагин, создаёт настройки и отказывается перезаписывать существующий каталог. Для восстановления создайте новую копию командой с новым конечным каталогом, например `docs/fixtures/issue32-folder-review/vault-reset-1`, и откройте её как хранилище. Рабочее хранилище пользователя не используется.

В Obsidian откройте этот каталог как хранилище, выключите Restricted mode в Community plugins и включите Obsidian AI Helper. После обновления сборки скопируйте `main.js`, `manifest.json`, `styles.css` в `.obsidian/plugins/obsidian-ai-helper/` тестового хранилища и перезагрузите Obsidian. Фактический id указан в `manifest.json` и определяет имя каталога.

Настройки генератора: русский интерфейс, `_folder.md`, контекст 32768, Inbox исключён из обычной индексации, автоматическая индексация выключена. В настройках плагина задайте доступный OpenAI-совместимый модель-сервер, его ключ при необходимости и модель диалога, поддерживающую JSON и контекст не меньше 32768. Embedding-модель для разбора не нужна. Для оценки рекомендаций подходит ваша модель диалога; конкретная рекомендация не гарантирована. Описания `Справка/_folder.md` и `Дневник/_folder.md` задают ожидаемые смысловые варианты. В Obsidian включите автоматическое обновление внутренних ссылок; генератор задаёт `alwaysUpdateLinks: true`.

## Область, редактор, перенос и пропуск

1. В меню `Inbox` выберите «Разобрать заметки». Открывается существующая вкладка «Разбор заметок» справа, без дополнительных редакторов. До запуска показано 4 заметки. `_folder.md` и `картинка.txt` исключены; исключение Inbox из индекса не мешает разбору.
2. Включите «Включить вложенные папки»: счётчик становится 5. Выключите: снова 4. Запросы до нажатия «Начать разбор» не отправляются.
3. Начните разбор. Заметка открывается в основном редакторе; панель показывает её название, путь и рекомендации. Порядок фиксирован по полному пути; следующий файл сам не переносится.
4. Используйте «Пропустить» для неподходящих заметок. На `Inbox/Конфликт.md` при рекомендации `Справка` попробуйте перенос. Конфликт сохраняет позицию и оба файла; кнопка открытия существующего файла открывает `Справка/Конфликт.md`. Вернитесь к исходной заметке и пропустите её.
5. На `Inbox/Метод.md` измените текст в основном редакторе. Результат становится устаревшим; ввод не вызывает новый запрос. «Обновить рекомендации» анализирует текущую редакцию. Ещё одна правка позволяет явно выбрать «Перенести по прежним рекомендациям». При переносе в `Справка` новая редакция сохраняется и открывается следующая заметка. Ссылка в `Связи/Обзор.md` обновляется по настройкам Obsidian.
6. Завершите очередь пропусками или выбранными переносами. Итог показывает перенесённые, пропущенные и оставшиеся (0); дополнительная команда для каждой заметки не нужна.
7. Повторите запуск с вложенными папками: `Inbox/Вложенная/Справка.md` открывается и анализируется как часть очереди.

## Свежий текст, удаление и ошибки

1. Восстановите хранилище. Начните очередь и остановитесь на первой заметке. До её пропуска измените текст одной из следующих заметок, сохраните его; удалите `Inbox/Удалить.md`.
2. Продолжайте пропусками. Изменённая заметка анализируется по новому тексту. Удалённый файл отмечается в панели как удалённый до анализа, учитывается среди пропущенных и не открывается для переноса.
3. В новом запуске задайте недоступный адрес модель-сервера. Ошибка сохраняет заметку и счётчики, без автоматического повтора. Исправьте адрес и нажмите «Повторить»: анализ той же заметки завершается. «Пропустить» при ошибке также доступно.
4. Установите контекст 100: анализ сообщает о нехватке контекста без усечения. Верните 32768 и повторите. Позиция сохраняется.
5. Если тестовый модель-сервер позволяет задать ответ, верните вместо JSON текст `некорректный ответ`: панель сообщает об ошибке, сохраняет позицию и предлагает повтор, пропуск и завершение. Поздний ответ и некорректный ответ дополнительно покрыты автоматическими тестами; при отсутствии управляемого сервера этот ручной шаг отметьте как не выполненный.

## Остановка, итог и новый запуск

1. Восстановите хранилище, перенесите одну заметку и пропустите другую. На следующем анализе нажмите «Завершить разбор», желательно пока модель-сервер отвечает. Итог учитывает перенос, пропуск и все оставшиеся, включая текущую заметку.
2. Дождитесь возможного позднего ответа: итог не меняется, следующая заметка не открывается, переносов не происходит. Выполненный перенос сохраняется.
3. Запустите разбор Inbox заново: счётчик отражает текущие файлы, перенесённой заметки там нет, рекурсивный флажок по умолчанию выключен. Прежние результаты и счётчики не восстанавливаются.
4. Закройте вкладку во время разбора и откройте её снова через меню папки, затем перезапустите Obsidian и повторите. В обоих случаях предлагается новый запуск, старая очередь не восстанавливается.
5. Проверьте меню другой папки и корня хранилища: специальная настройка Inbox не нужна. На обычном файле действие меню папки отсутствует.
6. Смените имя описания на `Правила.md`, выбрав оставить существующие файлы, и создайте `Inbox/Правила.md`. Именно оно исключено из очереди; старый `_folder.md` теперь обычная заметка.

## Язык и доступность

Повторите запуск на английском языке: меню, флажок, действия, ошибки и итог локализованы. Сузьте правую панель; кнопки переносятся, пути читаются, основной редактор доступен. Проверьте Tab, Space для флажка и Enter для кнопок, видимость фокуса в светлой и тёмной теме. Убедитесь, что сообщения о прогрессе и итог имеют доступный статус.

Результаты ручной проверки записывайте отдельно, с моделью, версией Obsidian и фактически выполненными шагами.
