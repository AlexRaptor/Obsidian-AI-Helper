# Ручная проверка подсчёта токенов в LM Studio

Автоматические проверки выполняет агент; проверку в Obsidian выполняет пользователь.

## Подготовка

1. Собрать плагин через `npm run build`. Скопировать `main.js`, `manifest.json`, `styles.css` в папку плагина тестового хранилища и перезагрузить Obsidian.
2. Запустить локальный сервер LM Studio, загрузить модель диалога. Указать в плагине её идентификатор и адрес `http://127.0.0.1:1234/v1` (либо фактический порт). Для браузерного SDK должен быть разрешён доступ WebSocket, а при необходимости — CORS. Если сервер требует токен, указать его в существующем поле API-ключа.
3. Скопировать содержимое `docs/fixtures/prompt-token-counting/vault/` в тестовое хранилище. Имя описания папки в настройках — `_folder.md`.

## Проверки

1. **Точный подсчёт.** Установить вручную окно контекста 4096 и резерв ответа 1024. Открыть `Inbox/План поездки.md`, запустить рекомендацию папки. Запрос должен пройти, хотя объём байтов описаний превышает окно; описания и заметка сохраняются полностью. В журнале LM Studio видны применение шаблона и подсчёт, затем отдельный запрос генерации. При необходимости увеличить фактическое окно загруженной модели; ручное значение плагина не меняет конфигурацию сервера.
2. **Нехватка места.** Установить окно 128 и повторить разбор. Генерация не запускается; сообщение содержит требуемое и доступное число токенов и фразу «Запрос посчитан токенизатором выбранной модели в LM Studio».
3. **Запасной способ.** Восстановить окно 4096. Отключить доступ к SDK WebSocket, оставив HTTP доступным (например, правилами тестового обратного прокси), и повторить разбор. Плагин завершает попытку подсчёта и сообщает о нехватке контекста по консервативной оценке с пояснением про байты UTF-8. Содержимое не усекалось. Повторить при незагруженной модели: подсчёт не должен загружать её автоматически.
4. **Отмена.** При задержанном SDK-ответе нажать «Остановить» или закрыть вкладку разбора. Поздний результат не должен запускать генерацию либо менять остановленную вкладку.
5. **Папки в чате.** Включить поиск папок, задать вопрос «Куда положить план поездки?» и затем «А после завершения?». Проверка учитывает историю, вопрос, системный промпт и все описания; диалог сохраняется только после успешного ответа.
6. **Смешанный поиск.** Настроить embeddings для поиска заметок, проиндексировать заметку из набора и выбрать «Заметки и папки». Задать вопрос о плане поездки. Проверяются все описания плюс найденные источники; при небольшом контексте отображается ошибка без усечения описаний.
7. **Локальность.** При адресе `127.0.0.1` подсчёт обращается только к локальным HTTP и WebSocket адресам LM Studio. Загрузка SDK не требует CDN или другого внешнего сервиса. Показатель размера описаний в настройках остаётся консервативной оценкой и не запускает подсчёт на сервере.

Точное число токенов зависит от модели и её шаблона. Если тестовый текст не помещается при 4096 токенах для выбранной модели, увеличить окно до 8192; превышение объёма байтов проверить по примеру с запасным способом.

## Дополнительная проверка vLLM, llama.cpp и Ollama

Использовать тот же набор `docs/fixtures/prompt-token-counting/vault/`. Для каждого сервера выбрать реальный идентификатор его модели и настроенный OpenAI-совместимый адрес, заканчивающийся на `/v1`. Размер окна загруженной модели должен соответствовать настройке сервера; ручное значение в плагине его не изменяет.

| Сервер | Ожидаемый способ |
| --- | --- |
| vLLM | Метаданные `/v1/models`, затем `/tokenize` с сообщениями и выбранной моделью. Пробного запроса `/chat/completions` для подсчёта нет. |
| llama.cpp | Проверка `/v1/models` и свойств выбранной модели, затем `/apply-template` и `/tokenize`; `autoload=false` не позволяет маршрутизатору загружать модель для подсчёта. |
| Ollama | Консервативная оценка по байтам; отдельные `/api/chat` и `/api/generate` для подсчёта не вызываются. |

1. **Полный разбор на vLLM и llama.cpp.** Повторить проверку 1 с окном 4096 или 8192 в зависимости от токенизатора. В журналах видна цепочка подсчёта до единственного запроса ответа. Передаваемые описания не сокращаются.
2. **Название сервера в ошибке.** Для каждого сервера установить окно 128 и запустить разбор. На vLLM и llama.cpp сообщение называет соответствующий сервер и токенизатор выбранной модели. На Ollama сообщение объясняет оценку по UTF-8 байтам. Генерация ответа не запускается.
3. **Недоступный API.** На vLLM или llama.cpp через тестовый прокси отключить `/tokenize`; отдельно отключить `/apply-template` у llama.cpp. Запрос не считается по простому тексту без шаблона, используется оценка по байтам. При неверной модели не выбирается другая доступная модель. При нескольких моделях в маршрутизаторе llama.cpp используется именно выбранная.
4. **Задержка и отмена.** Задержать `/tokenize` у vLLM или `/apply-template` у llama.cpp, затем остановить разбор. Поздний результат не запускает следующую стадию или генерацию. Без остановки ожидание всей цепочки ограничено пятью секундами, после чего применяется оценка по байтам.
5. **Чат.** Повторить проверки 5 и 6 для vLLM и llama.cpp: поиск папок и смешанный поиск должны использовать новый подсчёт с полной историей и резервом ответа.
6. **Прокси и ключ.** При использовании обратного прокси подтвердить, что все запросы сохраняют его префикс и API-ключ, не обращаясь к другому хосту. Для llama.cpp POST-запросы сохраняют идентификатор модели в теле и `autoload=false` в адресе.
