# Ручная проверка перевода заметок после реализации

Проверять после реализации, прохождения автоматических тестов и production-сборки. Сейчас эти сценарии описывают ожидаемое поведение будущей функции, а не подтверждают её наличие.

Ручная проверка нужна только для реального управления областями и рендеринга Obsidian: тестовый помощник проверяет вызовы публичного API, но не доказывает вид и поведение приложения. Снимки, сбои, отмена, структура запросов, целостность результата и конфликты записи покрываются автоматическими проверками из спецификации; повторять их вручную не требуется.

Общее хранилище для обоих сценариев: `docs/testing/note-translation/translation-vault/`. Общий генератор: `docs/testing/prepare_vault.py`. Исходные заметки и вложения: `docs/testing/note-translation/notes/`.

## Подготовка

1. Из корня репозитория выполнить `python3 docs/testing/prepare_vault.py --source docs/testing/note-translation/notes --dest docs/testing/note-translation/translation-vault`. Скрипт выполняет `npm run build`, создаёт хранилище вместе с `.obsidian/plugins/<id из manifest.json>/` и копирует туда `main.js`, `manifest.json`, `styles.css`. Перед запуском должны быть установлены зависимости (`npm install`). Для непустой папки он предлагает меню действий ниже; по умолчанию или при отсутствии ответа ничего не меняет.
2. Дождаться сообщения о готовом хранилище и установленном плагине. Сборка и подготовка файлов завершаются до удаления старого контента. В режиме замены только контента сборка не запускается. Идентификатор папки плагина берётся из `manifest.json`.
3. Открыть хранилище в настольном Obsidian, отключить Restricted mode, включить плагин, настроить доступное подключение и модель диалога. Модель может переводить иначе, чем пример в инструкции: точные литературные формулировки не являются критерием этих визуальных сценариев.
4. Выполнить сценарии `workspace.md` и `appearance.md`. Они совместимы и используют одно хранилище.

## Восстановление исходного состояния

Не использовать рабочее пользовательское хранилище. Закрыть тестовое хранилище перед обновлением. Чтобы обновить уже настроенное хранилище, передать его путь:

```sh
python3 docs/testing/prepare_vault.py --source docs/testing/note-translation/notes --dest "/путь/к/тестовому хранилищу"
```

Для непустой папки доступны четыре действия:

1. **Заменить полностью** — заменить все заметки, вложения и `.obsidian`, собрать и установить плагин заново. Настройки будут сброшены.
2. **Заменить, сохранив настройки плагина** — заменить заметки и вложения, собрать и обновить плагин. Сохранить `.obsidian`, включая файл `.obsidian/plugins/<manifest id>/data.json`, настройки Obsidian и другие плагины.
3. **Заменить только контент** — заменить заметки и вложения тестовыми данными. Оставить `.obsidian`, установленный плагин и его настройки без изменений; сборка не требуется.
4. **Отмена** — ничего не менять. Это действие по умолчанию при Enter или отсутствии ввода.

В вариантах 1–3 старый контент за пределами `.obsidian` удаляется. При отказе или ошибке сборки существующее хранилище не изменяется. Настройки и секреты не копируются из других хранилищ.

Для отдельной новой копии можно указать `--dest /tmp/note-translation-recheck-vault`. Этот путь заменяет путь общего хранилища во всех сценариях повтора. В новой копии потребуется включить плагин и настроить подключение.

Сгенерированное хранилище — расходные данные; исходниками для воспроизведения остаются файлы в `notes/`. Обязательный отдельный отчёт или скриншоты не требуются; найденные несоответствия достаточно описать по шагу сценария. Computer Use агентом не применяется.
