# Ручная проверка перевода заметок после реализации

Проверять после реализации, прохождения автоматических тестов и production-сборки. Сейчас эти сценарии описывают ожидаемое поведение будущей функции, а не подтверждают её наличие.

Ручная проверка нужна только для реального управления областями и рендеринга Obsidian: тестовый помощник проверяет вызовы публичного API, но не доказывает вид и поведение приложения. Снимки, сбои, отмена, структура запросов, целостность результата и конфликты записи покрываются автоматическими проверками из спецификации; повторять их вручную не требуется.

Общее хранилище для обоих сценариев: `docs/testing/note-translation/translation-vault/`. Генератор и исходные данные находятся рядом: `docs/testing/note-translation/prepare_vault.py`.

## Подготовка

1. Из корня репозитория выполнить `python3 docs/testing/note-translation/prepare_vault.py`. Он создаёт указанное общее хранилище и отказывается перезаписывать непустую папку.
2. Выполнить `npm run build`. В полученном хранилище создать `.obsidian/plugins/<id из manifest.json>/` и скопировать туда `main.js`, `manifest.json`, `styles.css` из корня репозитория. Источник идентификатора — manifest, не имя репозитория.
3. Открыть хранилище в настольном Obsidian, отключить Restricted mode, включить плагин, настроить доступное подключение и модель диалога. Модель может переводить иначе, чем пример в инструкции: точные литературные формулировки не являются критерием этих визуальных сценариев.
4. Выполнить сценарии `workspace.md` и `appearance.md`. Они совместимы и используют одно хранилище.

## Восстановление исходного состояния

Не использовать рабочее пользовательское хранилище. Для чистого повторения закрыть тестовое хранилище и запустить генератор с новой пустой папкой, например `python3 docs/testing/note-translation/prepare_vault.py --dest /tmp/note-translation-recheck-vault`. Затем повторить шаги установки плагина и настройки подключения. Путь `/tmp/note-translation-recheck-vault/` полностью заменяет путь общего хранилища во всех сценариях этого повтора. Генератор не удаляет файлы и не переносит настройки подключения или секреты.

Сгенерированное хранилище — расходные данные; исходником для воспроизведения остаётся генератор. Обязательный отдельный отчёт или скриншоты не требуются; найденные несоответствия достаточно описать по шагу сценария. Computer Use агентом не применяется.
