# #58: проверка протокола и качества реальной моделью

Исходники:

- [Полная статья How to take notes](issue58-source.md).
- [Четыре сложные фразы пользователя](issue58-phrases.md).
- Вариант без выделения и ссылок строится проверочным скриптом из тех же фраз;
  код и формула остаются защищёнными, чтобы сравнивать именно влияние оформления.

## Проверка агентом без интерфейса Obsidian

Модель доступна агенту. Скрипт запускает настоящие `NoteTranslation` и клиент,
включая бюджет, проверку, ограниченное исправление и сборку. `Vault` и области
заменены адаптером в памяти: пользовательские заметки и настройки не изменяются.
Это проверка реального модель-сервера и производственной операции, а не
доказательство фактического рендеринга Obsidian.

Из корня репозитория, с установленными npm-зависимостями:

```sh
node docs/testing/note-translation/check_model.mjs \
  --settings /path/to/vault/.obsidian/plugins/obsidian-ai-helper/data.json \
  --context 65536 --out /tmp/issue58-check --runs 3
```

`--settings` читается только для настроек. Ключ и адрес сервера не выводятся
и не записываются в отчёт. `--context` необязателен: без него используется
значение из файла и обычное обнаружение окна плагином. Пустые temperature/topP
передаются как отсутствие настройки, а не выдуманные значения сервера.
Пустой maxTokens использует бюджет операции; фактические ограничения каждого
запроса записываются отдельно.

`--sample phrases|article|plain` выбирает один исходник. По умолчанию прогон
останавливается при первой неисправленной ошибке; `--keep-going` собирает
результаты остальных запусков. Защитная остановка образца через 10 минут
действует только в проверочном скрипте и не меняет responseWait плагина.

В `--out` находятся `parameters.json`, `results.json`, собранные переводы и
ответы модели на публичные тестовые исходники. Полные запросы, заголовки
авторизации и файл настроек туда не копируются. Для воспроизведения проверки
сборки на записанных ответах без генерации:

```sh
node docs/testing/note-translation/check_model.mjs \
  --settings /path/to/data.json --context 65536 \
  --out /tmp/issue58-replay --runs 3 --sample phrases \
  --replay /tmp/issue58-check
```

В режиме replay счётчик использует консервативную локальную оценку, а ответы
читаются из указанного каталога. Это проверка сборки, не новые запуски модели.

## Проверка качества

Сравнить все три перевода сложных фраз с вариантами без оформления. Проверить
связность, согласование, наличие всех смысловых частей, пробелы между словами,
непустые подписи и вложенное выделение. В смешанной строке английские слова
должны перевестись, а исходные русские слова остаться без изменений. В коде и формуле должны остаться
`cache.get(key)` и `$E = mc^2$`; между ними должен сохраняться союз.

Для каждой статьи проверить весь текст, включая русский абзац, три подписи
ссылок, самоссылку на переведённый раздел, таблицу, callout, сноску,
`^stable-block`, код и формулу. Встраивание должно остаться ссылкой на исходную
заметку; его содержимое не должно попасть в перевод. Проверка структуры
автоматизирована, но правильное дерево не доказывает языковую точность.
Грамматические, стилистические и терминологические ошибки модели фиксировать
отдельно от повреждений структуры; локальная сборка их не угадывает и не правит.

## При необходимости проверки в самом Obsidian

Для повторения именно в интерфейсе закрыть тестовое хранилище и выполнить:

```sh
python3 docs/testing/note-translation/prepare_vault.py --dest docs/testing/note-translation/translation-vault
```

Для существующей папки выбрать режим 2 для обновления плагина с сохранением
настроек, режим 1 для полного сброса, режим 3 только для восстановления контента
или 4 для отмены. Генератор содержит статью, `Справка/Метод.md` и
`Вложения/Схема.svg`. Повторный запуск восстанавливает начальное состояние;
результаты перед ним сохранить вне тестового хранилища. Четыре фразы взять из
`issue58-phrases.md` в той же папке тестирования.

Открыть `docs/testing/note-translation/translation-vault`, включить community
plugins и настроить модель. Статью переводить командой и из контекстного меню;
созданные результаты удалять перед повторным запуском или сохранять копию.
Этот шаг нужен только для оценки фактического рендеринга/клика по ссылкам в
Obsidian. Работа команды/меню, протокол и сборка проверяются автоматическими
интеграционными тестами, отдельный пользовательский отчёт по ним не требуется.

## Результаты

Параметры, исходы нескольких запусков и языковые наблюдения фиксируются в
[отчёте проверки модели](issue58-model-report.md). Секреты не публикуются;
версия/квантизация указываются только если известны, отсутствие данных не
подменяется названием модели.
