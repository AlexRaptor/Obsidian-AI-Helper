# Текущая папка и имя заметки в рекомендации

Ручную проверку выполняет пользователь в Obsidian. Автоматические тесты проверяют отправляемый контекст; они не гарантируют, что конкретная модель выполнит инструкции.

1. Выполните `npm run build`, скопируйте `main.js`, `manifest.json` и `styles.css` в каталог плагина тестового хранилища и перезагрузите Obsidian.
2. Создайте заметку `4.Archives/Работа/КПР-2025q4.md` с текстом «Командный план развития за четвёртый квартал 2025 года. План завершён, задачи выполнены».
3. В файле описания папки `4.Archives/Работа` укажите: «Здесь хранятся завершённые рабочие материалы, кроме командных планов развития. Командные планы развития хранятся во вложенной папке КПР». В описании `4.Archives/Работа/КПР` укажите: «Здесь хранятся завершённые командные планы развития и задачи по их реализации». Используйте настроенное имя файла описания (по умолчанию `_folder.md`).
4. Запросите рекомендацию папки. Ожидается предложение переноса в `4.Archives/Работа/КПР`. Модель не должна называть эту папку текущей: текущая папка — `4.Archives/Работа`, имя файла — `КПР-2025q4.md`.
5. Перенесите заметку в `4.Archives/Работа/КПР` и повторите запрос. Теперь «Оставить в текущей папке» соответствует её фактическому расположению.
6. Отдельно проверьте заметку в корне хранилища: в отправляемом контексте `currentFolder` обозначен как `/`, а `fileName` содержит имя с расширением `.md`.

Запишите модель, версию Obsidian и фактические ответы. При повторении ошибки сохраните обезличенные сообщения запроса и ответа; исключите ключ доступа и конфиденциальное содержимое заметок.
