# Подготовка ручной проверки упоминаний заметок

Ручные сценарии подготовлены агентом, но не выполнены. Их выполняет пользователь после реализации соответствующего тикета в настоящем Obsidian. Рабочее хранилище не используется.

## Создание отдельного хранилища

Из корня репозитория:

```sh
npm run build
node docs/fixtures/note-mentions/create-vault.mjs docs/fixtures/note-mentions/vault
```

Путь хранилища: `/Users/selivanov/code/Obsidian-AI-Helper/docs/fixtures/note-mentions/vault`. Исходные тексты и настройки: [генератор](../../fixtures/note-mentions/create-vault.mjs). Он копирует текущую сборку плагина и отказывается перезаписывать существующее хранилище.

Для восстановления закрыть старое тестовое хранилище и создать новое, меняя назначение, например на `docs/fixtures/note-mentions/vault-reset-1`. Каждый независимый сценарий переименования или удаления начинать на свежем наборе. После новой сборки для нового этапа создать новое хранилище, чтобы проверить именно актуальный плагин.

## Настройки

1. Открыть созданную папку как хранилище Obsidian. Отключить Restricted mode, включить Obsidian AI Helper и перезагрузить приложение. Плагин уже находится в `.obsidian/plugins/obsidian-ai-helper/`.
2. Выбрать русский язык. Для действий с отправкой указать OpenAI-совместимый модель-сервер, ключ при необходимости и модель диалога. Тестовые тексты будут переданы этому серверу.
3. Проверить автоматически определённое окно контекста либо указать фактический поддерживаемый размер вручную. Не брать произвольный лимит: для заметок и резерва ответа должно быть достаточно места.
4. Выключить поиск. Для этих ручных сценариев индекс и embedding-модель не нужны. Папка `Личное` намеренно исключена из индексации и остаётся доступной для явного выбора.
5. Открыть чат плагина рядом с основным редактором. На этапе только текущей заметки использовать `1.Projects/Monexa.md`; после добавления общего списка доступны все файлы.

## Какие проверки обязательны

- [Текущая заметка](current-note.md): настоящее поле ввода, клавиатура, курсор, тема и текст открытого редактора.
- [Несколько упоминаний](multiple-notes.md): редактирование нескольких элементов в настоящем поле сообщения.
- [Жизненный цикл файлов](file-lifecycle.md): реальные события переименования, перемещения, удаления и идентичность файлов.

Отдельной ручной приёмки для предварительного рефакторинга, расширения каталога, алгоритма фильтрации и интеграции бюджетов поиска не требуется: их результаты проверяются автоматически. Упоминание таких возможностей в тестовых данных не делает их обязательными ручными сценариями.

## Запись результата

Для каждого выполненного случая записать версию Obsidian, ревизию плагина, тему, язык, номер тикета, ожидаемый и фактический результат. Указать «пройден», «не пройден» или «не выполнен»; при сбое описать шаги воспроизведения. Проверки запросов и ответов записывать с моделью и лимитом контекста. Ответ модели сам по себе не доказывает состав запроса; при расхождении проверить содержимое запроса в журнале модель-сервера или сетевой панели Obsidian. Не записывать ключ API в отчёт.

Автоматические проверки выполняет агент. Ручные сценарии выполняет пользователь; Computer Use для них допустим только по его явной просьбе.
