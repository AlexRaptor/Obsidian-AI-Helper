# Ручная приёмка: изменения выбранных файлов в Obsidian

Тикет: [#39 — Изменения выбранных файлов](https://github.com/AlexRaptor/Obsidian-AI-Helper/issues/39), часть спецификации #33.

Статус: подготовлено, не выполнено. Выполняет пользователь после реализации #39. Здесь проверяются настоящие события хранилища и идентичность файлов; автоматические сценарии с подменой Obsidian выполняет агент.

Подготовка: [настройки](setup.md). После `npm run build` создать отдельное хранилище:

```sh
node docs/testing/note-mentions/create-vault.mjs docs/testing/note-mentions/file-lifecycle-vault
```

Точный путь: `/Users/selivanov/code/Obsidian-AI-Helper/docs/testing/note-mentions/file-lifecycle-vault`. Исходные данные находятся в [генераторе рядом со сценариями](create-vault.mjs); прежний путь `docs/fixtures/note-mentions/create-vault.mjs` также работает.

Каждый случай выполнять на свежем наборе. Для восстановления закрыть тестовое хранилище и создать новое той же командой с назначением `docs/testing/note-mentions/file-lifecycle-vault-reset-1` (далее `-reset-2` и т. д.). Существующее хранилище генератор не перезаписывает. Переименовывать и удалять только тестовые файлы через интерфейс Obsidian.

## MN-F1. Переименование и перемещение

1. Добавить в черновик вопрос с двумя упоминаниями `Личное/План.md` и одним `Знания/План.md`.
2. В файловом проводнике Obsidian переименовать личный план в `Личное/План выходных.md`.
3. Проверить обновление обоих упоминаний и списка выбора без повторного выбора. Переместить этот файл в `Проверка/Новый путь/План выходных.md`.
4. Создать по прежнему пути `Личное/План.md` новый тестовый файл с меткой `ПОДМЕНА-НЕ-ВЫБРАНА-91`.
5. Изменить текст перемещённого файла, добавив метку `СВЕЖИЙ-ПЛАН-93`. Закрыть его вкладку и открыть Monexa.
6. Отправить вопрос о метках выбранных заметок. В запросе проверить новый путь, свежую метку и единственный снимок перемещённого файла.
7. На свежем наборе повторить выбор и переименование, удалить одно повторение упоминания и отправить: вложение сохраняется. Повторить с удалением обоих повторений: снимка личного плана нет.

Ожидание: оба упоминания остаются связаны с перемещённым исходным файлом, отображают новый путь и дают один его снимок с `ЛИЧНОЕ-17`. Новый файл по прежнему пути не подменяет выбор. При расхождении ответа модели проверить состав запроса, как указано в общей инструкции.

## MN-F2. Закрытая вкладка и другой активный файл

1. Выбрать через @ `Знания/План.md` в вопросе о его метке.
2. Закрыть вкладку этой заметки, открыть Monexa и перейти обратно в чат.
3. Отправить подготовленный вопрос.

Ожидание: закрытая вкладка не делает существующую заметку недоступной; читается файл плана обучения с меткой `ЗНАНИЯ-29`, а не активная Monexa.

## MN-F3. Удаление одного файла и исправление черновика

1. Подготовить вопрос с упоминаниями Monexa и `Проверка/Для удаления.md`.
2. Удалить второй файл через Obsidian, затем попытаться отправить вопрос.
3. Проверить объяснение с проблемной заметкой и сохранность всего черновика. Не должно быть ответа по одному оставшемуся файлу как по успешно отправленному полному набору.
4. Создать новый файл по удалённому пути с меткой `НОВЫЙ-ФАЙЛ-НЕ-ВЫБРАН-92`. Повторная попытка не должна автоматически восстановить привязку удалённого файла на новый.
5. Удалить проблемное упоминание из черновика и отправить вопрос только с Monexa. Отдельно проверить явный новый выбор заново созданного файла.

Ожидание: отправка частичного набора блокируется, текст и остальные упоминания не теряются, пользователь может исправить выбор. Новый файл становится вложением только после явного выбора.

## MN-F4. Список и исторический снимок

1. Оставить список @ открытым. Создать, переименовать и удалить тестовую заметку, включая текущую: список обновляется сразу, исчезают устаревшие имена и пути. Каталог не зависит от перестроения индекса.
2. На свежем наборе успешно отправить вопрос с планом обучения. Затем переименовать или удалить исходный файл.
3. Задать уточняющий вопрос без нового упоминания.

Ожидание: новый список отражает текущее хранилище, но успешно отправленный исторический снимок сохраняется и доступен в следующем запросе. Изменение оригинала не переписывает историю и не блокирует вопрос по уже отправленному снимку.

## MN-F5. Повторное открытие чата

1. Создать черновик с вопросом и упоминанием. Закрыть и вновь открыть то же представление чата по его существующему жизненному циклу. Проверить сохранность черновика; создание нового представления не является восстановлением старого.
2. Переименовать выбранную заметку один раз.

Ожидание: название обновляется однократно, нет дублирующих реакций и сообщений, выбор не теряется из-за старых обработчиков. Восстановление диалога после перезапуска приложения не входит в проверку.

Записать результаты по [общей инструкции](setup.md#запись-результата). Эти сценарии не выполнялись агентом.
