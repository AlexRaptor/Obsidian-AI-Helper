# Ручная проверка #28: поиск папок в чате

Сценарии подготовлены, но в настоящем Obsidian агентом не выполнялись. Ручную проверку выполняет пользователь в отдельном хранилище.

## Хранилище и настройки

Из корня репозитория:

```sh
npm run build
node docs/fixtures/issue28-folder-search/create-vault.mjs docs/fixtures/issue28-folder-search/vault
```

Готовое чистое хранилище фактически создано по пути `/Users/selivanov/code/Obsidian-AI-Helper/docs/fixtures/issue28-folder-search/vault`. Точные пути и тексты исходных файлов находятся в [генераторе](../fixtures/issue28-folder-search/create-vault.mjs). Генератор копирует текущую сборку `main.js`, `manifest.json`, `styles.css` в `.obsidian/plugins/<manifest.id>/` и отказывается перезаписывать существующий каталог. Для восстановления создайте новый набор, например `.../vault-repeat-1`, и откройте его как отдельное хранилище. Рабочее хранилище не использовать.

Obsidian: стандартная тема, Settings → Community plugins → Restricted mode выключен, AI Helper включён. Для проверки ссылок используйте стандартное открытие внутренних ссылок, Cmd/Ctrl+click и среднюю кнопку мыши. Настройки Files and links уже заданы генератором: абсолютные ссылки и автоматическое обновление ссылок.

Плагин: язык `ru`, имя `_folder.md`, исключена папка `Личное`, автообновление заметок выключено. Индекс не строить. Embedding-модель не настраивать. Укажите свой OpenAI-совместимый модель-сервер, ключ при необходимости и доступную **модель диалога**, способную анализировать русский и английский текст. В окне контекста укажите реально поддерживаемое моделью значение не менее `32768`; резерв ответа оставьте по умолчанию (1024). При меньшем окне используйте соответствующее значение и ожидайте явное сообщение о нехватке контекста. Пользовательский системный промпт: «Отвечай по-русски, объясняй решение кратко». Реальный сервер и названия моделей пользователь выбирает из доступных ему; никаких ключей в наборе нет.

Исходные кандидаты: `/`, `Знания`, `Знания/Проект`, `Личное`. `Пустая` — только шаблон; `Знания/Без описания` собственного описания не имеет. `Другие описания/about.md` распознаётся только после смены имени. Обычные заметки `GTD.md`, `Личное/Секрет.md` и `Знания/Без описания/Контроль.md` должны оставаться неизменными.

## 1. Выбор источников и поиск папок без обычного индекса

1. Откройте чат AI Helper. Поиск изначально выключен. Включите его: появляется нативный список, выбран режим «Заметки».
2. Выберите «Папки». Состояние обычного индекса скрывается; отдельное окно не открывается. Спросите: «Какие папки подходят для материалов о GTD?».
3. Получен ответ модели диалога и проверенные источники с полным путём папки и описания. Раскрываемые описания показывают содержательный текст без комментариев. Нет требования embedding-модели, полной индексации или готовности обычного индекса, нет оценки embedding-сходства.
4. `Пустая` и `Знания/Без описания` не предлагаются. `Личное` участвует несмотря на исключение. Контрольный текст из `Личное/Секрет.md` отсутствует в запросе модели и в ответе. Если модель-сервер ведёт журнал запросов, проверьте JSON: четыре кандидата, у `Знания/Проект` контекст корня, `Знания` и собственное английское описание; обычных заметок нет.
5. Выключите и включите поиск: выбранные «Папки» сохраняются. Переключите язык плагина на `en`: список показывает `Notes / Folders`, подписи источников — `Folder description`. Тексты файлов не переводятся и не меняются. Верните `ru`.
6. Уменьшите ширину панели: выбор источников и кнопки доступны, элементы переносятся без обрезания.

Восстановление: очистить диалог, вернуть язык `ru`; при правках файлов создать новый набор.

## 2. Совет до создания заметки, уточнение и конфликт родителей

1. В режиме «Папки» спросите: «Где создать будущую заметку о GTD? Я ещё не решил, что в ней будет».
2. Допустимы несколько объяснённых вариантов либо уточняющий вопрос; не должно быть навязанного предпочтения проектов. Уточните: «Это справочное объяснение метода» — ожидается обоснованный совет по описаниям (прежде всего `Знания`).
3. Очистите диалог. Спросите: «Где создать план внедрения GTD в текущем проекте?».
4. При предложении `Знания/Проект` модель объясняет явное противоречие с родителем и приоритет конкретного описания. Ответ содержит полный путь, объяснение и проверенную ссылку. Отбор и формулировка зависят от модели, но предупреждение при использовании противоречащих правил обязательно.
5. Спросите: «А где хранить рецепты?». Допустимо отсутствие подходящей папки или уточнение; выдуманная папка не получает активной ссылки.
6. Проверьте список файлов: ни один вопрос не создал и не переместил заметку. История уточнений сохраняется. Пользовательский системный промпт применяется.

Восстановление: очистить диалог. Содержимое файлов сверить с генератором.

## 3. Проверенные ссылки и актуальность

1. Получите ответ с источниками. Нажмите ссылку на описание `Личное` — открывается именно `Личное/_folder.md`, несмотря на исключение. Cmd/Ctrl+click, средняя кнопка и меню ссылки позволяют открыть описание в новой вкладке. Наведение использует нативный preview Obsidian.
2. Измените текст использованного описания и снова нажмите старую ссылку: переход блокируется с сообщением об изменении или недоступности описаний. То же ожидается после удаления описания. Изменение описания родителя также блокирует прежний переход для дочерней папки.
3. Повторите вопрос: используется свежий текст. Создайте новый набор и смените имя на `about.md`, выбрав «Сохранить без переименования». Новый запрос видит только `Другие описания`; старые ссылки на `_folder.md` не открываются.
4. В обычном поиске Obsidian найдите `_folder.md`: описания остаются обычными Markdown-файлами и доступны вне плагина.

Восстановление: новый чистый набор.

## 4. Режим «Заметки» и обычные исключения

Только для этого сценария нужны доступная **embedding-модель** и завершённый обычный индекс. Настройте embedding-модель, затем явно постройте индекс через настройки или кнопку чата. Модель диалога остаётся настроенной.

1. Выберите «Заметки» и спросите: «Какие этапы GTD описаны в заметках?».
2. Источником служит `GTD.md`. `_folder.md` не конкурируют с заметками, `Личное/Секрет.md` остаётся исключённой. Состояние индекса и обычное оформление сходства снова доступны.
3. Переключитесь на «Папки»: описания, включая `Личное`, снова участвуют. Набор обычного индекса не ограничивает набор папок.

Восстановление: новый набор без embedding-модели и индекса либо очистка индекса и удаление настройки embedding-модели.

## 5. Нехватка контекста, ошибки и остановка

1. В режиме «Папки» уменьшите окно контекста до `1024` и задайте вопрос. Плагин сообщает о нехватке контекста для полного набора, ничего не отправляет модели и не сокращает набор папок. Вопрос восстановлен в поле ввода, успешная история не потеряна. Верните окно к реальному значению не менее `32768` и повторите — запрос проходит.
2. Укажите недоступный адрес модель-сервера или недоступную модель диалога. После ошибки вопрос доступен для повтора, успешная история сохраняется. Верните рабочие настройки и повторите.
3. На вопросе с длительной генерацией нажмите «Остановить». Уже полученный текст может остаться с пометкой остановки; поздний текст не добавляется, отменённый ход не входит в историю следующего запроса. Повторите с очисткой диалога и закрытием панели во время запроса.

Восстановление: вернуть рабочие сервер, модель и окно контекста, очистить диалог; для полного восстановления создать новый набор.
