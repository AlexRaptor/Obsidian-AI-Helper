# Дополнительная проверка экспорта чата — #73

Ручная приёмка не обязательна: критерии экспорта покрыты автоматическими тестами. Этот сценарий позволяет дополнительно проверить работу с вашим модель-сервером в Obsidian. Модель диалога должна поддерживать вызовы инструментов; обычный текстовый ответ модели о сохранении не заменяет созданный файл.

## Подготовка и восстановление

Данные: `/Users/selivanov/code/Obsidian-AI-Helper/docs/testing/chat-export/notes/`.
Хранилище для всех сценариев: `/Users/selivanov/code/Obsidian-AI-Helper/docs/testing/chat-export/notes-vault/`.

Закройте тестовое хранилище в Obsidian перед подготовкой или восстановлением. Из корня репозитория выполните:

```sh
python3 docs/testing/prepare_vault.py --source docs/testing/chat-export/notes --dest docs/testing/chat-export/notes-vault
```

Первый запуск собирает и устанавливает текущий плагин. Для обновления кода с сохранением настроек выберите режим 2, для восстановления только заметок — режим 3. Режимы 1–3 удаляют прежний контент этого тестового хранилища вне `.obsidian`, включая созданные экспортом файлы. После восстановления откройте хранилище заново и начните новый диалог. Для независимого повторения любого сценария используйте ту же команду и режим 3; для последовательной проверки всех сценариев восстановление между ними не требуется.

1. Откройте подготовленную папку как хранилище Obsidian.
2. В настройках Community plugins отключите Restricted mode и включите Obsidian AI Helper.
3. В настройках плагина задайте адрес модель-сервера, ключ при необходимости и модель диалога с поддержкой инструментов. Выберите русский язык интерфейса. Проверьте подключение. Убедитесь, что окно контекста определилось; если нет — укажите фактический размер из настроек модель-сервера.
4. Откройте чат плагина через боковую кнопку или палитру команд. Выключите поиск по заметкам на время этой проверки.

## 1. Полная переписка и точная граница

1. Отправьте: `Обсудим поездку. Рассматриваем поезд и самолёт. Ответь двумя короткими пунктами.` Дождитесь ответа.
2. Отправьте: `Самолёт отвергаем, едем поездом. Дату пока не выбрали.` Дождитесь ответа.
3. Отправьте: `Сохрани весь чат в новую заметку «Переписка» в папке «Экспорт». Нужны исходные реплики, не саммари.`
4. Откройте ссылку на созданную заметку, переключитесь в режим исходного текста.

Ожидается: `Экспорт/Переписка.md`; роли «Пользователь» и «Модель»; исходные тексты всех реплик в порядке чата, включая отвергнутый самолёт и саму команду сохранения. Текст не пересказан. Последующее сообщение об успехе, ожидание, системный промпт и JSON вызовов инструментов отсутствуют. Файл появляется после получения полного вызова модели, без обязательного предпросмотра или подтверждения.

## 2. Оборванный ответ

1. В том же диалоге попросите: `Напиши подробный план поездки на 30 дней, не менее 20 пунктов.`
2. Когда появится несколько строк, нажмите кнопку остановки в чате. Если ответ уже завершился, повторите с более длинным запросом.
3. Отправьте: `Сохрани весь чат в заметку «С остановкой» в папке «Экспорт».`
4. Откройте `Экспорт/С остановкой.md`.

Ожидается: сохранены вопрос и реально полученная часть ответа, рядом есть пометка «Незавершённый ответ; включён только полученный текст». Продолжение не придумано. Сохранены также видимые результаты предыдущего экспорта, но отсутствует сообщение об успехе текущего экспорта.

## 3. Вложения по умолчанию

1. Напишите `Обсудим @Поездка`, выберите заметку `Материалы/Поездка.md` в подсказке упоминания и отправьте. Дождитесь ответа.
2. Откройте `Материалы/Фрагмент.md` в редакторе и выделите только строку `ВЫДЕЛЕННЫЙ_ФРАГМЕНТ_73: купить билеты после согласования даты.`
3. В чате напишите `Обсудим @@`, добавьте предложенный выделенный фрагмент через подсказку и отправьте. Дождитесь ответа.
4. Отправьте: `Сохрани весь чат в заметку «Без текстов вложений» в папке «Экспорт».`

Ожидается: в `Экспорт/Без текстов вложений.md` у соответствующих сообщений есть названия и ссылки на обе заметки. Плагин не добавляет отдельные блоки полных текстов вложений. Модель могла процитировать материал в своих ответах — такие цитаты сохраняются как обычные реплики.

## 4. Исторические снимки вместо текущих файлов

1. После сценария 3 измените `Материалы/Поездка.md`: замените её текст на `НОВАЯ_ВЕРСИЯ_ЦЕЛОЙ_ЗАМЕТКИ_73`.
2. Замените содержимое `Материалы/Фрагмент.md` на `НОВАЯ_ВЕРСИЯ_ФРАГМЕНТА_73`. Не прикрепляйте эти заметки заново.
3. Отправьте: `Сохрани весь чат в заметку «Со снимками» в папке «Экспорт». Включи полные исторические снимки прикреплённых заметок и снимки выделенных фрагментов.`
4. Откройте `Экспорт/Со снимками.md` в исходном режиме.

Ожидается: у вложений сохранены первоначальный текст с `МАРКЕР_ПОЛНОЙ_ЗАМЕТКИ_73` и выделенная строка `ВЫДЕЛЕННЫЙ_ФРАГМЕНТ_73`. Нет обеих строк `НОВАЯ_ВЕРСИЯ_…`, нет `СОСЕД_СВЕРХУ_НЕ_ЭКСПОРТИРОВАТЬ_73` и `СОСЕД_СНИЗУ_НЕ_ЭКСПОРТИРОВАТЬ_73`. Для выделения не экспортируется остальная заметка, использовавшаяся для скрытой проверки актуальности.

## 5. Коллизия и отдельное сохранение решения

1. Отправьте: `Сохрани весь чат в заметку «Занято» в папке «Экспорт».`
2. Проверьте исходную `Экспорт/Занято.md` и новую заметку.
3. Отправьте: `Сохрани только итоговое решение о поездке в отдельную заметку «Решение» в папке «Экспорт». Укажи принятое решение и открытые вопросы.`

Ожидается: исходная `Занято.md` содержит `НЕ_ПЕРЕЗАПИСЫВАТЬ_73`; экспорт создан как `Занято (2).md` (или следующий свободный суффикс). В `Решение.md` находится подготовленный моделью итог, а не полная переписка: поезд принят, самолёт отвергнут, дата остаётся открытой.

## 6. Остановка ожидания экспорта

1. Отправьте: `Сохрани весь чат в заметку «Отменённый экспорт» в папке «Экспорт».`
2. Нажмите остановку, пока модель ещё отвечает и файл не создан.
3. Дождитесь окончания генерации на модель-сервере.

Ожидается: `Экспорт/Отменённый экспорт.md` не появляется. Если файл успел создаться до нажатия, остановка его не удаляет — для проверки начните заново с новым названием.

Автоматическое воспроизведение без подключения к модель-серверу:

```sh
npx vitest run test/chat-export.test.ts
```

## Проверка с настоящим модель-сервером

При ошибочных отказах модели полезно отдельно проверить её реакцию на историю, содержащую прежний ошибочный отказ. Следующая проверка воспроизводит эту историю и вложения через ввод и кнопки ChatView, затем отправляет команду экспорта вашему настоящему модель-серверу. Файлы создаются в памяти теста; рабочее хранилище не меняется. В запрос уходят тестовые материалы и сохранённый системный промпт из `data.json`; содержимое заметок вашего хранилища не читается. Настройки подключения читаются из указанного `data.json`, ключ не выводится и не записывается в репозиторий.

```sh
AI_HELPER_LIVE_SETTINGS=/absolute/path/to/data.json npx vitest run test/chat-export-live.test.ts
```

Без переменной `AI_HELPER_LIVE_SETTINGS` этот тест пропускается. Обычный набор тестов не обращается к модель-серверу. Проверка фиксирует температуру 0; размер контекста берёт из настроек, а при пустом значении использует 32 000. Если фактическое окно модели меньше, укажите его в настройках перед запуском. Предыдущие сообщения и первый экспорт воспроизводятся подставными ответами; финальный экспорт со снимками и последующий ответ выполняются настоящей моделью.
